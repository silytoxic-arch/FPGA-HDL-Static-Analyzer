# V1.4.140 R-9-2 共享边沿先序关系

本版本继续推进规则逆向和判断准确性，不调整界面或表格。对外规则编号继续严格使用官方三段式 `R-X-X` / `A-X-X`。

## 原生证据

`R-9-2` 的原生入口 `FUN_180699180` 与 `R-9-4` 共用关系构建器 `FUN_1804d56f0`。该构建器调用 `FUN_1804c4430` 识别条件边沿；已恢复证据确认：

- 过滤表依次为 `AST_POSEDGE(0x65)`、`AST_NEGEDGE(0x66)`、`AST_LOGIC_AND(0x45)`、`AST_BIT_AND(0x25)`；
- `FUN_1804f3870` 先记录当前匹配节点，再按子节点顺序递归，即 AST 先序；
- 入口采用第一个成功候选，因此复合条件后代可以建立类别 1/2 时钟关系，多个候选只取先序第一个；
- 旧式 `event` AND 的事件属性和同名电平等式不限制左右操作数顺序。

证据来自附件 `T-Linter.dll` 的离线静态反编译，不代表运行了附件程序。DLL SHA-256 为 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`；持久化证据为 `docs/evidence/native_vhdl_edge_condition_preorder.txt`。

## 产品接入

- `R-9-2` 的类别 2 主 IF、类别 1 ELSIF 和类别 1 ELSE 链接 IF 均改用共享的先序边沿识别器；
- 合法旧式边沿位于复合条件真实子树中时，可以建立时钟关系；
- 多个边沿候选严格保留先序第一个成功候选，不把后续时钟错误加入关系集合；
- 类别 3/4 排除、关系源码行排除、控制候选去重和条件信号赋值分支保持不变；
- 别名、generate/configuration、包限定或扩展名称、错误恢复和完整层次传播仍未恢复，相关无告警继续保持人工复核，不声明完整原生等价。

## 新增验证

- 类别 2：复合主条件左子树中的交换式旧式边沿可建立关系；
- 类别 1：ELSIF 复合条件中的后代旧式边沿可建立关系；
- 类别 1：ELSE 链接 IF 的复合条件后代边沿可建立关系；
- 两个显式边沿位于同一 OR 条件时，只采用 AST 先序中的第一个时钟名；
- 既有 `R-9-2` 直接 IF/CASE、类别 3/4、WHEN、关系行排除和每条件去重边界继续回归。

实施台账仍将“核心谓词已接入”与“完整厂商算法等价”分开记录；本轮不会把未恢复路径标为合规。
