## 缺陷与结果

V1.4.253 的宏生成模块已能通过展开顶层准入，但报告的设计结构为空。
现在通用及标准模式都在展开 Verilog 上提取有界结构、语法/语义和时序：
复现中的 macro_owner 从 0 个设计单元变为 1 个、含 2 个端口；clocked_owner
报告 3 个端口、1 个时钟和 1 个时序过程。宏生成的组合非阻塞、时序阻塞和 defparam
实例也已通过从通用模型到标准条款的端到端验证。

## 解析位置与报告位置

新增 FrontendSourceView，以展开文本及虚拟坐标作为解析输入，报告转换返回独立值。
结构和时序先在虚拟坐标中合并，之后映射模块、端口、参数、重复声明、实例、形参/实参、
参数覆盖、时钟、复位、过程事件、同步器及简单传输的位置；不会因两个过程映射到同一宏调用
行和第 1 列就把它们合并丢失。

映射根文件整行文本与原文一致，且解析列/偏移相互吻合时，保留精确物理列和字节偏移。
宏展开、include、逻辑 line 或同路径冲突而无该证明时，保留已建立文件/行，列 1、偏移 0。
逻辑 line 坐标不再伪称选中物理根文件的字节偏移，解析值不被报告转换覆盖。

未迁移的标准专用适配器继续消费可绑定到物理源码的模型，并在工程范围恢复实例解析和
顶层标记；其计算状态与用户看到的展开结构分开。通用核心诊断继续参与已有标准翻译。
这保留了原生 raw-line 扫描和物理 token 适配器的输入边界，没有把报告偏移拿去索引展开文本，
也没有把尚未迁移的适配器宣称为完整 AST。无命中仍不表示规则合规。

## 冻结 include 文本与错误边界

展开器的 input_file 增加只读文本快照，不改变输出流。头文件诊断的既有注释豁免使用
实际读入内容，不在分析后重新读磁盘。同一路径读到不同内容时不据此证明豁免；
Windows 文本流与内存根的 CRLF 转换不会被误认为冲突。冲突源也不获得精确字节偏移。

展开失败不会回退成看似有效的通用结构/语义模型。没有宏控制的原文件词法/结构错误，
以及纯条件指令的不匹配/未闭合诊断，仍可独立按物理位置报告，避免注释被展开器移除后丢失错误。
普通原文件风格与代码规模统计仍使用物理文本。
