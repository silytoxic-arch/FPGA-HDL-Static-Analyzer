# 第一百三十九轮：条件表达式优先级与非阻塞三目边界

目标 DLL SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
本轮使用原生 Bison 表离线重放和已有宽度 helper 静态证据，未执行厂商 DLL。

## 原生分组证据

本轮重放器保留归约派生树，而非只记录归约序号。输入为预定义 token，未执行词法器、
语义动作或运行时检查；派生树证明的是语法分组，宽度行为依赖此前恢复的 flag-zero helper。

- `!a+b`：规则 681 加法拥有规则 691 逻辑非子项。
- `!(a+b)`：规则 691 逻辑非拥有括号包裹的规则 681。
- `a==b|c`：规则 659 按位或拥有规则 675 相等比较子项。
- `a**b**c`：两个规则 686 左结合；公开固定版本语法的 `%left OP_POW` 仅作交叉印证。
- `q <= cond ? yes : no`：规则 522 是 `attr lvalue OP_LE delay expr`，其 expr 按规则 641
  独立归约为三目节点。赋值 OP_LE 不属于三目条件的比较节点。

## 产品修正

旧实现看到表达式起始 `!` 或任意顶层比较就返回 1，导致 `!a+b`、`a==b|b` 这样的
多位根表达式漏报；旧三目扫描也会把非阻塞赋值 `<=` 混入条件。

新增有完整范围消费、优先级和递归预算的条件表达式树适配器，按照已有原生 flag-zero
判据组合已知宽度：逻辑/比较根为 1，已恢复算术/按位根取子项最大值，幂传播第一子项，
拼接求和、固定十进制重复求积。运算符树的位置与报告位置继续分离。

三目提取先在可识别的 always/initial 过程入口中收集赋值运算符，再把这些 `<=` 当作
RHS 边界；RHS 中的关系 `<=` 仍留在条件表达式内。复用现有有界语句/LHS 扫描器，
覆盖裸语句、begin/end、if/else、组合事件和 always_comb 等入口。

## 验证与边界

新增表达式树专项验证根节点、括号、嵌套逻辑、拼接/重复、完整消费和深度上限；
端到端验证普通与宏生成形式、比较/非阻塞 `<=` 混合及组合过程。
版本对照仅是产品自身回归，不冒充厂商 oracle。完整结果见版本记录。

三目结果宽度、参数绑定及厂商错误恢复仍未完整恢复。任务/复杂事件或延时前缀等尚未被证明
的过程输入保留边界；未知节点不会变成已证明合规。完整算法验证保持 0/209。
