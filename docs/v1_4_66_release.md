# V1.4.66 规则编号与规则恢复说明

## 对外规则编号

- GJB10157 的 103 条规则逐条使用附件附录 A 的三段索引，例如 `GJB10157.5.2.1` 对外显示为 `R-2-1`。
- 标准明确标为建议类的条目保留 `A-*`，例如 `GJB10157.5.2.18` 显示为 `A-2-8`，不伪造为 R 类。
- GJB9765 附件没有单独的 R/A 对照附录；根据正式条款层级和 T-Linter 样例名称规范化为三段索引，例如 `GJB9765.4.8.e` 显示为 `R-8-e`，`GJB9765.4.5.f.2` 显示为 `R-5-f2`。
- GUI 问题列表/详情、CLI 目录与规则说明、TXT、JSON、SARIF 和 HTML 报告统一使用公开编号。
- JSON/SARIF 继续输出 `clauseId`；旧条款号和新公开编号都可用于规则说明、禁用项与严重级覆盖。
- 209 条公开编号已验证全部唯一。证据和边界见 `docs/evidence/standard_public_rule_id_mapping.md`。

## GJB9765 4.8.e

从 SHA-256 为 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0` 的 `T-Linter.dll` 恢复：

- `FUN_180609b30` 只对 `AST_ALWAYS(0x52)` 根执行规则检查；
- `FUN_1806097d0` 递归收集每个 `AST_NULL(0xb0)` 和零子节点 `AST_BLOCK(0x54)`；
- 首个 BLOCK 仅含一个 `AST_EDGE(0x67)` 的 ALWAYS 也报告，对应带事件/敏感信息但无实际语句的空进程；
- 原生结果按收集节点逐项输出，不去重。

产品在既有 NULL、空 IF 分支和空进程基础上，补齐空 CASE alternative 与空 LOOP 循环体，每个确定空节点报告一次。完整证据见 `docs/evidence/native_vhdl_empty_statement_4_8_e_findings.md`。
