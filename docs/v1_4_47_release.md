`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`）的只读
Ghidra 反编译继续确认：

- GJB10157.5.2.10 的 `FUN_18052cd30` 先从 `DAT_18135b808` 精确解析一个
  `AST_MODULE`，再计算有驱动无负载集合；
- GJB10157.6.1.7 的 `FUN_180555380` 只有在设计记录名称等于该共享值时，才进入直接
  时钟记录和后续层次关系图分析；
- GJB9765.4.9.h 的 `FUN_18060b400` 也只对名称相等的 VHDL 设计记录收集时钟域；
- GJB10157.5.1.8 对该值的使用是顶层存在性门控，之后仍扫描工程源记录，不能改成只统计
  顶层模块文本；
- GJB9765.4.2.c 在多个候选容器和不同条件分支中使用该值，现有证据只证明候选过滤/豁免，
  尚不足以安全收窄为“只检查顶层”，因此本版不修改该规则。

产品在显式 `top-module`/`--top-module` 存在时，对 5.2.10、6.1.7 和 4.9.h 应用已证实
的单一顶层边界；未配置时保留原有逐设计单元兼容行为，干净结果仍为人工或工程上下文复核。
5.2.10 的过滤只影响该条款映射，非选中根的写后未用信号仍可进入更宽泛的 5.2.18。
