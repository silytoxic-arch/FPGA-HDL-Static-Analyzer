# V1.2.5 持续逆向检查点

仍不是全部 209 条算法已恢复的最终版本。本轮增加原生证据支持的三个部分检测器：

- 9.4.3：function 内非阻塞赋值；排除条件/RHS 比较、task/always 和函数原型。
- 9.2.6：可证明依赖运行时变量的 case 分支标签；排除分支语句体，未知标签保留待复核。
- 9.3.6：repeat 的完整计数表达式变量依赖；参数作用域隔离，未知包/宏/函数语义保留待复核。

8.5 改为按算术表达式子树递归检查 X/Z，覆盖拼接、复制、三目、函数实参、位选和移位，避免兄弟子表达式错误关联。按原生 ALWAYS/ASSIGN roots 限定范围。
9.2.9 限定到 default 内赋值子树，不再因条件或 standalone task 中的 X 误报；原生额外排除条件尚未完整恢复。

外部报告状态由 `passed` 改为 `no-violation-found`（“未检出”，不是标准合规承诺）。8.4、8.5、9.2.2、9.2.9 和部分 VHDL 检查未报警时仍为 `manual-review-required`；三个新增部分检测器也保持人工复核模式，发现违规则正常定位报警。
这是 JSON 状态值兼容性变更，schemaVersion 升为4；使用报表 API 的脚本应同步调整。

逐条恢复、实现、测试与未知边界见 [209 条实施台账](evidence/native_rule_implementation_ledger.json)；本轮原生 Evidence ID 见 [第三轮说明](native_rule_recovery_pass3.md)。
Mac ARM64 构建可用；Windows 脚本保留，未生成或验证 Windows EXE。

构建后验证：105/105 CTest、89/89 CLI 回归通过。附件446个示例复测，自动条款151/172匹配，人工复核条款131/254示例匹配，工程上下文条款10/20匹配；后两类不能把未报警当作合规。仍未与供应商运行结果逐项对照。
