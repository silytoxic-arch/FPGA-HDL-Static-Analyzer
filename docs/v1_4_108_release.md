# V1.4.108 R-6-2 常量表达式求值

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。对外规则编号继续严格采用官方三段式 `R-X-X` / `A-X-X`。

## 新恢复的原生边界

- `FUN_1804b78d0` 是 `R-6-2` 名称值表的递归常量求值器。
- 类型 `0x10` 读取带有效标志的常量；类型 `0x13` 从对象 `+0x1a8` 名称表读取先前登记值。
- 类型 `0x43/0x44` 分别为 `AST_POS/AST_NEG`；类型 `0x3c..0x3f` 依次为 `AST_ADD/AST_SUB/AST_MUL/AST_DIV`。
- 其他 AST 类型直接求值失败。二元运算仅在两侧递归求值均成功时计算结果。
- 单目正负的零值路径不返回成功；除法分支未观察到本函数内的除零保护。
- 以上结论来自附件 DLL 的离线静态反编译，不代表运行了附件软件。

证据：`reverse-tools/evidence/r6_2_constant_evaluator.c`，SHA-256 `4bc000795b51fc2a0ab9807e01c1216970a50277bcbae41835a5fb3efd3b6181`。

## 产品修正

- owning entity 的 generic 默认值和当前 architecture 的 constant 可使用前序已登记名称；
- 支持括号、单目正负以及 `+ - * /`，并遵循 VHDL 的乘除优先级；
- 支持负中间常量继续参与后续表达式，只在转换函数最终宽度为有界正整数时采用；
- `mod/rem`、幂、除零、超出有符号 32 位的结果、前向未定义名称、包常量及局部遮蔽均失败关闭；
- 未求得宽度不产生 `R-6-2` 结论，规则状态继续保持 `ManualReviewRequired`，不伪判合规。

## 回归覆盖

- generic `2 + 2`：求得 4 位并报告对 8 位目标的不等宽；
- generic `BASE * 2`：读取前序 generic 名称；
- architecture `NEG := -4; WIDTH := NEG + 12`：保留负中间值并求得 8 位；
- `2 + 3 * 2`：按优先级求得 8 位；
- `16 / 4`：求得 4 位；
- `8 mod 4`、`8 / 0` 和前向名称：均不得伪造宽度，其中无报告仍保持人工复核；
- V1.4.107 及此前全部规则测试继续执行。
