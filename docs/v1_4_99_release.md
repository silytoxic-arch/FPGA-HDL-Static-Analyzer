# V1.4.99 A-5-29 类别 1/2 源码归属修正

## 新恢复的原生边界

- `FUN_1801c7b80` 保存源码 IF 后将当前节点降低为 CASE；源码第一条件保留为直接 `AST_COND`，ELSIF/ELSE 保持 `AST_ELSIF` / `AST_ELSE` 节点。
- `FUN_1804d24a0` 只有在 ELSIF，或 ELSE 内的链接 IF 中找到边沿时才产生类别 1/4。裸主条件 `falling_edge` 加常量赋值不属于类别 1。
- `FUN_1804d68a0` 的类别 2 要求主条件本身是边沿，只检查其分支块首节点链接的嵌套源码 IF，并只对该链接 IF 的直接 `AST_COND` 调用关系和常量赋值辅助器。ELSIF 分支不能向主条件借用赋值标志。
- `FUN_1804c48c0` 的关系集合包含直接标识符、单目 NOT 标识符、位/逻辑 AND/OR，以及标识符与字符 `'0'`/`'1'` 的等值关系；其他运算不应被词法适配器猜测接纳。

## 产品修正

撤销 V1.4.97/V1.4.98 中“裸下降沿 IF + 字面量赋值”的过宽分支。V1.4.99 仅在以下源码结构可证明时对下降沿标识符执行 `_n` 检查：

1. 主 IF 条件含直接 `falling_edge(identifier)`；
2. THEN 分支首项为嵌套 IF；
3. 嵌套 IF 主条件属于已经恢复的关系表达式子集；
4. 嵌套 IF 的直接主条件分支含已经恢复的字面量 RHS 赋值。

既有时序模型证明的低有效复位/置位检查保持不变。

新增回归覆盖：裸下降沿常量赋值不报告、普通下降沿数据传送不报告、分支外字面量不报告、非首项嵌套 IF 不报告、仅 ELSIF 分支写常量不报告，以及首项嵌套 IF 主分支写常量时报告。
