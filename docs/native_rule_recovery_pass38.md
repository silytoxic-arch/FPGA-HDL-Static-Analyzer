# 第三十八轮：GJB10157 R-12-5 全局函数名称图

原生 `T-Linter.dll`（SHA-256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`）的 `FUN_180588f70` 再核对后确认：候选映射 `+0x158`、调用邻接表 `+0x198` 和环成员集合都只用函数名字符串作键，键中没有 module、文件或候选组身份；这些容器在外层候选组循环间没有模块隔离。

这修正了产品原来的一个重要偏差。产品此前使用 `(module, 函数名)` 作为键，会漏掉不同 module 中不同函数名共同形成的递归环，并会把不同 module 中同名的递归函数分别报告。现在改为一次分析共享全局函数名图：重复名称覆盖报告节点，但全部同名候选的调用边继续合并；环仍按完整成员名称集合去重。

新增回归覆盖跨 module 的 `f→g→f` 闭环，以及两个 module 都定义同名自递归 `f` 时只报告一次并定位到最后覆盖的函数节点。公开编号保持官方三段式 `R-12-5`，内部条款键 `GJB10157.9.3.5` 只用于追溯。
