## 确认真实规则入口及报告字段

构造器 FUN_180024d60 注册 VLR-020009，安装 GJB9765_VHDL_4_10_h vtable，
再设置规则名 GJB9765_VHDL.4.10.h。PE 读取确认 vtable 0x180ef9a78 的 slot 0
确为 FUN_18068aaf0，与现有库存一致；没有把相邻规则的入口当作本规则。

该入口按规则对象 +0x78 的根分组遍历，每组清空三个全局向量，调用 FUN_18068b420。
随后逐项比较时钟向量 DAT_181361b48 与控制向量 DAT_1813619d8 的节点名称，
按相同长度和 memcmp 相等追加时钟节点指针到输出向量 DAT_181361b60。
比较与追加循环没有去重或首次命中后 break；M 个同名时钟节点和 N 个同名控制节点
形成 M×N 次输出。报告读取所追加时钟节点的 +0x214 行号，根的文件字段，
固定 Warning，列字符串为空。

固定正文来自 0x180f0c238 的 25 字节 GB18030：
`bdfbd6b9cab1d6d3d7f7ceaad2ecb2bdb8b4cebb2fb8b4cebb`，
解码为“禁止时钟作为异步复位/复位”。保留原始重复措辞，没有按意图改写为另一段文本。
0x180de47b9 的首字节为 00，确认空列；产品使用缺省列 1。

## 控制节点不会凭常量赋值产生

FUN_18068b420 仅对分类器 FUN_1804d5520 返回 1/2 的 ALWAYS 收集：

1. FUN_18068bd30 接受 source IF/ELSIF（0xaa/0xab），查看直接 COND（0x58）
   内的直接 EQ（0x36），追加其两个操作数指针。
2. FUN_18068c2c0 在受限的内部 IF/常量动作分支追加 EQ 操作数对；其入口首先
   用通用树类型选择器 FUN_1804f3870 查找 BLOCK，再检查其中直接 IF 和 COND。
3. FUN_18068cc30 只是追加一个 16 字节指针对，不去重，也不制造条件。
4. 最终每对优先选择第一个 Identifier（0x13），否则采用第二个操作数；
   FUN_18068bee0 另行从边沿/事件条件提取时钟节点。

这些路径都需要已有的 EQ/IF 条件，不存在独立的“任意直接常量赋值即报警”分支。
常量动作检查可限制一个已有内部条件，不等于凭常量赋值生成新的条件节点。

## 追踪 rising_edge 的前端来源

ASCII 引用定位实际 VHDL 回调 FUN_1801b7610，随后枚举 257 个具名 Context
的回调位移，找到 Function_call_or_indexed_name_partContext：
Context vtable 0x180e66650，进入委托 0x180178f00，listener +0x9b8。
TraceListenerContext 再确认实际委托和实现，避免仅凭字符串引用命名函数。

普通 rising_edge/falling_edge 调用在该回调中按名称分别重标为 0x65/0x66。
它们不是 EQ（0x36），并没有生成复位比较节点。
配合上一轮保留的 IF 源树快照和 VHDL 克隆路径，可区分源条件与 Verilog 简化结果。
单个 rising_edge(clk) 真分支仅有 dout <= '0' 时，没有可供交集使用的 EQ 控制节点；
即使存在时钟候选，也不应据此追加本规则报告。
