# V1.4.117 R-6-4 整数赋值二次定位

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。对外规则编号继续严格采用官方三段式 `R-X-X` / `A-X-X`。

## 原生证据闭环

- `GJB9765_VHDL_4_6_c` slot 0 `FUN_1806016c0` 除常量初值判定外，还递归收集 `AST_SIGNAL(0x78)` / `AST_VARIABLE(0x79)`。
- 该分支只保留节点 `+0x109 != 0` 的对象；`R-6-5` 的独立类型分支与中文标签共同证明该字节对应整数类型标志。
- 原生同时保存这些对象的物理行，随后扫描双子节点 `AST_ASSIGN_LE(0x56)`；赋值与声明物理行相同时跳过。
- 目标必须属于上述整数对象集合。RHS 中的 `AST_IDENTIFIER(0x13)` 只有在“不属于认可常量、但属于拒绝常量”时才在赋值点报告；`AST_VARASGN(0xa2)` 不属于该分支。
- 从同一 DLL 映像只读恢复三个 GB18030 片段：`0x180f018e0`“常量”、`0x180f018d0`“的赋值表达式中”、`0x180f018a8`“不是固定整型值或可计算的固定整型值”。

证据：`docs/evidence/native_vhdl_constant_static_initializer_4_6_c_findings.md`；保留证据 ID `ev_5f591cf433b08c94fd59aae3b050b90a666c6db29bb7ea7f776975767cec926c`。附件 `T-Linter.dll` 的 SHA-256 仍为 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 产品修正

- `R-6-4` 在完成同一设计根的常量状态表后，继续扫描简单名称目标的 `<=` 赋值。
- 仅直接声明为 `integer` 的 signal/variable 可进入目标集合；端口、用户子类型和其他类型不依据名称猜测。
- RHS 只有引用同一根内已经判为动态的常量才追加问题；未知、跨 package、用户函数或未完成绑定的常量仍保持人工复核。
- 复现原生声明物理行过滤，避免把声明同行降低结果重复定位为赋值问题。
- 诊断定位到赋值目标，中文消息包含目标和被拒绝常量名称；公开 `ruleId` 仍只输出 `R-6-4`。

## 新增验证

- 动态常量初值加整数 signal 的 `<=` 引用：常量声明和赋值点各报告一次。
- bit 目标引用同一动态常量：只报告常量声明，证明整数类型门控。
- integer variable 使用 `:=`：只报告常量声明，证明不扩张到 `AST_VARASGN`。
- 未解析常量用于整数 `<=`：不自动报告，继续保持人工复核。
- 整数对象声明与 `<=` 赋值处于同一物理行：只报告常量声明，复现原生行过滤。
