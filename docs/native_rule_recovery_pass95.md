# 第九十五轮：R-6-3 条件源行接入

沿用第九十四轮相同目标映像，静态分析未执行目标。

## 生产者核对

- NumberContext 虚表 0x180e1e850 的 exit 派发至实际监听器 +0x1550，函数
  FUN_180117e30。数值转换返回的常量 AST 显式写入 getStart()->getLine()
  至 +0x210；实数路径也显式写入，产品本轮仅使用已有 0/1 整数字面量适配。
- Hierarchical_identifierContext 虚表 0x180e1f728 的 exit 派发至 +0x1680，
  FUN_180106010。函数先将 getStart()->getLine() 写入 DAT_18131e000，再构造
  0x13 标识符；构造器从已绑定的回调取得此值。只接入直接标识符，不推广层次名。
- ExpressionContext 已证实逻辑取反节点的 +0x210 是 `!` 所在表达式起始行。
- R-6-3 主函数的两条相等分支分别读取右常量或左常量的位置，而非整个 IF。
  直接标识符及逻辑取反分支读取对应条件节点位置。报告只有行，没有列。

原始绑定见 `reverse-tools/evidence/t_linter_pass95/`；规则主函数保存在第九十三轮。

## 产品变化与边界

相等比较定位到常量 token 行，直接条件定位到标识符行，逻辑取反定位到 `!` 行。
产品列设为 1 以适配原生行级定位。新增跨行正向/反向相等、直接条件、跨行逻辑
取反断言，以及同一行两个报告在列统一后仍保留的重数验证。

不改变已支持条件形态或合规状态。宏生成事件、复杂关系、专有前端的其它路径、
非 0/1 常量的完整转换和全局诊断顺序仍待恢复，完整算法等价仍为 0/209。
