## 原生遍历范围

上一轮保留的 FUN_18068b420 在完成当前节点处理后，无条件递归全部直接子节点。
没有 generate/block 停止分支。新追踪到的 Generate_statement 进入回调
FUN_1801b7c10 创建 type 0x63 容器，Block_statement 回调 FUN_1801afda0
创建 type 0xb4 容器；退出均弹栈。它们不会改变后代 ALWAYS 的 0x52 类型。
因此之前产品只要看到 generate/block 就跳过整个 architecture 的限制过宽。

Process_statement 解析器及进入回调已在前两轮保留：可选 postponed 仍创建
ALWAYS + BLOCK，变化在 Context 起始名称/行号，而没有另设 postponed 分类标志。
本轮读取 listener vtable 0x180e802b8 的前几个非析构虚槽，均指向同一返回空桩
0x1800e7160；其反编译仅 return。未观察到额外 terminal 回调改变该结论。

## 分类器原型歧义与指令核对

初次无原型反编译把 FUN_1804d5520 对 FUN_1804c5070 的调用显示成根参数 0。
此输出不能作为算法事实：调用指令前 RCX 仍是传入根，RDX 被设为局部向量地址。
仅重新反编译仍未修正这一错误；记录了原先两个函数均无已知调用约定/参数的元数据。

根据指令验证的 Windows x64 寄存器位置，在 Ghidra 分析数据库中显式注释两个函数：
root 在 RCX，分类/输出指针在 RDX；walker 的已消费调用不使用返回值，分类器返回
EAX 类别值。脚本带目标摘要拒绝检查，改变分析数据库，不修改目标 DLL。
重新反编译才正确显示 `FUN_1804c5070(root, &local_vector)`。
这些是分析推定的 ABI 注释，不是厂商调试类型或恢复的原始 C++ 声明。
保留错误输出并在清单标为 known-inaccurate，避免把其假参数当作真实行为。

FUN_1804c5070 只沿 root 的直接 BLOCK、其直接 Sequential BLOCK，再检查
带 +0x183 标志及 +0x188 source IF 快照的 CASE。指令窗口 0x1804c515c–0x1804c5177
确认 RDX 指向 +0x188 字段，验证快照类型 0xaa，再把该快照追加到输出向量。
分类器对这些 IF 快照分类，而不读取 process 名称。多个顶层 IF 会形成 6/7/8/9 等
其他类别，A-10-4 仍只接受 1/2；新来源范围不等于放开所有进程语法。

## generate 语法与保留树

FUN_180183e40 处理标签、生成方案、可选声明/BEGIN、并行语句列表和 end generate。
方案 FUN_1801841f0 只有两种分支：FOR 参数规格（0x1e）或 IF 条件（0x24），
其他前瞻抛解析异常。已恢复路径没有 case/elsif/else 替代生成的解析分支。
产品接入 IF/FOR，不把其他生成语法自动归入同一已恢复路径。

保留树中每个源 process 只有一个 ALWAYS；递归收集不按 FOR 区间进行展开，
也不根据 IF 条件把静态后代删掉。新适配器按这个保留源码树的边界检查，
没有推算实际 elaboration 后的实例数量。此前的 VHDL 克隆及普通导入路径边界仍适用。

## 产品范围与词法绑定

新增结构化结束边界：`end [postponed] process [label];`、`end block [label];`、
`end generate [label];`。architecture 的结束查找先跨过完整的子容器，
局部函数的裸 end 或字符串中的关键字不会把所属 architecture 过早截断。
按容器递归处理，而不是因为有一个不支持的局部区域就放弃已知的外层进程。

容器内支持简单 signal/constant 声明及可选 BEGIN，复制可见绑定到子区域：

- 明确的 std_logic/std_ulogic 信号可建立局部标量绑定，包含默认初值和信号种类。
- 任意局部对象先隐藏外层同名对象；非标量、常量和 FOR 的生成迭代参数不会继承
  外层时钟类型。子区域结束后恢复外层绑定。
- 会遮蔽 IEEE 类型/边沿函数的对象名及未解析的类型、子程序、导入、接口声明，
  保持未知；这些区域不会被猜测为已成功绑定。
- 不同局部声明产生不同词法 owner。同一 owner 的已证明配对保留全部次数；
  不同 owner 但拼写相同的节点，其原生后续名称归一化仍未闭环，跨 owner 的额外
  配对保持 incomplete，不猜测相等，也不猜测合规。

NameContext 与 signal 回调保留原始名字及全局查表行为的证据；这不足以证明所有
后续限定名规则，故上面的 owner 是产品来源绑定标识，不冒充厂商内部节点标识。
architecture 隔离、显式 IEEE 类型和邻接上下文继承仍是既有来源子集约束。
同时修正 architecture 对象隐藏的旧类型继承，以及带约束端口提前结束列表的问题。
