## GJB10157.8.7 POW 原生公式接入

DLL 静态反编译确认 `FUN_1805790d0` 的 `AST_POW(0x42)` 分支只接受恰好
两个子节点，并要求第一个子节点为 `AST_IDENTIFIER(0x13)`。函数分别推断底数
和指数操作数的位宽，指数位宽必须大于零。

进一步直接读取 DLL 数据段：

- `DAT_180ef3ea8` = `0x4000000000000000` = double `2.0`；
- `DAT_180e836b8` = `0x3ff0000000000000` = double `1.0`。

由此确认原生违规条件为：

`target_width < (int)(pow(2.0, exponent_width) - 1.0) * base_width - 1`

这里使用的是指数操作数的位宽，而不是指数运行值。产品现接入两个直接、静态
定宽、非 memory 信号操作数，并只在浮点结果可以精确等价为整数、后续有符号
乘减不会溢出的范围内自动报告。字面量底数按照原生 AST_IDENTIFIER 门槛排除；
超范围转换继续保持 `ManualReviewRequired`，不猜测具体平台未定义边界。

新增测试覆盖：违规目标、精确阈值、1 位下界以及字面量底数排除。实际词法器将
`**` 表示为两个相邻 `*` token，本版已按该真实 token 形态适配。
