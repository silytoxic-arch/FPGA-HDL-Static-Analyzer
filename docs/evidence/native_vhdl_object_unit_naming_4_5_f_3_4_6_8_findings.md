## Recovered predicates

f.3 的递归函数只在类型 `0x75` 或一个具有特定内部名称的类型 `0x54` 容器下检查直接类型 `0x0a` 子节点。每个非空名称取自 `+0x48`，再进入规则对象 `+0xc0/+0xe0/+0x100` 和 `+0x144..+0x146` 控制的通用命名比较器。附件正反例把目标对象和默认策略确定为显式 `constant` 声明与大小写无关的 `C` 前缀。产品不把 generic/port 接口中的 `constant` 类关键字当作这一对象类型。

f.4 只接纳根节点类型 `0x76`，读取 `+0x48` 名称，并通过 `FUN_1804d6e80(..., 2)` 与规则对象 `+0xe0` 的字符串比较尾部。既有端口规则的独立恢复和附件示例共同确定 `0x76` 是 entity，默认后缀为 `_ent`。

f.6 遍历每个设计根的直接子节点，只接纳类型 `0x75`，然后对 `+0x48` 名称执行同样的大小写无关模式 2 尾部比较。附件示例确定该节点是 architecture，默认后缀为 `_arc`。

f.8 先收集类型 `0x97` 的点分名称，抽取其中的包名部分、转小写、排序并去重。随后遍历全局类型 `0xa9` 包节点，只对名称存在于前述集合的节点执行规则对象 `+0xe0` 的模式 2 后缀比较。附件两组示例分别覆盖“package declaration + package body”和 `use work.<package>.all` 路径，默认后缀为 `_pack`。这不是对所有点分库引用执行字符串扫描；IEEE/STD 库包不应因自身名称不带 `_pack` 而被产品报告。
