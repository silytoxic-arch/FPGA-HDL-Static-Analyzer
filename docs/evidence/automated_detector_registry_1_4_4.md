# V1.4.4 自动检测器注册表审计

## 问题

V1.4.3 中有 27 条规则已经具备可执行的、有原生证据或附件规则文本支持的确定违规检测器，且相关正反例和边界测试已经存在，但规则目录仍标记为 `ManualReview`。这会在审计和产品说明中隐藏实际检测能力。

本次只修正检测器注册和评估模式，不放宽任何源码接纳条件，也不把“未发现违规”改成“合规”。标准评估器的全局不变量保持不变：

- 命中检测器：`Violated`；
- 未命中但不需要外部工程上下文：`ManualReviewRequired`；
- 缺少库单元、层次关系或策略上下文：`ProjectContextRequired`。

## 重新登记为 Automated 的规则

### Verilog / GJB10157

- `GJB10157.10.1`、`.10.2`、`.10.3`、`.10.4`：状态机死锁/default 恢复/初始化/状态数检测；
- `GJB10157.12.2`：状态机 safe 模式；
- `GJB10157.6.2.5`：明确非 SRAM 技术上下文下的上电初始化；
- `GJB10157.7.2.2`：基本门反馈锁存器；
- `GJB10157.9.2.6`：case 分支变量或逻辑表达式；
- `GJB10157.9.3.5`、`.9.3.6`：递归函数与 repeat 变量；
- `GJB10157.9.4.10`：数组/存储器复杂索引。

### VHDL / GJB9765

- `GJB9765.4.2.b`：输出端口回读；
- `GJB9765.4.6.c`、`.4.6.d`、`.4.6.e`：常量静态性、隐式数值转换、有符号/无符号混算；
- `GJB9765.4.9.a`：时钟路径再汇聚；
- `GJB9765.4.10.a`、`.c`、`.d`、`.e`、`.f`、`.i`、`.k`：复位反馈、同步释放、悬空、覆盖、复位域、同步复位输入和组合复位；
- `GJB9765.4.11.a`、`.c`、`.d`、`.e`：无效状态处理、合法初始化、三段式结构和枚举状态类型。

每条规则的原生入口、已接入判据、测试文件和未覆盖边界仍由 `native_rule_implementation_ledger.json` 逐条记录。

## 保留非 Automated 的规则

- `GJB10157.5.2.15` 保持 `ManualReview`：附件合规示例中的参数名 `Data` 与已恢复 DLL 默认参数小写判据冲突，不能选择一方后冒充完整厂商语义。
- `GJB10157.6.1.7`、`GJB10157.7.3.3`、`GJB9765.4.14.d.4`、`GJB9765.4.9.h` 保持 `ProjectContext`：其完整判断需要时钟域、子模块端口、外部文件或层次关系。

## 验证边界

附件样例审计中的 432 个 Automated 样例全部匹配。ManualReview 的一正一反样例保留已记录冲突；ProjectContext 的剩余不匹配来自附件未提供 `my_module1` 端口定义，不通过伪造模型消除。
