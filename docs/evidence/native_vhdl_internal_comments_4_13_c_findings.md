## Recovered predicate

规则构造函数 `0x1800258a0` 安装 vtable `0x180efade0`，slot 0 为
`FUN_1805bc5a0`。该函数把类型常量 `0x78` 和 `0x79` 交给递归收集器，得到内部 signal 与
variable 声明候选。每个候选名称取自 `+0x48`，物理行号取自 `+0x214`。

对每个候选，原生函数重新定位源文件并读取至候选所在的精确物理行，然后在该行执行原始
字节搜索，寻找连续字符 `--`。找不到时为该声明候选生成诊断。前置或后置相邻行的注释不
满足规则；同一行的分组名称共享该行标记；该搜索不区分真正注释和字符串中的 `--`。

`0x180efae28` 起的 GB18030 常量可解码为“应添加注释说明.”和“信号/变量”。产品据此
逐名称报告定义行缺少注释，并排除实体 port 接口中的显式 `signal` 类。

## 已验证边界

- 声明前一行注释不生效。
- 分组 signal 对每个名称分别建立候选。
- 多行声明按名称所在物理行判断，类型行注释不回溯。
- variable 与 signal 均被检查。
- 同行注释、同行分组注释及字符串内原始 `--` 标记均通过。
- 实体 port 接口中的显式 `signal` 类不作为内部声明检查。

## 限制

类型 `0x78`、`0x79` 的专有枚举名、别名和共享变量细分、子程序接口类、错误恢复节点、
扩展标识符、源编码转换、重复设计根及原生诊断排序尚未完全恢复。产品使用注释感知词法器
识别 VHDL signal/variable 声明候选，再对原始物理行执行已恢复的字节判据；不声明与厂商
前端完全等价，干净结果仍保留人工复核语义。
