## Recovered predicate

原生入口为大型复位网络关系分析器，而不是按复位信号名称或进程数量检查。恢复出的关键阶段如下：

1. 按设计单元建立复位、时钟、进程和连接关系映射。
2. 遍历类型 `0x75` 的进程相关节点，并从其中提取类型 `0x56`、左右两端均为类型 `0x13` 且无下级子节点的直接标识符赋值；这对应直接的寄存器传递边。
3. 通过 `FUN_1804d0140` 等辅助函数构造展开后的关系组。
4. 最终候选必须同时满足：`FUN_180676aa0` 找到关联记录；`FUN_1805a85f0` 找到至少一条匹配路径；`FUN_1805a1ec0` 返回的同步属性标志为真。任一同步路径证明失败即进入报告分支。
5. 报告采用原始节点 `+0x214` 的物理行和 `+0x1e0` 的文件绑定信息。

DLL 内置 GB18030 诊断文本解码为“应使用可以同步瘦放的复位信号进行复位”；“瘦放”是厂商字符串中的原始错字，结合规则标题和附件语义应为“释放”。

附件违反例由原始 `rst_n` 直接异步控制业务寄存器。符合例先在一个进程中用 `rst_n` 异步置位两个同步级，在时钟分支中令第一级进入非复位值并将第一级传到第二级，业务进程只使用第二级 `rst_n_synl`。这证实原生判定依赖复位路径和寄存器传递关系，而非简单禁止异步复位。

## 产品接入

产品实现源码可严格证明的附件形态：

- 复位必须出现在进程敏感列表并作为时钟事件前的首个条件，证明它是异步控制。
- 同步器的两个寄存器在异步分支被置为复位有效值。
- 时钟分支把第一级置为相反的非复位值，并执行第二级 `<=` 第一级的直接传递。
- 同步器进程本身允许使用原始异步复位；业务寄存器必须使用已证明的第二级。
- 原始复位仍直接控制业务进程时，即使工程中另有未使用的同步器，也继续报告。
- 同步复位、普通组合条件和注释不进入本规则。

验证覆盖附件正反例、单级链、未使用同步器、同步复位、高有效双级链和直接信号传递边界。
