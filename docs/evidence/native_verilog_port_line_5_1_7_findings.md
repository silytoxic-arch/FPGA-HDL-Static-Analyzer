## 恢复判据

构造函数 `FUN_180020f40` 把全局规则对象的 vtable 设置为 `0x180eeb778`，因此生效的 slot 0 是 `FUN_18052ae80`；同一类关联的 `0x180eeb730/FUN_18074b080` 不是该对象最终安装的执行入口。

`FUN_18052ae80`：

1. 遍历规则对象 `+0x68` 中的源文件记录。
2. 遍历全局连续记录区 `[DAT_18133c160, DAT_18133c168)`；记录步长严格为 `0xb8`。
3. 对每个 `i` 与所有 `j>i` 两两比较。
4. 要求记录 `i` 与记录 `j` 的 `+0x70` 字符串都精确等于当前源文件字符串。
5. 比较两条记录首字段；相等即进入诊断路径。诊断使用后一个记录 `j` 的 `+0x30` 名称作为独立元数据、首字段行号及来源元数据，严重度为 `Warning`；正文对象 `0x180eeb7c0` 的 22 字节 GB18030 数据精确解码为“一行中存在多个端口声明”，正文不拼接端口名。

全局记录生产者也已闭合：

- `FUN_180134f60` 产生类型字符串 `inputport`；
- `FUN_1801349e0` 产生类型字符串 `inoutport`；
- `FUN_180135fc0` 产生类型字符串 `outputport`；
- 三者均把首位置行号、名称、来源文件和类型复制到同一 `0xb8` 字节记录，并追加至 `[DAT_18133c160, DAT_18133c168)`。

因此首字段是本规则使用的物理行分组键；同一文件同一行的每个端口记录对都会报告一次。若同一行有 `N` 个端口，诊断数为 `N*(N-1)/2`，并定位到每一对中的后一个记录。算法不比较端口方向，故继承方向与重复写出方向的形式等价触发。

V1.4.182 对条件编译后的活动源码解析模块端口，按文件和物理行分组，并保留原生两两比较的诊断乘法。参数列表逗号不计入端口；同一文件中即使端口属于不同模块，只要物理行相同也按原生记录比较；未激活预处理分支不产生记录。输出固定正文“一行中存在多个端口声明”和 `Warning`，并覆盖 ANSI 继承方向、显式三方向及非 ANSI 声明。
