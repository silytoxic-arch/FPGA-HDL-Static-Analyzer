# GJB10157.6.2.8 内部时序信号作为异步复位原生判据

## Recovered predicate

目标为用户附件中的 `T-Linter.dll`，SHA-256 为
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

静态逆向观察到：

- `GJB10157_VLOG_6_2_8` 构造函数位于 `0x180022900`，注册
  `GJB10157_VLOG.6.2.8`，并将规则对象 `+0x158` 清零；
- slot 0 为 `FUN_1806f8890`（`0x1806f8890`），已有证据
  `ev_5134c94e891c153e7d80bced19ef594689c4eac2a62a449ed9797b5ba29af105`；
- slot 1 为 `FUN_180564050`（`0x180564050`），已有证据
  `ev_16b894aa8c8c4e639d06ec49e60914d47df3cf0a8dc74fe48f5c0a9f0c8c24a3`；
- `FUN_180564050` 直接调用 `FUN_1804e6df0`；后者仅在节点类型为
  `AST_ALWAYS(0x52)` 且直接子节点中存在 `AST_POSEDGE/AST_NEGEDGE(0x65/0x66)`
  时返回接纳状态；
- `FUN_1806f8890` 在接纳的时钟沿过程中递归收集
  `AST_ASSIGN_EQ/AST_ASSIGN_LE(0x55/0x56)`，将赋值目标名与已建立的异步复位关系名
  比较，相等时对每个匹配赋值节点独立构造诊断；
- 默认分支通过 `FUN_1800d37b0` / `FUN_1801380f0` 依次拼接 GB18030
  常量 `异步复位` + `normalized-target` + `由时序逻辑驱动`；
- 报告级别常量 `DAT_180ee83b0` 为 `警告`；位置复制匹配赋值 AST
  `+0x1e0` 的源文件和 `+0x210` 的物理行，未写入原生列号。

因此已证明的核心判据是：由本模块时钟沿过程赋值产生的内部信号，又被用作异步复位
或置位信号时，每个匹配的 blocking/nonblocking 赋值 AST 均报告一次。默认原生诊断为
`异步复位<normalized-target>由时序逻辑驱动`，级别 `Warning`，定位到赋值物理行且无原生列。
附件违规例中的 `my_ff_rst` 满足该判据；附件正确例中的组合逻辑复位不属于这个
时序生成分支。

附件说明同时提到锁存器，但当前类过滤器只证明了带边沿 `always` 的路径。锁存器是否经
另一套综合关系进入同一诊断尚未建立，因此产品不把锁存器路径冒充为已恢复原生逻辑。

## Product integration boundary

产品在同一 Verilog 模块内，将解析器确认的异步复位/置位信号集合，与时钟沿过程的简单赋值目标
逐节点比较；确定匹配产生 `GJB10157.6.2.8` 诊断。产品保留赋值节点重数，将无原生列映射为
第 1 列，并输出上述精确正文。外部复位、实例输出复位以及仅由组合逻辑产生的复位不会触发本条款的
这个子判据。

原生异步复位关系的完整构建与关系重数、锁存器综合路径、跨层次传播、库单元、宏、generate、
别名、复合左值、转义名归一化边界及全局诊断顺序仍未恢复。无诊断时保持
`ManualReviewRequired`，不声明完整厂商算法等价。静态摘录见
`reverse-tools/evidence/t_linter_pass79/a5_3_internal_reset.txt`。
