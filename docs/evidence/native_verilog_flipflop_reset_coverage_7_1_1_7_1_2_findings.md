### GJB10157.7.1.1

- 静态注册包装器为 `0x180022a50`，类构造函数为 `0x18055ddb0`；slot 0 为
  `FUN_18055e770`，slot 2 为仅接纳 `AST_MODULE(2)` 的 `FUN_1807238a0`，证据
  `ev_34073b3f9020270ea752c6de0e419d56d4a95fc558a0ca1cb938eb6a6d76db53`；
- 主函数遍历综合后的关系记录，收集 `AST_ALWAYS(0x52)` 及其
  `AST_POSEDGE/AST_NEGEDGE(0x65/0x66)` 后代；
- 事件关系随后与单个寄存器记录和源码位置关联，命中混合复位覆盖时调用
  `FUN_18055e020` 构造结果；
- `FUN_180560070` 定位 IF 降低树的最终 `AST_DEFAULT`，并沿同物理行的嵌套
  `AST_CASE(0x57)` 跟随 else-if 链；
- `FUN_18055fd10` 收集最终 default 分支内的 `AST_ASSIGN_EQ/LE(0x55/0x56)`，
  `FUN_18055f9a0` 收集同一 IF 树中物理行不晚于最终 default 行的赋值。两者均只把
  直接首子节点为 `AST_IDENTIFIER(0x13)` 的赋值写入归一化目标表；
- `FUN_18055e020` 对最终 default 目标表逐项查找此前分支目标表；每个缺失目标独立
  报告。此前目标表为空也不跳过，因此空复位分支会对全部 default 目标报告；
- 原生级别固定为 `error`，正文精确拼接为
  `always语句中混合使用有复位和无复位的触发器：触发器“<目标>”未进行复位`；
  文件取当前设计记录，行号取缺失目标在最终 default 分支的赋值物理行，不含列号；
- 附件错误例中 `my_sig` 在复位和数据分支均赋值，而 `my_sig2` 只在数据分支赋值；
  正确例在复位分支同时覆盖两者。

第八十一轮完整静态摘录见
`reverse-tools/evidence/t_linter_pass81/r6_1_async_if_assignment_coverage.txt`。

## Product integration boundary

产品对条件预处理后的 Verilog/SystemVerilog 源码执行以下确定检查：

- 单一简单边沿事件的 `always`：其中的简单赋值目标按“没有异步复位/置位”报告
  `GJB10157.7.1.2`；
- 多边沿 `always`：仅当首层语句是与事件极性一致的简单复位 IF 时，`R-6-1` 把
  IF/ELSE-IF 最终 ELSE 的简单赋值目标与其前全部分支目标比较；
- 数据分支目标未出现在首个复位分支时，报告 `GJB10157.7.1.2`；`R-6-1` 独立使用
  最终 ELSE 与此前全部分支的比较，不要求此前目标非空，并按缺失目标输出精确原生
  `Error` 正文、赋值物理行与产品第 1 列；
- `R-6-1` 以源代码 `else` 物理行作为 `AST_DEFAULT` 行的有界代理；最终 ELSE 中与
  `else` 同行的赋值也进入此前目标表，复现 `FUN_18055f9a0` 的 `赋值行 <= default行`
  截止行为；
- 支持直接/取反标识符及标识符与一位 0/1 常量相等比较形式。
