FUN_1804f3870 traversal
-----------------------
For a non-null node, FUN_1804f3870 first scans the filter integers and appends
the current AST pointer to the output vector if its type matches. It then loops
over the current node's child vector from index zero upward and recursively
calls itself for each child. Therefore the candidate vector is AST preorder:
current matching node before matching descendants, with siblings in child
order. The filter order does not reorder nodes; it only tests membership.

FUN_1804c4430 consumes that vector from index zero upward and stops on the
first successful candidate. AST_LOGIC_AND/AST_BIT_AND candidates are passed to
FUN_1804d4cc0. AST_POSEDGE/AST_NEGEDGE candidates are accepted only when the
case-folded node name is exactly rising_edge/falling_edge and there is exactly
one AST_IDENTIFIER child.

FUN_1804d4cc0 legacy event idiom
--------------------------------
The helper requires an AND node with at least two direct children and scans
all direct children without requiring their source order. It recognizes:

  * an AST_IDENTIFIER with exactly one AST_ATTRIBUTE_DESIGNATOR child whose
    case-folded name is exactly event; and
  * an AST_EQ with exactly two children containing an AST_IDENTIFIER and one
    of the two embedded binary character constants.

It compares the case-folded event identifier with the equality identifier,
requires a resolved non-empty output name and edge value other than 3, and
returns success. Consequently equality/event operands may be swapped across a
direct AND, source parentheses do not survive as an obstacle, AST_LOGIC_OR and
AST_BIT_OR are not legacy-edge candidates, and a recognized descendant AND or
edge call remains discoverable through an otherwise unsupported parent node.

Remaining boundary
------------------
The proprietary frontend's exact AST construction for malformed expressions,
overloaded or selected names, extended identifiers and recovery nodes remains
unresolved. The product implementation therefore admits only syntactically
bounded basic identifiers, exact binary literals and source expression trees
whose child order can be reconstructed without claiming full frontend parity.
