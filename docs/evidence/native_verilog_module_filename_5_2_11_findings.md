# GJB10157.5.2.11（A-2-1）模块名与文件名规则恢复

## 目标与身份

- 附件：`T-Linter.dll`
- SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 构造函数：`0x1800211c0`
- 规则入口：`FUN_180749660`（`0x180749660`）
- 公开编号：`A-2-1`
- 内部映射：`GJB10157.5.2.11`

本记录来自附件二进制的离线静态分析，不是原软件运行观测。

## 已观察事实

1. 构造函数同时注册内部标识 `VLR-140002` 和 `GJB10157_VLOG.5.2.11`。
2. 入口遍历规则对象 `+0xa8` 模块映射中的每一个模块条目。
3. 从模块 AST `+0x1e0` 读取源路径，并通过 `FUN_1804f20e0` 把每个反斜杠替换为正斜杠。
4. 从规范化路径中反向寻找最后一个 `.` 和最后一个 `/`，取两者之间的字节串作为文件主名：
   - Windows 与 POSIX 分隔符结果一致；
   - 多点文件名使用最后一个点；
   - 无扩展名时使用完整文件名；
   - 文件名以点开头时主名为空。
5. 模块映射键经 `FUN_1804df040` 去除 Verilog 转义标识符前缀。
6. 文件主名与模块名使用 `memcmp` 加长度进行大小写敏感的精确比较。
7. 不相等时读取 AST `+0x210` 物理行，未观察到列号字段；严重度固定为 `Warning`。
8. GB18030 片段拼成精确消息：

   `模块名<module>与文件名<stem>不匹配.`

## 产品接入

- 按每个解析模块执行比较。
- 独立于宿主操作系统地统一 `\` 和 `/` 路径。
- 实现最后斜杠、最后点、无扩展名和点文件边界。
- 保持转义模块名规范化及大小写敏感比较。
- 使用原生消息、`Warning`、AST 物理行和第 1 列。
- 增加 Windows 路径、多点文件名、无扩展名、点文件、大小写、转义模块名和定位测试。
