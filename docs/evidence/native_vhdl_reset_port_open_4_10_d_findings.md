## Recovered predicate

原生入口不是“时序进程没有复位分支”检查。`FUN_1805aee10` 收集组件/实体连接及复位相关名称，统一小写后构造关系集合，并通过 `FUN_1804d0140` 建立展开后的连接记录。

入口末段存在两条告警路径：

1. 复位形式端口能直接解析到连接记录时，若记录表明该端口没有驱动，入口在该连接记录的物理位置输出告警。
2. 直接记录不足时，入口调用 `FUN_1805b04b0`。该辅助函数在关系组中匹配形式端口名和关联名，并在连接状态字段为零时输出告警。

原生 GB18030 常量分别解码为：

- `寄存器复位端口`
- `未被驱动,处于悬空.`
- `禁止悬空`

附件违反例和符合例的结构完全相同，唯一相关差异是：

- 违反：`rst_n => open`
- 符合：`rst_n => rst_n`

因此已经证实的核心谓词是：组件或实体实例的寄存器复位形式端口存在显式关联，但实际端为 `open`、未形成驱动关系时报告。附件中原有 Python 规则把“时序进程没有复位分支”映射到 4.10.d，与 DLL 原生入口及示例均不一致，产品未采用该逻辑。

## 产品接入

产品实现严格限定在可由源码证明的子集：

- 只处理已声明为输入方向的形式端口。
- 只处理本地组件声明或已解析实体的端口表。
- 形式端口名称按 VHDL 大小写不敏感规则归一化，并要求以 `rst` 或 `reset` 开始。
- 只有命名或位置关联中明确写出的 `open` 才报告。
- 普通输入端口的 `open`、缺省未关联、注释/字符串伪代码均不映射为本规则。

验证覆盖附件正反例、本地组件命名关联、位置关联、跨文件可解析实体、普通输入 `open`、省略复位关联及注释边界。
