# A-1-5 端口顺序原生恢复记录

公开规则编号严格采用官方三段式 `A-1-5`。内部条款键 `GJB10157.5.1.5` 仅用于源码、附件和逆向证据关联，不作为界面规则编号。

- 附件版本：T-Linter V3.1.4.251205
- 目标文件：`T-Linter.dll`
- SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 构造函数：`FUN_180020d90`
- 活动入口：`FUN_180529870`

- 位置名称比较：`FUN_1800dc750`
- 关系类别谓词：`FUN_1804dedf0`、`FUN_1804dee00`

## 恢复判据

1. 构造函数注册字符串 `GJB10157_VLOG.5.1.5` 并安装 `Yosys::GJB10157_VLOG_5_1_5::vftable`。虚表 slot 0 为 `FUN_180529870`，slot 1 为只接纳 `AST_MODULE(2)` 的 `FUN_1807238a0`。
2. 活动入口从每个被接纳的唯一模块根递归收集 `AST_WIRE(6)`；节点字节 `+0xa0/+0xa1` 将端口分成 input `1/0`、output `0/1`、inout `1/1`。内部声明 `0/0` 不进入实际端口列表。
3. 每个实际端口记录大小为 `0x28`：规范化名称位于起始处，物理行号保存在 `+0x20`。原生报告不携带已恢复列号。
4. `FUN_1804dedf0` 接纳关系类别 2 或 3；相邻时钟命名规则独立证明这组为时钟。`FUN_1804dee00` 接纳关系类别 0 或 1，对应复位。入口先收集时钟关系名，再收集复位关系名。
5. 只有同时存在于 input 名称列表的特殊关系名才进入期望列表；随后依次追加尚未出现的普通 input、output、inout。`FUN_180529750` 使用区分大小写的完整字节相等判断。
6. 期望列表按名称去重。如果实际端口包含重复名称，期望/实际数量会不一致，入口直接跳过该模块，不产生顺序诊断。
7. 只有期望与实际数量相等时才逐位置调用 `FUN_1800dc750`。第一个名称不一致即输出一条诊断并 `break`，所以每个模块最多一条。
8. 原生严重度为小写 `error`，位置是首个不一致实际端口的物理行，产品使用第 1 列。固定 GB18030 正文为“端口列表应按照“时钟、复位、输入、输出、双向端口”的顺序描述”。

## 产品接入

- 使用解析结构中的端口源码顺序和方向标志构造实际列表。
- 使用已建立的时钟/复位语义关系，不依靠 `clk`、`rst` 字符串猜测。
- 按时钟、复位、普通输入、输出、双向端口生成期望列表，并保持每组的源码顺序作为有界适配。
- 重复端口名按原生数量不一致路径跳过；每个模块只报告首个不一致端口。
- 严重度、固定正文、物理行和第 1 列与原生输出一致。
- 报告层把内部条款键映射为公开编号 `A-1-5`。

## 未解决边界

- 原生关系容器按设计记录逆序、记录内部顺序收集多个时钟或多个复位；完整关系生产顺序仍未恢复。产品对多时钟/多复位保持源码顺序，因此无告警不能证明等价。
- 自定义库语义、别名、跨层次传播、配置、generate、interface/modport 和宏展开关系。
- 错误恢复模块、重复模块键、扩展标识符及全局诊断排序。

因此本规则记为“证据支持的核心判据；集成源码适配器”，但安静结果仍为 `ManualReviewRequired`，不声明完整原生等价。
