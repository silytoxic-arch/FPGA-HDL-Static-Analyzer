## Recovered predicate

规则构造函数 `0x180025780` 安装 vtable `0x180efaca8` / `0x180efacf0`，slot 0 为
`FUN_1806b1620`。该函数在每个设计根下查找类型 `0xa4` 的实体端口容器，并把容器的
每个直接子节点作为独立候选。候选名称来自 `+0x48`，物理行号来自 `+0x214`。

对每个候选，原生函数读取源文件从开头至候选所在物理行，并仅在该候选的精确物理行
中以字节方式搜索连续字符 `--`。该行找不到 `--` 时，为该端口生成诊断。位于声明前一
行或后一行的注释不满足规则；同一物理行上的分组端口共享该行注释；字符串或其他文本
中的原始 `--` 字节也会满足搜索，因为该检查不经过词法注释分类。

原生消息区可恢复到“端口”和“无注释”等片段。产品实现据此逐端口报告
“端口 `<name>` 的定义行缺少注释”，并只检查 VHDL 实体端口，不检查 generic 或体系结构
内部 signal。

## 已验证边界

- 声明前一行的注释不算端口定义行注释。
- 分组声明会为同一行的每个端口分别建立候选并分别报告。
- 分组声明行带 `--` 时，该行全部端口通过。
- 多行端口声明按每个端口名称所在物理行判断。
- `--` 出现在字符串默认值中仍被原始字节搜索接受。
- 声明后一行的注释不回溯生效。
- generic 与体系结构内部 signal 不纳入该规则。

## 限制

类型 `0xa4` 的专有枚举名、错误恢复节点、扩展标识符、生成式接口、源文件编码转换、重复
设计根及原生诊断排序尚未完全恢复。产品使用解析器确认的实体端口和原始物理行执行相同
核心判据；不声明与厂商前端完全等价，干净结果仍保留人工复核语义。
