# GJB9765.4.14.c.3 运算符空格判据（核心逐字节判据已接入）

目标附件：`T-Linter.dll`，SHA-256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 原生静态观察

`FUN_1805c9e90` 以 `fgets(..., 0xff, ...)` 读取源文件，遇到首个字面 `--` 停止当前读取块余下扫描。它分别处理 `/=`，以及 `+`、`-`、`*`、`/`、`=`；显式排除 `**` 的配对星号。`=` 分支使用常量位图 `0x1400800000000000` 排除前一字节 `/`、`:`、`<`，并排除后一字节 `>`，使 `/=`、`:=`、`<=`、`=>` 不被普通等号分支重复处理。`/=` 分支还在后一字节为 `>` 时排除 `/=>`。分支仅接受相邻 ASCII 空格或 Tab，缺少任意一侧分隔时形成 Warning。证据 `ev_4714c6cdd73e074b9417da0ba3b318724c7493e865252ce39215b2c0ef88d199`。这是反编译伪代码观察，不等同原厂源码或运行结果。

## 产品接入

V1.4.24 取消完整物理行扫描，改为复现原始 `fgets(0xff)` 读取块：

- Windows 文本模式下每块最多 254 个数据字节，并按块递增诊断序号；
- 在首个字面 `--` 处截断，即使它位于字符串中；
- 识别 `/=` 和单个 `+`、`-`、`*`、`/`、`=`；
- 排除 `<=`、`:=`、`=>`、`**` 和 `/=>`；
- 只有紧邻两侧均为 ASCII 空格或 Tab 才不报告；
- 字符串中的运算符同样参与检查；
- 候选仍可读取注释起点字节作为右邻接，块末尾缺右邻字节的单运算符被跳过；
- 每个不合规运算符定位到其首字符并输出 Warning。

附件违反例 `INPUT1= '0'`、`B1/='1'`、`/1` 检出，遵循例不检出。回归测试还覆盖全部算术运算符、注释、字符串、字符串中的 `--`、幂运算、被排除的复合符号、异常 `/=>`、form-feed、254 字节边界和运算符紧邻注释。
