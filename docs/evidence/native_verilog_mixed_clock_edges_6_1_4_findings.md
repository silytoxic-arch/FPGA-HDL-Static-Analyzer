# GJB10157.6.1.4 原生判据恢复

对外规则编号采用官方三段式 `A-4-1`。目标文件为附件中的
`T-Linter.dll`，SHA-256 为
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 已观察事实

- 构造函数 `0x180022270` 注册规则键 `GJB10157_VLOG.6.1.4`，并安装虚表
  `0x180ef0a40`；slot 0 为 `FUN_18054f6c0`。
- slot 0 通过 `FUN_180545f70`、`FUN_18054efc0` 建立综合后连接模型，再调用
  `FUN_180552630` 执行规则判断。
- `FUN_180552630` 对设计记录进行模块名称归一化，并通过 `FUN_18054fd70`
  展开相关端点。端点少于两个时不进入双边沿判断。
- 每个准入端点通过 `FUN_1809b6870(endpoint+0x88, 0)` 取得边沿索引，并把
  `1 << index` 合入位掩码。掩码达到 `3` 表示同一关系族出现两种有效边沿。
- 达到 `3` 时，函数分别为此前保留的端点和当前冲突端点构造报告，随后退出该
  关系族遍历。因此原生报告粒度是每个冲突族两条，而不是一条汇总告警。
- 两条报告均使用端点编码的来源文件和物理行，不写入列；严重度均为
  `Warning`。
- GB18030 字符串 `0x180ef0aa4` 是 `时钟`，`0x180ef0a88` 是
  `不能同时使用上升沿和下降沿`，精确正文为
  `时钟<归一化名称>不能同时使用上升沿和下降沿`，无标点。
- 附件示例证明关系图覆盖同名信号上下沿、时钟生成器输出上下沿，以及
  `inv = ~CLK` 后的有效边沿翻转。
- 名称格式化辅助函数 `FUN_180553f80` 对普通反斜杠标识符去除前导反斜杠，
  但对部分 `$`、双反斜杠和数字前缀形式保留原表示。

## 产品有界适配器

- 在同一模块内对直接连续别名和一元反相连续别名进行循环安全的反向归一化；
  每经过一次反相就翻转有效边沿。
- 每个归一化时钟族保留第一个源码可表示的上升沿端点和下降沿端点；两者都存在
  时，在两个物理行各输出一条原生正文，列使用第 1 列占位。
- 正反例覆盖直接双边沿、时钟原语输出、一元反相、直接别名、同边沿重复使用和
  双端点报告重数。

## 推断与未知项

产品的直接/反相源码别名是对原生综合网表遍历的有界适配。完整图拓扑、端点遍历
顺序、库原语的反相属性、跨模块传播、多位时钟、复合表达式、生成结构、宏以及
特殊转义名称仍未知。未发现问题继续标记为 `ManualReviewRequired`，不宣称完整
专有前端算法等价。
