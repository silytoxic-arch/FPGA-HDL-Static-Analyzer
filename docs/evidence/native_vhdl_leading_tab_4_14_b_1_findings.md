# GJB9765.4.14.b.1 行首 Tab 扫描（核心判据部分恢复）

目标附件：`T-Linter.dll`，SHA-256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。完整静态分析记录见 `rea_vhdl_leading_tab_4_14_b_1_bundle.json`。

## 原生观察

规则槽 0 指向 `FUN_1805bda30`。该函数通过 `fopen`、`fgets(buffer, 0x200, file)` 逐块读取 VHDL 源码，并按块计数。首字节属于一组代码字符或为换行时跳过；否则向后扫描，先遇到 Tab 则跳过，先遇到另一组代码字符或换行则报告；非空块扫描到末尾仍未遇到 Tab 也报告。两组字符判断使用不同的常量位掩码。证据：`ev_18d4943dfaaee8f0aa7b3c890ddda29c8b39c5fe4fd31f7481114ce8ba9ee4f6`。

这段函数没有测量或比较 Tab 宽度。随包规则文字虽要求“统一制表符 Tab 的大小”，但不能把该文字当作本函数已执行的检查。首字符已属于代码字符的行直接跳过；仅有空格的非空行会报告。原生函数读取的是字节，注释行没有被预先排除。

## 产品接入和验证

`src/analysis/standard_evaluator.cpp` 按两个原生字节集合和 `fgets(512)` 的 511 字节最大载荷实现读取块扫描；超长物理行会拆成多个块，每块单独判断并递增诊断序号。`tests/standard_accuracy_tests.cpp` 验证空格缩进、Tab 缩进、仅有空格的块、注释、先遇到 Tab、511 字节边界和超长行第二块序号。附件违反例产生本规则诊断，遵循例无本规则诊断。
