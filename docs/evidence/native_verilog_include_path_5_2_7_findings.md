# GJB10157.5.2.7 原生 include 路径判据

## 目标与证据类型

目标为附件 `T-Linter.dll`，SHA-256：
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
以下为静态反编译观察，不是运行时执行结果。

## 二进制直接观察

- 构造函数 `0x180021a60` 安装的 vtable 首槽指向规则执行函数 `0x18053afd0`；证据
  `ev_af0e347e01ea6c4a2bbe1c2aa8728196d805d66f0895e1fd354c1452ff684e3b`。
- 执行函数遍历规则对象 `+0x68` 的模块名称映射。每个映射值先复制为 AST 根指针向量，
  只有向量长度恰为 1、指针非空且根类型为 `AST_MODULE(2)` 时，才读取该根 `+0x1e0`
  保存的源文件名并逐物理行打开文件；完整静态反编译见
  `reverse-tools/evidence/r2_7_include_decompile.txt`（SHA-256
  `502e6ea84b7b7fa49a332e1a35022be4a81750eca55f3a1f830a1ca997053be6`）。
- 每行先查找精确八字节 `` `include``，再查找该行任意位置的 `:`；两者都存在时报告。
  汇编中的 `0x60`（反引号）和 `0x3a`（冒号）比较进一步确认这一点；证据
  `ev_6abeb4923565b69c010a094b3e4106e612e4e7fc64537e6e37b6d4290670a65d`。

因此它不是通用绝对路径识别器，也不是 HDL lexer：

- `C:/...`、路径中间冒号以及同行其他位置的冒号均可触发；
- `/absolute/path` 没有冒号，不满足恢复出的核心谓词；
- 注释、字符串、畸形指令或未激活条件分支不会被原生逐行扫描过滤。

模块映射还确定了报告次数：

- 没有 `AST_MODULE` 的物理文件不会被本规则打开；
- 同一文件中的两个不同且唯一绑定的模块会各自打开该文件，因此同一命中行报告两次；
- 同名模块存在两个 AST 根时，该模块名的向量长度不为 1，整个映射项被跳过；
- 若一个唯一模块与一个重复同名模块组共享文件，只有唯一模块贡献一次扫描。

诊断常量 `0x180eeddf0` 的 41 字节 GB18030 文本为
“文件引用时,必须使用相对路径而不是绝对路径”，并且执行函数把严重级别固定为 `error`；
原始字节见 `reverse-tools/evidence/r2_7_include_message.txt`（SHA-256
`2135a254c5e90fbc7364abb5cf60c4f63f3084fa2413cc0290b3cfc1f7e6f96d`）。

## V1.4.18 产品实现

产品现在先按解析后的 Verilog/SystemVerilog 模块名建立全工程定义次数，再对每个源文件按
“唯一模块数”重复执行同一物理行判据。无模块文件不执行；同名重复定义不贡献扫描次数。
诊断位置使用原生已证实的文件和物理行，产品必须提供的列号固定为 1。已删除此前挂在该
GJB 条款下、但没有 DLL 证据的 Unix 斜杠绝对路径扩展，并使用恢复出的原生中文消息。

边界测试覆盖：盘符路径、路径中间冒号、普通相对路径、Unix 绝对路径、注释、未加引号
指令、冒号位于路径外、未激活宏分支、字符串文本、无模块文件、同文件不同模块、同名重复
模块，以及唯一模块与重复模块组混合。
