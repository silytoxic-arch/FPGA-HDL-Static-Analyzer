# R-5-2 同一复位线路同步/异步混用原生判据

目标为用户附件中的 `T-Linter.dll`，SHA-256 为
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。以下结论来自静态分析，未执行目标文件。

## 已观察事实

- 构造函数 `0x180022670` 注册 `GJB10157_VLOG.6.2.2`，最终虚表
  `0x180ef1200` 的 slot 0 是 `FUN_180557c70`；slot 1 是只接受
  `AST_MODULE(2)` 的 `FUN_1807238a0`。
- 主函数遍历关系记录；`FUN_1804dee00` 只在记录首字节小于 `2` 时接受该记录。
  被接受记录的名称经过 `FUN_1804df040` 归一化后进入 32 字节字符串向量，已有名称不会重复插入。
- 每个 `AST_ALWAYS(0x52)` 都递归收集 `AST_POSEDGE(0x65)` 与
  `AST_NEGEDGE(0x66)`；只有边沿节点总数恰好为 `1` 的过程继续检查。
- 主函数收集过程中的 `AST_REDUCE_BOOL(0x2d)`，只取向量中的第一个条件，再递归收集其
  全部 `AST_IDENTIFIER(0x13)`。
- 每个归一化后存在于异步控制名称向量的标识符都独立进入报告构造，没有观察到按名称、
  过程或物理行去重。
- `FUN_18003e420` 将标识符名称与 `0x180ef1248` 的 GB18030 常量拼接，精确正文为
  `<名称>同时作为了异步复位和同步复位`。
- 报告严重级别字面量为 `error`，位置来自匹配标识符的源文件和 `+0x210` 物理行，
  未观察到列字段。

附件违规例中，`RST` 先在双边沿过程中建立异步复位关系，随后出现在仅
`posedge CLK` 过程的首个条件中；合规例没有后一种同步条件使用。

## 产品有界实现

- 在同一 Verilog/SystemVerilog 模块中，以解析器确认的异步控制集合为候选。
- 仅检查事件控制中恰好含一个 `posedge`/`negedge` 的 `always`/`always_ff`。
- 仅检查该过程源码中的第一个 `if` 条件；其中每个匹配标识符分别报告，包括同一行的重复标识符。
- 正文恢复为原生固定格式，位置使用匹配标识符的物理行和列 `1` 表达原生“无列”。
- 原有通用 `RTL-MIXED-RESET-MODE` 仍供非标准分析使用，但不再汇总映射为本条标准结果。

## 未知边界

关系记录类型字节 `0`、`1` 的完整语义、异步关系生产器、跨模块与层次名称作用域、
库原语复位端、宏、`generate`、非 `if` 条件的前端降低、转义名称归一化和全局诊断顺序
仍未恢复。产品只接入确定的同模块首个 `if` 子集；无诊断保持 `ManualReviewRequired`，
完整专有前端算法等价仍为未完成。
