## Recovered predicate

`FUN_1805d2930` 对每个当前分析根执行以下流程：

1. 遍历全局设计记录，仅接纳 `record+0x2f3 != 0` 且 `record+0x2d8 != 0` 的实体候选。
2. 比较当前分析根与候选在 `+0x1e0` 的字符串，只有完全相等的记录才通过。结合规则语义、附件正反例和后续报告字段，该字符串是同一源文件的绑定键；不同文件中的实体不会合并计数。
3. 通过 `FUN_1805d3350` 按记录指针去重并保存每个候选。
4. 候选数量必须严格大于 1 才进入报告分支。
5. 报告分支遍历完整候选集合，不只报告第二个实体；每条诊断采用对应实体节点 `+0x214` 的物理行号。

原生 GB18030 告警常量位于 `0x180efdce8`，解码为“一个文件宜对应一个设计实体”。规则严重度常量为 `Warning`。

因此，恢复出的核心谓词为：同一个 VHDL 源文件含有两个或更多实体声明时，对该文件中的每个实体逐条报告；architecture 数量和其他源文件中的实体不参与该文件计数。
