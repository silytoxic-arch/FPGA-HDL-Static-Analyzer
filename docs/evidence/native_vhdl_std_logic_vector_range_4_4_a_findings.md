# GJB9765.4.4.a 原生判断恢复

## 目标与身份

- 规则：`GJB9765_VHDL.4.4.a`，多位信号、变量定义时必须设置位宽。
- 二进制：`T-Linter.dll`，SHA256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
- vtable slot 0：`FUN_18062f980`，伪代码证据 `ev_49fd7ba62f3c0d44a67f9ed996b129de149549d7d6d2b0662f358f472b529551`。
- 构造函数证据：`ev_d30df8482fff0d7d3b0beb84a7a8c1973ad902367d3d3e5dd760a48067c9b12f`。

## 恢复的核心判断

入口先调用递归收集器 `FUN_180630500`。收集器接受四类 AST 节点：

- `0x78`
- `0x79`
- `0x0a`
- `0x9c`

入口随后只检查收集结果中的类型 `0x9c`。对该节点：

1. 读取字段 `+0xd0` 上的类型名；
2. 与只读 ASCII 字符串地址 `0x180e81368` 做完整比较，内容为 `std_logic_vector`；
3. 名称相等且直接子节点数量小于 2 时报告 Warning；
4. 报告位置取该子类型节点的物理行号字段 `+0x214`。

附件约束声明 `std_logic_vector(7 downto 0)` 对应带范围节点，而不带括号范围的声明满足“少于两个子节点”的报告条件。报告文本地址 `0x180f061b8` 的 54 字节按 GB18030 解码为“std_logic_vector数据类型的对象在定义时应有位宽范围限制”。

产品实现会检查以下无括号范围出现位置：

- 泛型声明；
- 实体端口声明；
- 常量、信号和变量声明；
- `array ... of std_logic_vector` 元素子类型。

类型转换本身带有括号，不会被误判为未约束声明；注释由词法分析器排除。

## 附件验证

违反例活动代码中有 5 处无范围 `std_logic_vector`：

- 泛型 `G_MY_GENERIC`；
- 常量 `c_my_constant`；
- 信号 `int_sig1`；
- 数组元素类型 `my_type`；
- 进程变量 `v_my_var1`。

正确例中的所有同名类型均带 `(downto/to)` 范围，结果为零告警。

## 未决范围

专有枚举 `0x78/0x79/0x0a/0x9c` 的完整名称、`range <>`、无约束数组元素传播、别名与包限定名称、扩展标识符、错误恢复、重复设计根和诊断顺序仍未完全恢复。未告警结果仍要求人工复核，不宣称与完整供应商前端等价。
