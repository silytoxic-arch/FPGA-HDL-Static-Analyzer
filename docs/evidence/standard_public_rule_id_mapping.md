# GJB 规则公开编号映射证据

## 目标

FPGA HDL Static Analyzer 对外显示标准索引编号；内部继续使用完整 GJB 条款号作为兼容键和证据追溯键。报告中的 `ruleId` 是公开编号，`clauseId` 是原标准条款。

## 输入与完整性

- GJB 9765-2020 扫描版 PDF：SHA-256 `7f995074357d435be00c523c0522ca617a1c7dc4dfd1cf7512e91a52960cea63`，35 页。
- GJB 10157-2021 扫描版 PDF：SHA-256 `e2afe86421ec793a338af33fa3288c5f7e99b458d76cb7991bb79398c397dc27`，51 页。
- T-Linter `examples_html` 中与当前规则清单对应的样例文件。
- 固化映射 `src/analysis/standard_rule_public_ids.inc`：SHA-256 `79fc16383fd0e1e28f293394fa5ed7a5da44db39fcdc2f5bed20c352540f1bd7`。

## 已观察事实

1. 两份 PDF 均为无文本层的扫描件；使用 180 DPI 页面渲染和 macOS Vision OCR 读取标题及附录。
2. GJB10157 附录 A 使用三段索引，例如 `GJB10157.5.2.1` 对应 `R-2-1`；建议类条目保留标准中的 `A-*`，例如 `GJB10157.5.2.18` 对应 `A-2-8`。
3. GJB10157 的 103 条产品规则中，95 条索引同时出现在 T-Linter 样例源码名称（`utest_GJB_R_*` 或 `utest_GJB_A_*`）中；其余 8 条由 PDF 正文或附录补齐：10.1、10.2、10.3、10.4、12.2、6.2.5、7.2.2、8.3。
4. GJB9765 正文逐条标明“强制准则”或“建议准则”；按正文顺序分别形成同组内的 `R` / `A` 数字序号。附件规则入口未收录的正式条目保留编号空档，不能把后续条目向前压缩。

## 产品映射

- GJB10157：逐条使用标准附录的 `R-组-序号` 或 `A-组-序号`，不从条款号机械推导。
- GJB9765：逐条使用正文的强制/建议属性和同组顺序建立三段纯数字编号。例如：
  - `GJB9765.4.2.a` → `R-2-1`
  - `GJB9765.4.8.e` → `A-8-1`
  - `GJB9765.4.5.f.2` → `A-5-3`
  - `GJB9765.4.11.c` → `R-11-3`（未收录的 `4.11.b` 保留空档）
- 非 GJB 内建规则（例如 `RTL-LATCH-INFERRED`）保持原编号。

## 验证边界

- 编译期要求公开编号表与 209 条规则清单等长，并拒绝任何不是 `R-X-X` / `A-X-X` 的编号；
- 209 条规则生成的公开编号必须全部非空，并在各自标准配置内唯一；跨标准允许复用同一编号。
- `findStandardRuleDetail` 和 `findStandardRuleExample` 同时接受公开编号与旧条款号。
- GUI、CLI、TXT、JSON、SARIF、HTML 对外使用公开编号；JSON/SARIF 保留 `clauseId`。
- 禁用规则和严重级覆盖同时接受公开编号与旧条款号，已有工程配置无需迁移。
- GJB9765 的公开编号来自正文强制/建议属性及正式顺序，不把条款字母或嵌套点号直接拼入编号。
