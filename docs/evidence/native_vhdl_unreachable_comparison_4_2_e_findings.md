# GJB9765.4.2.e 原生不可达比较恢复记录

目标为附件 T-Linter.dll，SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。本记录为 Ghidra 12.1.4 离线静态分析，不是原软件运行观察。

## 已恢复判断

入口 `0x1805d0e00` 重建名称/宽度映射后，调用递归收集器 `0x1805d1d00`。
收集器接受类型 `0x34..0x36`、`0x3a..0x3b`、恰好两个子节点的关系节点，且左侧必须是没有子节点的直接名称 `0x13`。右侧直接常量 `0x10` 提供数值记录。

最终检查要求左侧宽度不为 -1、右侧恰有一条记录且宽度已知。设 `M = 2^W - 1`、右侧值为 C，报警分支只有：

- `0x36`（EQ）：C > M。
- `0x3a`（GE）：C > M。
- `0x3b`（GT）：C >= M。

收集的 LT/LE 节点没有对应报警分支，NE 不进入收集器；不交换操作数，不等同于通用的“条件恒真/恒假”规则。报警文本为“设计中不宜存在多余代码或不可达分支”。

反编译器将浮点调用参数错误显示为 undefined4，故另外核对机器指令：`0x1805d0e5f` 从 `0x180ef3ea8` 加载 double 2.0（字节 `0000000000000040`），`0x1805d10ea` 转换宽度，`0x1805d10f1` 调用数学函数，随后转换结果并减一。报告分支的比较方向也与伪代码一致。
