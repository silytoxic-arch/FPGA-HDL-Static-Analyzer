## Recovered predicate

节点接收函数仅接收 `AST_MODULE(2)`。主函数对模块名称/路径派生键执行规范化，并与规则上下文保存的顶层名称比较；只有相等的模块进入检查。

原生函数在该模块下递归收集三类节点：

- `AST_ASSIGN (0x4d)`：连续赋值；
- `AST_ASSIGN_EQ (0x55)`：阻塞过程赋值；
- `AST_ASSIGN_LE (0x56)`：非阻塞过程赋值。

阻塞和非阻塞过程赋值直接报告。连续赋值会读取第二个子节点（右值根），仅当其类型不是 `AST_IDENTIFIER(0x13)` 时报告。因此直接连线 `assign OUT4 = IN2;` 不属于胶合逻辑，而 `assign OUT4 = IN1 & IN2;` 的右值是运算表达式，会报告。附件违规样例中的顶层时序 `always` 赋值也按过程赋值报告。

完整函数还证明每个收集到的赋值节点都会独立追加结果，没有首个命中即退出或正文去重。同一行两次对同一左值赋值会保留两条字节相同的诊断；一条连续赋值语句中的多个 net assignment 在前端形成多个 `AST_ASSIGN`，分别判断。

两个报告分支共用同一正文构造链。DLL 字节串 `0x180f13930`、`0x180f13920` 和 `0x180ee83b0` 分别解码为 `顶层`、`包含胶连逻辑` 和 `警告`；字符串加法辅助函数证明完整正文为 `顶层<规范化模块名>包含胶连逻辑<规范化左值名>`。模块名和左值名先通过 `FUN_1804df040` 去除 Yosys 前导反斜杠。位置取赋值节点的文件 `+0x1e0` 与物理行 `+0x210`，没有写入列号。

- 顶层阻塞/非阻塞过程赋值逐项报告；
- 连续赋值的右值为直接标识符或有界标识符选择时不报告；

- 已实例化子模块内部的功能逻辑不按顶层胶合逻辑报告；
- 条件编译先筛选活动分支。

产品使用上述原生动态正文、Warning、物理行和第 1 列占位，并保留逐赋值重数及逗号分隔 net assignment 的独立判断。
