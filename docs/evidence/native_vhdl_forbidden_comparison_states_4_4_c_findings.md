## Recovered predicate

- `FUN_18063eff0` 递归遍历 AST，但只在当前节点类型位于 `0x34..0x37` 或 `0x3a..0x3b` 且恰好有两个直接子节点时收集候选。由已恢复的相邻规则可将这六类限定为 `LT/LE/EQ/NE/GE/GT` 关系节点。
- 对关系节点只查看两个直接子节点，不递归借用操作数内部的字面量：
  - 类型 `0xb2/0xb3` 的直接字面量子节点直接加入候选；
  - 类型 `0x10` 的常量先调用 `FUN_1801a85c0(name, "XxOoBb", 0, 6)`；该函数是字符集合 `find_first_of`，返回 0 时整个关系不收集，因此以 X/x、O/o、B/b 开头的进制字面量被排除，基数标记不会被误认为状态 X。
- `FUN_18063e9d0` 对每个候选的名称字段分别查找精确大写字符 `Z`、`U`、`H`、`L`、`-`、`W`、`X`。任意一个存在即对该候选报告一次；一个字面量含多个禁止字符仍只报告一次，两个直接字面量都命中则分别报告。
- 诊断模板位于 `0x180f076f0`，GB18030 解码为“条件判断表达式中不能与 'Z', 'U', 'H', 'L', '-','W'，'X'进行比较”。
- 原生检查不要求字面量的其他字符都属于 std_logic 状态集合；只要直接字面量名称包含上述字符之一就命中。

- 将原有“同一表达式边界内存在关系符即报告”的近似算法替换为二元关系驱动的直接操作数检查。

- 仅在剥除包围整个操作数的括号后，操作数恰好是一个字面量时报告；函数调用、拼接、算术、逻辑或限定表达式内部的元值不再被错误借入外层关系。
- 按原生精确字符集合搜索大写 `XZUHLW-`，不把小写字符、问号或十六进制基数标记扩大解释为本规则。
