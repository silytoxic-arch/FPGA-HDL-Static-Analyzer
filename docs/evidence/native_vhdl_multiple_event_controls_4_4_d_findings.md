# GJB9765.4.4.d VHDL 多 event control 规则恢复记录

## 目标与二进制身份

- 目标规则：`GJB9765.4.4.d`
- 附件版本：T-Linter V3.1.4.25120520251205115359
- `T-Linter.dll` SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 构造函数：`0x180027150`
- slot 0：`FUN_1805d8800`（`0x1805d8800`）
- 关键辅助函数：`FUN_1805d8f40`（`0x1805d8f40`）、`FUN_1805d8fb0`（`0x1805d8fb0`）
- 本记录来自 Ghidra 12.1.4 静态反编译，不代表观察了原软件运行。

## Recovered predicate

- `FUN_1805d8f40` 递归遍历节点，并在进入每个类型 `0x52` 的进程/always 子树前把事件计数器清零。
- `FUN_1805d8fb0` 递归遍历该子树。类型 `0xad` 的节点名称经大小写折叠后，只有长度和内容都精确等于 `event` 才计数。
- 类型 `0x65` 或 `0x66` 的边沿事件节点也直接计数。
- 每次计数后，只要累计值大于 1，就把当前事件节点加入待报告集合。
- 主函数逐个报告待报告节点，使用节点自身的源文件和行号。因此一个进程含 N 个事件构造时会报告 N-1 次，并定位到第二个及之后的事件。
- 原生实现不按信号名称或边沿极性去重。同一信号分别使用上升沿和下降沿仍属于两个 event control；进入另一个进程后重新计数。

## 产品接入

- `GJB9765.4.4.d` 不再复用“不同信号的多个时钟”通用诊断，而使用独立 VHDL 进程级检查。
- 识别 `signal'event` 以及 `rising_edge(...)`、`falling_edge(...)`，第二个及之后的构造逐个报告。
- 注释与字符串由公共词法器排除；不同进程各自独立计数。
- 通用 `RTL-MULTIPLE-CLOCKS-PER-PROCESS` 仍保留给其他规则，避免改变 `GJB9765.4.9.d` 的既有语义。

## 已知边界

- 类型 `0x52/0x65/0x66/0xad` 的完整枚举名、前端对 IEEE 边沿函数的重载解析与 AST 降级细节仍未完整恢复。
- 产品目前按词法函数名识别 `rising_edge`、`falling_edge`，尚不能证明同名用户函数是否应排除。
- 复杂属性前缀、生成后的进程、错误恢复节点及原生遍历顺序仍可能产生差异。
- 未检出保持 `ManualReviewRequired`，不宣称完整原生等价。

## 回归覆盖
