# GJB9765.4.7.b VHDL FOR 循环变量写入规则恢复记录

## 目标与二进制身份

- 目标规则：`GJB9765.4.7.b`
- 附件版本：T-Linter V3.1.4.25120520251205115359
- `T-Linter.dll` SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 构造函数：`FUN_1800294f0`（`0x1800294f0`）
- slot 0：`FUN_1806073c0`（`0x1806073c0`）
- 循环递归器：`FUN_180607b10`（`0x180607b10`）
- 赋值收集器：`FUN_180607b90`（`0x180607b90`）
- 本记录来自 Ghidra 12.1.4 对用户附件的离线静态反编译，不代表观察了原软件运行。

## Recovered predicate

- `FUN_1806073c0` 对每个设计根清空当前循环名和一个按节点排序的违规集合，然后递归遍历整棵树。
- `FUN_180607b10` 遇到类型 `0x5c` 的节点时，把节点 `+0x48` 名称保存为当前循环变量名，并调用 `FUN_180607b90` 扫描这个循环的完整子树；随后仍递归其所有子节点，因此嵌套 FOR 又会作为独立根检查。
- `FUN_180607b90` 递归寻找类型 `0xa2` 且至少有两个子节点的赋值节点。它将第一个子节点的 `+0x48` 名称与当前循环变量名作精确字节比较；相同则把第二个子节点保存到违规集合。
- 主函数最终逐条使用保存节点的源位置报告。`0x180f02838` 的 GB18030 文本为“禁止在for循环体内修改循环变量”。
- 附件的 `i := i + 1` 与上述两子节点赋值形状一致；仅在右值读取 `i` 不满足左端名称比较，不报告。

## 产品接入

- 识别可完整配对的顺序 `for name in ... loop ... end loop`，排除 `for ... generate`。
- 在完整循环体（包括嵌套 IF、CASE、WHILE、LOOP 和内层 FOR）中检查 `:=` 左端。
- 左端与当前或任一外层 FOR 变量按 VHDL 大小写不敏感规则相等时报告。
- 普通信号赋值 `<=`、读取循环变量以及赋值其他变量不报告。
- 同一源码赋值同时匹配同名嵌套循环时按位置去重。

## 已知边界

- 专有 AST 类型 `0x5c/0xa2` 的调试枚举名、错误恢复循环、循环参数别名、生成后节点、扩展标识符和原生有序集合遍历顺序仍未完全恢复。
- 产品仅对结构完整的顺序 FOR LOOP 作肯定判断；无法配对的循环保持人工复核，不伪判合规。
- 不宣称与专有 VHDL 前端的全部节点降级和诊断顺序完全等价。

## 回归覆盖

`tests/standard_accuracy_tests.cpp` 覆盖直接修改、只读循环变量、修改其他变量、嵌套内外层变量、内嵌 WHILE 后继续修改、同名嵌套位置去重以及 FOR generate 排除。
