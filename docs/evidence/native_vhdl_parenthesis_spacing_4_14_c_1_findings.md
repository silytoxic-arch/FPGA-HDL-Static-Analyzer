# GJB9765.4.14.c.1 括号内侧分隔判据（核心逐字节判据已接入）

目标附件：`T-Linter.dll`，SHA-256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 原生静态观察

`FUN_1805c86a0` 使用 `fgets(..., 0xff, ...)` 逐块读取源文件，在首个字面 `--` 处停止当前块扫描，并以可变布尔标记汇总每块结果。打开侧位图 `0x18500000600` 解码为 Tab、LF、空格、双引号、单引号和 `(`，数字另有分支放行；关闭侧位图 `0x3ff028500000600` 解码为 Tab、LF、空格、单双引号、`)` 和数字。其他相邻字节会置位。

打开括号后若紧随大小写不敏感的六字节 `others`，代码会把标记直接清零，而不只是跳过当前括号，因此可清除同一读取块中更早的违规；后续违规又会重新置位。每个最终仍置位的块最多形成一条 Warning。证据 `ev_605bc62247ae26de1fd44533e8f014675f07dbb94c4994938c014d6bfa0bb603`。这是反编译伪代码观察，不是原厂源码或运行观测。

## 产品接入

V1.4.24 改为原始 `fgets(0xff)` 读取块扫描，并接入：

- Windows 文本模式下最多 254 个数据字节的独立读取块和块序号；
- 首个字面 `--` 截断，包括字符串内的双连字符；
- 两个精确允许字符集合，其他 Unicode/C 空白不自动放行；
- 字符串内容参与检查；
- `(others` 按出现顺序清除已有行标志，之后的违规可再次置位；
- 每个最终置位的读取块最多报告一次，定位到最后一次有效置位括号。

附件违反例中的 `if (INPUT1...)`、`elsif (B1...)`、`conv_integer(INPUT1)` 检出，遵循例不检出。边界测试覆盖字符串、注释、数字、单双引号、嵌套同侧括号、空括号、form-feed、254 字节分块，以及 `(others` 跨块和前后违规的顺序作用。
