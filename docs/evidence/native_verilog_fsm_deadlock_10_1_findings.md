## 原生证据

`FUN_1804fe030` 对每个设计根建立关系容器，遍历状态/转换记录，并在候选关系标准化后对每个对象调用 `FUN_180502c50`。该辅助函数继续构造和遍历状态节点关系，最后同时进入 `FUN_1804feaf0` 与 `FUN_1805000b0` 两条规则专用诊断路径。入口不是对 `case`、状态名称或文本关键字的简单匹配，而是先形成 FSM 关系图再分析节点。

V1.4.176 对四个函数重新执行只读 Ghidra 反编译，原始输出保存于
`reverse-tools/evidence/r14_1/native_core_functions.txt`（SHA-256
`6d0d4e8759c1c9ea007a7c83ce6c8134c08519169889bd7e21758033c50c6731`）。
常量区读取保存于 `reverse-tools/evidence/r14_1/native_strings.txt`（SHA-256
`e84afd6420f305449df8d9600cda0971c4afd921c0b4a26e8d641e85a3983d86`）。

本轮新增确认：

- `FUN_1804feaf0` 是死循环路径。它在候选出边集合大小为一、唯一目标等于当前状态且名称不是精确 `default` 时进入报告，并拼接 GB18030 文本 `禁止使用死循环状态机，`、状态机变量名、`状态` 和状态名。
- `FUN_1805000b0` 是不可达路径。它查找精确四字节键 `init`，把该关系复制为遍历起点，调用 `FUN_1804fd790` 形成可达集合；随后逐个枚举图状态，对不在可达集合中的状态分别报告。消息拼接为 `状态机变量<变量名>状态<状态名>不可达`。
- 两条报告路径都把严重级别字符串设为 GB18030 `警告`，不是“错误”。产品目录已据此改为 Warning。

## Recovered predicate

产品接入两个无需猜测复杂表达式语义即可证明的图子集：

1. 先用既有严格适配器证明一进程状态更新，或二进程 `state <= next_state` 直接传递；
2. `case` 控制和状态标签必须是简单标识符或数值原子；
3. 每个显式状态分支都必须能解析出至少一个落在同一状态集合内的直接目标，才把转换图视为完整；
4. 若某状态的完整去重目标集合只有它自身，则按原生死循环路径逐状态报告；
5. 若显式 `initial` 或受控复位分支能够唯一给出属于该状态集合的简单初始状态，则从该状态遍历完整转换图，并按原生不可达路径逐个报告未访问状态。

状态变量和符号状态名按 Verilog 标识符规则保持大小写敏感；只有数值字面量的进制/未知位字符做 ASCII 小写归一化。

普通双向循环不报告；含显式离开边的状态不报告；目标表达式复杂、分支没有可解析目标或图不完整时不下自动合规结论。

## 验证

`tests/standard_accuracy_tests.cpp` 覆盖：

- 单一自环吸收状态报告，并验证原生 Warning 严重级别与消息格式；
- 直接二进程 FSM 的吸收状态报告；
- 两状态循环不报告；
- 自环同时存在显式离开边时不报告；
- 从显式 `initial` 状态出发的可达闭环不报告；
- 与初始状态断开的双状态子图逐状态报告不可达；
- 初始目标不属于显式状态集合时不猜测不可达；
- `IDLE` 与 `idle` 保持为两个不同状态；
- 转换图不完整和 `casex/casez` 通配语义不做自动判定。

## 未恢复部分

- 原生 `init` 关系的全部生产路径、多个初始节点的合并与优先级；
- 条件常量折叠、互斥性与可满足性；
- 宏、generate、层次、别名、多驱动和通配 case；
- 两条原生诊断路径的精确告警文本、数量和顺序。

因此本次完成了死循环与 `init` 可达性两条核心路径的有界源码适配；复杂或不完整图仍保持人工复核，不宣称完整原生等价。
