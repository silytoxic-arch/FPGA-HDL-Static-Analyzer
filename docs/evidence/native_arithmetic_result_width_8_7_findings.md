# GJB10157.8.7 原生算术结果位宽判据

目标：附件 `T-Linter.dll`，SHA-256
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
以下内容来自 Ghidra 12.1.4 静态反编译，并非运行时观察。

## `FUN_1805790b0` 根节点准入

槽 1 接受 AST 类型 `0x02`，以及 `0x4d..0x56` 中由位掩码 `0x305`
选出的 `0x4d`、`0x4f`、`0x55`、`0x56`。结合已恢复映射，这包括模块、
连续赋值、单元连接路径、阻塞赋值和非阻塞赋值。主入口
`FUN_180577640` 对普通赋值推断目标宽度，并把算术 RHS 及目标宽度传给
`FUN_1805790d0`。

## `FUN_1805790d0` 运算分派

helper 按 `node_type - 0x3c` 分派：

- `0x3c/0x3d`（ADD/SUB）：为每个直接子节点建立“操作数序号→推断位宽”映射。
  任一操作数位宽大于目标位宽时立即违规；操作数位宽等于目标位宽时，通常也
  违规，但存在下面已恢复的拼接豁免。该分支没有比较两个标识符是否相同，因而
  `A-A` 不会因恒等于零而获得额外豁免。
- `0x3e`（MUL）：遍历全部直接子节点，对每个子节点调用 `FUN_1808f4650`
  推断位宽并求和；当 `target_width < sum(child_widths)` 时返回违规。
- `0x3f/0x40`（DIV/MOD）：对整个运算节点执行宽度推断，并在
  `target_width < inferred_width - 1` 时报告。`FUN_1808f46c0` 对这两个
  节点递归遍历直接子节点并取最大子宽度；对两个直接信号的有界形态，
  `inferred_width = max(left_width, right_width)`。
- `0x41`：没有对应分支。
- `0x42`（POW）：要求恰好两个子节点且第一个子节点类型为 `0x13`
  （跨规则映射为 AST_IDENTIFIER）。分别推断底数和指数操作数位宽，且指数位宽
  必须大于零。DLL 数据段 `0x180ef3ea8` 为 IEEE-754 `2.0`，
  `0x180e836b8` 为 `1.0`，最终在
  `target_width < (int)(pow(2.0, exponent_width) - 1.0) * base_width - 1`
  时报告。这里使用的是指数操作数的**位宽**，不是指数运行值。

## ADD/SUB 拼接豁免的字段与顺序证据

`FUN_1805790d0` 仅在操作数节点类型为 `AST_CONCAT(0x22)` 且直接子节点数大于
1 时复制其最后一个子节点 `+0x88` 的三指针向量，并逐字节检查：向量为空或
每个字节均为 `0` 时，记录该操作数序号。随后处理等宽操作数时，只有未记录的
序号才计为违规。

同一 DLL 的宽度推断函数 `FUN_1808f46c0` 在 `AST_CONSTANT(0x10)` 分支以
`(+0x90)-(+0x88)` 计算常量位宽，确认这里是常量位状态向量，而非字符串。
Yosys 官方 `AstNode` 定义中相应字段为 `std::vector<RTLIL::State> bits`；官方
`RTLIL::State` 定义又确认 `S0=0`、`S1=1`、`Sx=2`、`Sz=3`。因此 DLL 的逐字节
条件精确表示“空 bits 向量或全部为 S0”。

Yosys 官方 Verilog grammar 的 `concat_list` 递归先构造右侧列表，再把左侧表达式
追加到 children 尾部，所以 AST 最后一个子节点对应源码拼接最左项。产品据此
恢复以下原生条件：

- `{1'b0, A}` 的最左项 bits 全为 S0，可获得等宽豁免；
- `{1'b1, A}`、`{1'bx, A}` 不满足；
- 标识符、选择和其他受支持结构节点自身的 bits 向量为空，DLL 也将其视为满足；
- 单项 `{A}` 因直接子节点数不大于 1 而不满足；
- 即使满足拼接条件，操作数宽度大于目标时仍然违规。

## 本轮产品接入

乘法分支的判定条件已经完整到足以支持固定宽度、两个直接信号操作数：结果
所需位宽是两个操作数位宽之和，目标小于该值即报告。例如两个 3 位信号相乘，
5 位目标报告，6 位目标不报告。

DIV/MOD 分支现已按原生的非常规阈值接入两个直接、静态定宽信号操作数；没有
用通常的 HDL 经验公式替换它。POW 也接入两个直接静态定宽信号的有界子集，
仅在公式可精确转换且原生有符号整数乘减不会溢出的范围内报告；字面量底数按
原生 AST_IDENTIFIER 门槛排除。ADD/SUB 继续使用已接入的有界双信号判据。
## 嵌套算术表达式宽度

`FUN_1808f4650` 包装器把宽度初始化为 `-1`，并把第五个字节参数传给
`FUN_1808f46c0`。GJB10157.8.7 在 ADD/SUB、MUL、DIV/MOD 和 POW 的全部五处调用
前均有 `MOV byte ptr [RSP+0x20],0`；Windows x64 ABI 中这是第五参数。因此规则
使用的是 helper 的 flag-zero 路径。

该路径对嵌套 ADD/SUB/MUL/DIV/MOD 取子节点最大宽度；对嵌套 POW、单目正负号
传播第一个子节点宽度；拼接求各项之和，复制求常量次数乘内容宽度。最外层规则
分支仍使用各自公式，尤其最外层 MUL 才会对两个直接子节点的已推断宽度求和。

产品现递归支持由静态定宽标识符/选择、显式定宽字面量、拼接/复制、括号和单目
正负号组成的这些算术形态。其他 AST 运算符、函数、动态选择、未解析参数、达到
`0x1000000` 原生实现上限的位宽、单元端口绑定和诊断去重仍属于人工复核边界。
