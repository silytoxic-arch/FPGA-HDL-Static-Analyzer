# T-Linter 单一顶层配置恢复记录

## 目标与身份

- 样本：`T-Linter.dll` V3.1.4.25120520251205115359。
- SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
- 导出生产者：`Yosys::CheckRule::setTopModule`，地址 `0x1806298c0`。
- 共享字符串：`DAT_18135b808`。
- Verilog 消费者：`FUN_180543030`、`FUN_1806fbb10`、`FUN_1805437e0`、
  `FUN_18052cd30`、`FUN_180555380`。
- VHDL 消费者：4.2.d 的 `FUN_180782710`、4.9.h 的 `FUN_18060b400`、4.2.c 的
  `FUN_18078ae30`。4.2.c 不是简单的“只检查顶层”，而是只豁免所选顶层的 `INOUT` 边界。

以下结论来自对上述 DLL 的只读 Ghidra 反编译，不是供应商源码，也没有执行目标程序。

## 观察

1. `setTopModule` 对普通名称调用 `FUN_180623a30`，生成带单个前导反斜杠的 Yosys 内部名称；已经以 `\\` 或 `$` 开头的名称不再添加前缀。
2. 该函数按完整长度和 `memcmp` 遍历已解析设计。不存在时返回失败；成功时把规范名保存到 `DAT_18135b808`。
3. 三个 Verilog 规则消费者读取同一字符串，分别把它作为“只检查此顶层”或“跳过此顶层”的边界。
4. `FUN_180782710` 首先用 `DAT_18135b808` 构造查找键，在设计表中解析记录；随后还对记录中的两个名称字段做完整长度和字节比较，成功后才收集 `AST_ARCHITECTURE` 直接子项。
5. `FUN_18052cd30` 精确解析该名称对应的 `AST_MODULE`，只在该模块内执行 5.2.10 的
   驱动集合减负载集合；`FUN_180555380` 仅对名称相等的设计记录进入 6.1.7 的直接时钟
   关系与后续层次图路径。
6. `FUN_18060b400` 仅对名称相等的 VHDL 设计记录执行 4.9.h 的时钟域收集。
7. `FUN_18078ae30` 的两个候选循环都对当前 entity 名称与该字符串执行完整相等比较。
   非顶层候选直接报告；顶层候选只有在目标端口带 `+0x104` 时豁免。相邻规则及附件把
   该字节确认到 `INOUT` 模式，因此产品按 architecture/entity 实现同一边界。

## 产品映射

- `AnalysisOptions::topModule` 保存显式选择；CLI 使用 `--top-module NAME`，配置文件使用 `top-module NAME`。
- Verilog 普通名称和带前导反斜杠的规范名均映射到产品词法器保存的不带反斜杠名称；比较保持大小写敏感。
- VHDL entity 按语言大小写不敏感语义解析。该点是基于 VHDL 语义的产品适配；原生前端规范化函数的正式名称仍未知。
- 显式名称必须在当前标准适用的设计单元中唯一命中。缺失或重复时分析产生错误并在标准规则执行前失败关闭，不回退到实例图根。
- 未提供显式名称时保留原有实例图根兼容模式，但无告警仍为 `ManualReviewRequired`，不把推断根等同于原生配置。

## 验证

- Verilog 多根工程：选择 `top_a` 后，5.3.2/5.3.3 只检查 `top_a`，5.3.4 把另一个根 `top_b` 视为非顶层。
- Verilog `\\top_a` 与普通 `top_a` 得到相同选择。
- 缺失顶层产生明确错误，三个顶层相关规则均不猜测结果。
- VHDL 多根工程：配置 `TOP_B` 能大小写不敏感地只选择 `top_b` 的 architecture 运行 4.2.d。
- Verilog 多根工程：5.2.10 和 6.1.7 只接受显式选择的模块；5.2.18 的宽泛冗余映射不受
  5.2.10 过滤影响。
- VHDL 多根工程：4.9.h 只接受显式选择的 entity，并覆盖大小写不敏感选择。
- VHDL 多根工程：4.2.c 只豁免所选 entity 的 `INOUT` 三态；切换顶层后豁免随之转移，
  顶层 `OUT` 与非顶层 `INOUT` 均报告。

## 未知范围

原生对 VHDL 扩展标识符、Verilog `$` 内部名称、重复设计记录、库/配置绑定及损坏语法恢复的完整行为仍未知。4.2.c 的顶层/INOUT 组合边界已经恢复，但其复杂关系候选生产者仍未完全解释。显式配置解决了已证实消费者的选择偏差，但没有恢复各规则剩余的全部前端降低和综合数据库语义，因此不能据此宣称相关规则完整等价。
