## Recovered predicate

- 主函数按设计单元清空候选、驱动和已报告名称集合。
- 类型 `0x78` 的声明名称进入候选集合；`FUN_1805fbc20` 还从类型 `0x76` 的上下文中选择满足字段 `+0xa1` 的声明加入候选集合。
- 对类型 `0x56`、`0xa2` 的赋值，主函数取第一个子节点作为目标，规范化名称后加入驱动集合。
- 原生实现还解析工程连接记录；记录种类 `1`、`2`、`7` 可把候选名称加入驱动集合，说明端口方向和层次连接参与驱动判定。
- `FUN_1804d0140` 依据形式端口字段 `+0xa0/+0xa1/+0x104` 构造连接种类；这些字段已由相邻端口后缀规则和附件正反例分别确认为 `IN/OUT/INOUT`。`OUT/INOUT` 对应的种类 `1/2` 会进入驱动集合。
- 连接记录的第二次遍历只在种类 `3` 且记录标志为零时进入未驱动诊断分支；它再次要求名称属于候选集合、不在驱动集合且未报告。结合构造器可知，这是内部实际信号作为层次输入源但没有本地或层次驱动的分支。
- `FUN_1805fbf60` 递归收集类型 `0x13` 的已解析标识符。名称属于候选集合、未出现在驱动集合且未报告过时，才在该标识符的源代码行发出诊断。
- 主函数把赋值右值、条件和其他表达式节点送入读取辅助函数；同一名称只报告一次。
- 因此本条的有界核心谓词是“内部信号被读取，但没有识别到赋值或层次驱动”，并不是“所有尚未赋值的声明”。未读取声明属于其他冗余规则。

## 产品接入

- `RTL-UNDRIVEN-SIGNAL` 继续只覆盖内部信号、存在读取且无本地驱动的情况。
- 诊断位置由声明行修正为第一次实际读取行，与原生辅助函数使用标识符节点位置一致。
- 同一信号多次读取仍只报告一次；赋值后再读取保持无告警。
- 对本 architecture 中声明的 component，以及工程内唯一解析的 entity，直接标识符实参现在按形式端口方向处理：连接 `IN` 视为层次读取，连接 `OUT/INOUT` 视为层次驱动。
- 父 architecture 与 entity 可以跨文件；具名和位置关联均覆盖。重名 entity、未声明的隐式 component、表达式、选择名与 `open` 不猜测，继续保持 `ManualReviewRequired`。
