## 恢复的核心判断

slot 0 通过 `FUN_1804c5890` 收集 VHDL 进程，由 `FUN_1804d56f0` 构造分类时钟关系。它随后遍历 `AST_CASE(0x57)` 及其 `AST_COND(0x58)` 子节点；`FUN_180698e40` 将条件候选关联到源位置，最终把候选控制名与时钟关系名集合求交集。交集非空时在候选位置报告。内部还涉及赋值节点和层次关系，其全部传播语义尚未恢复。

对 `FUN_1804c5890 @ 0x1804c5890` 的完整定点反编译进一步证明，它是非递归两级收集器：只遍历输入根的直接 `AST_ARCHITECTURE(0x75)` 子节点，再遍历各 architecture 的直接 `AST_ALWAYS/process(0x52)` 子节点并按顺序追加。它不会进入 generate、block、子程序或其他并发节点。因此本规则的时钟关系来源以及随后基于该进程向量收集的 IF/CASE 候选都必须限定为 architecture 直接 process；嵌套 process 不得向外扩散时钟名，也不得自身产生控制端告警。持久化证据为 `docs/evidence/native_vhdl_direct_process_collector_4c5890.txt`，SHA-256 `fdfe77d6d9ec134b166d321c11ef651b5b7fbc15bba2280f725f8afe72d05f91`。

定点恢复进一步证明：`FUN_180698e40` 对直属 `AST_COND` 调用 `FUN_1804c48c0`，并只排除分类值 2 的记录；候选记录由条件 AST 和小写控制名组成。`FUN_1804c48c0` 接受单独 `AST_IDENTIFIER(0x13)`、单操作数 `AST_BIT_NOT(0x24)`、四种 AND/OR 节点 `0x25/0x26/0x45/0x46`，以及二元 `AST_EQ(0x36)`。EQ 只把精确字符字面量 `'0'`、`'1'` 分别归类为 0、1。

AND/OR 首先调用 `FUN_1804d4cc0`。该辅助函数只识别同名标识符的 `event` 属性和电平等式组合；识别成功时返回名称及 0/1 极性，调用方不再递归收集，从而把 `clk'event and clk='1'` 这类边沿表达式排除在“时钟作为控制信号”候选外。识别失败才递归收集 AND/OR 两侧的普通候选。函数调用、其他关系运算和任意算术没有通用递归入口。

主函数 `FUN_180699180` 对 `FUN_1804d56f0` 返回的关系树执行两个精确区间遍历：键 `[1,2)` 与 `[2,3)`，因此只消费类别 1 和类别 2；类别 3、4 没有进入时钟名称集合。共享生产器的优先级是：`FUN_1804d71d0` 成功写类别 3；否则 `FUN_1804d24a0` 返回 1/4 时分别写类别 1/4；再否则 `FUN_1804d68a0` 成功写类别 2。

已有完整分类器证据把这些类别约束为源码形状：类别 3 没有识别到边沿；类别 2 的主 IF 条件本身是边沿；类别 1/4 都是外层非边沿控制后在 ELSIF/ELSE 找到边沿，区别是类别 1 同时具有 `FUN_1804d20e0` 证明的常量动作，类别 4 没有。故类别 4 虽包含边沿，也不能为本规则建立时钟名称。主函数还记录类别 1/2 关系对应源码行，并在随后遍历 lowered CASE/COND 时排除这些时序条件自身，再对其余候选执行名称交集。

`FUN_1804d20e0` 的已恢复直接分支同样属于这条共享关系生产路径。它递归进入 `AST_BLOCK(0x54)`，只检查恰有两个子节点的 `AST_ASSIGN_LE(0x56)` / `AST_VARASGN(0xa2)`；RHS 为直接 `AST_CONSTANT(0x10)`、首个直接子节点为 `AST_OTHERS(0x89)` 的 `AST_CONCAT(0x22)`、全部直接子节点均为常量的 `AST_CONCAT`，或一个已绑定且存在于每设计根命名值树中的 `AST_IDENTIFIER(0x13)` 时，动作可证明为静态。`FUN_1804cbad0` 只从所属实体泛型、当前 architecture 的直接常量和直接类型枚举文字建立该大小写不敏感集合；普通信号、process 局部常量、局部 package 常量和其他 architecture 声明不属于该集合。因此这些来源能把后续 ELSIF/ELSE 边沿归入本规则消费的类别 1，而未证明的动态或局部名称仍保留为被排除的类别 4。

共享关系构建器调用的 `FUN_1804c4430` 并不要求整个条件根就是边沿。其过滤表依次为 `AST_POSEDGE(0x65)`、`AST_NEGEDGE(0x66)`、`AST_LOGIC_AND(0x45)`、`AST_BIT_AND(0x25)`；`FUN_1804f3870` 先收集当前匹配节点，再按子节点顺序递归，入口随后采用第一个成功候选。因此类别 1/2 关系使用 AST 先序中的第一条可识别边沿：合法边沿可位于复合条件后代，旧式 `event` AND 的事件属性和电平等式可左右交换；若前后存在多个候选，只由先序第一个成功候选建立该关系的时钟名称。持久化字节、枚举映射和遍历证据见 `docs/evidence/native_vhdl_edge_condition_preorder.txt`。

主函数对类别 1/2 的每个关系对象调用 `FUN_1804bb030` 取得其内部关系记录，把非空记录源 AST 的 `+0x214` 行号加入整数向量；同时把关系对象自身来源 AST 的 `+0x214` 行号加入同一向量。后续遍历带源码 IF 链接的 CASE 时，先把链接 IF 的 `+0x214` 与该向量逐项比较，命中则不调用候选收集器。这是明确的按源码行排除，不只是边沿表达式语法过滤。

V1.4.142 对 `FUN_180699180` 的完整定点导出再次确认两个类别区间的消费细节：主函数对类别 1 和类别 2 的每个关系对象分别调用 `FUN_1804bb030` 收集内部记录行号，但只把关系对象自身 `+0x48` 处的单一规范化名称（反编译表达为 `puVar23 + 9`）送入 `FUN_1804d77f0` 建立时钟名集合。因此类别 1 的第一个边沿是该对象的主时钟名；后续边沿记录参与源码行排除与类别状态，却不会被本规则当作第二个时钟名。完整导出为 `docs/evidence/native_vhdl_clock_mux_control_4_9_b_main.txt`，SHA-256 `bc0fe99c941b098695fbbecafde00bf62c3b2eb93a6323f973efd833c6296a23`。

共享来源 IF 收集器 `FUN_1804c5070` 只从进程语句块固定深度取得直接 source-linked IF，因此普通语句之前或之后的每个独立顶层 IF 都分别建立关系，而分支、CASE、LOOP 内的 IF 不会成为独立关系根。`FUN_1804d24a0` 对类别 1/4 按源码顺序处理全部直接 ELSIF：第一个边沿成为主关系名，后续边沿写入内部记录；非边沿静态分支可在首边沿之前或前两个边沿之间建立静态动作标志，但第二个边沿已经追加后，后续静态分支不再把类别 4 提升为类别 1。ELSE 路径扫描直接链接 IF 时不断覆盖指针，最终只采用最后一个直接链接 IF 的主条件，不使用该 IF 的 ELSIF，也不进入 CASE/LOOP 中更深的 IF。

`FUN_1804c48c0` 的输出是按小写名称索引的树容器；`FUN_180698e40` 遍历容器条目生成候选。因此同一个 COND 中 `clk and clk` 的两次引用只形成一个名称条目，原生诊断重数是“每条件、每不同名称”，不是每词法出现一次。

`FUN_1804c0de0` 把候选 AST 指针和规范化名称构造成一个 `0x28` 字节记录，`FUN_18069a710` 随后把每个记录追加到向量并将末端推进 `0x28`。该追加函数不比较名称、AST 指针或源码行；其“源指针位于当前向量内”分支仅用于扩容时的源别名保护。因此去重边界严格停留在上述单个条件的名称树内：不同 IF/CASE 条件中的同名时钟仍分别报告，`AST_WHEN` 中不同直接 `AST_COND` 子节点的同名时钟也分别保留。持久化反编译证据见 `docs/evidence/native_vhdl_clock_mux_control_4_9_b_candidate_append.txt`。
