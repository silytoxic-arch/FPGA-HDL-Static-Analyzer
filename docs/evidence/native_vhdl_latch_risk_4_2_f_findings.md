# GJB9765.4.2.f 原生 VHDL 锁存器风险判据

## 目标与二进制身份

- 附件：T-Linter V3.1.4.25120520251205115359 `T-Linter.dll`
- SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 构造函数：`FUN_180026c90`
- vtable：`0x180ee0af8`、`0x180efdb10`
- slot 0：`FUN_18077ad60`
- 遍历器：`FUN_18077c840`
- IF 检查器：`FUN_18077b8e0`
- CASE 检查器：`FUN_18077b0c0`
- 条件赋值检查器：`FUN_18077c530`

## Recovered predicate

构造函数把 `+0x158..+0x15e` 七个选项字节全部写为 1。共用执行槽逐设计根调用遍历器；过程分类中出现边沿/事件关系时不进入锁存器分支，无这些关系的组合过程才递归检查。

- `+0x158`：IF/ELSIF 链缺少最终 ELSE 时报告。
- `+0x159`：先收集一个 IF/ELSIF/ELSE 链全部分支出现的赋值名称，再对每个已有分支报告其缺少的名称。
- `+0x15a`：CASE 普通分支缺少构造内已出现的赋值名称时报告。
- `+0x15b`：CASE 的 OTHERS 分支缺少构造内已出现的赋值名称时报告。
- `+0x15c`：CASE 缺少 OTHERS 分支时报告。
- `+0x15d`：条件赋值缺少 ELSE，或简单三子项形式的 ELSE 标识符与赋值目标归一化后相同时报告。
- `+0x15e`：构造函数明确启用，但在本轮已恢复的执行分支中尚未找到独立读取点，保持未知。

二进制中的 GB18030 文本分别说明 IF 当前/ELSIF/ELSE 分支缺少赋值、IF 缺 ELSE、CASE 当前/OTHERS 分支缺少赋值、CASE 缺 OTHERS、条件赋值缺 ELSE及 ELSE 保持原值会产生锁存器。

## 产品接入

移除 `RTL-LATCH-INFERRED` 到本条款的宽泛翻译，改为 VHDL 专用结构检查：

- 仅检查无 `rising_edge`、`falling_edge`、`'event` 的过程；
- 对结构配对成功的 IF 与 CASE 按分支赋值名称集合报告；
- 即使分支内完全没有赋值，IF 缺 ELSE或 CASE 缺 OTHERS仍能报告；
- 识别简单条件信号赋值缺 ELSE和 `else target` 自保持；
- 嵌套结构作为独立构造继续检查。

## 验证与限制

附件正反例继续匹配。新增回归覆盖：附件式 IF/CASE 两条诊断、无赋值结构缺省、IF/CASE 某分支漏赋值、条件赋值缺 ELSE、ELSE 自保持、完整分支，以及时钟过程排除。

原生关系类别名称、`+0x15e` 用途、赋值收集器对别名/聚合/选择名/错误恢复树的完整行为、嵌套记录归属、generate/子程序过程、常量折叠和诊断顺序仍未知。产品只对有界且配对成功的 token 结构作肯定报告，干净结果仍需人工复核，不声明完整厂商前端等价。
