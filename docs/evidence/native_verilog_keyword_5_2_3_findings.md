# R-2-3 关键字命名规则证据

## 目标与边界

- 附件：`T-Linter.dll`，SHA-256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
- 本记录区分 DLL 中直接观察到的判断流程、附件规则文本，以及本产品据此采用的策略；不把未恢复的厂商 GUI 默认值写成事实。

## 原生实现观察

- 规则构造注册点为 `0x180021790`，规则对象虚表为 `0x180eeca70`，槽 0 入口为 `0x180535e60`。
- 本轮完整反编译导出保存于 `reverse-tools/evidence/t_linter_pass61/r2_3_decompile.txt`；候选类型和逐地址字符串保存于同目录 `r2_3_strings.txt`。
- 槽 0 遍历对象 `+0xa8` 的有序模块名称映射；只有恰含一个非空 `AST_MODULE(2)` 的组进入检查。一个重复模块组不会阻止同文件中另一个唯一模块组。
- 候选类型精确为 `AST_MODULE(2)`、`AST_WIRE(6)`、`AST_PARAMETER(9)`、`AST_LOCALPARAM(10)`、`AST_CELL(79)`、`AST_TASK(3)` 和 `AST_FUNCTION(4)`。
- 槽 0 构造并按固定顺序查询六张表：VHDL、Verilog、SystemVerilog、SDF/EDIF、PSL、Windows。对象 `+0x148` 起的类别布尔值决定每张表是否参与；首个“已启用且精确匹配”的类别触发报告，已启用但未匹配的较早类别不会阻止后续类别。
- 名称采用 ASCII 不区分大小写的精确成员匹配，不是子串匹配。六张表及保留的重复/组合字面量已在 `verilog_keyword_names.h` 中固化。
- 六类命中分别拼接固定前缀 `禁止使用VHDL关键字同名的`、`禁止使用Verilog关键字同名的`、`禁止使用SystemVerilog关键字同名的`、`禁止使用SDF/EDIF关键字同名的`、`禁止使用PSL关键字同名的`、`禁止使用Windows关键字同名的` 与原始归一化名称；中间没有分隔符，末尾没有后缀。
- 所有六类均固定为 Error，文件来自唯一模块根，物理行来自候选节点 `+0x210`，原生记录没有列字段。
- `runCheck.exe` 的配置分发函数对本规则只调用通用 `setRule`，没有调用类别专用 setter；DLL 导出表也没有发现关键字类别 setter。因此附件可见调用链不能证明六个布尔值的厂商 GUI 默认组合。

## 附件规则文本

附件 `examples_html/GJB10157_VLOG.5.2.3.html` 明确写明：“禁止使用VHDL、Verilog、SystemVerilog、SDF和EDIF关键字”。这与原生六类表的前四类一一对应，未提及 PSL 或 Windows 保留名称。

## 产品策略

- 未提供工程配置时，按规则文本启用前四类：VHDL、Verilog、SystemVerilog、SDF/EDIF；PSL 与 Windows 关闭。
- 工程显式策略优先，包括显式全部关闭。这样既能复现规则文本规定的错误，又不把未证明的 PSL/Windows 扩展当作标准要求。
- 只有语法可接受、模块根唯一且属于已恢复声明形态的源码才进入该判断。命中可确定为违规；未命中仍为“需人工复核”，不声明整条规则合规。
- V1.4.197 按模块名称组独立准入，输出六类精确正文、固定 Error、声明物理行和第 1 列；公开界面与报告仅显示官方编号 `R-2-3`。

## V1.4.12 条件编译边界

- 原生判断消费前端已解析的 AST 声明，因此产品在工程 `defines` 配置可成功预处理时，对预处理后的活动 token 流运行有界源码适配器。
- 活动分支中的保留名称会报告，非活动分支不报告；诊断行列映射回原始源文件。
