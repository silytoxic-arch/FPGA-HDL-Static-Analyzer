3. 递归收集器 `FUN_1805853a0` 只收集首个直接子节点为 `AST_IDENTIFIER(0x13)` 的 `AST_CASE(0x57)`，并排除与模块根同一源码行的 CASE。
4. 消费函数只处理直接 `AST_COND/CONDX/CONDZ(0x58..0x5a)` 中首子节点为 `AST_DEFAULT(0x5b)`、且至少还有一个语句子节点的分支。
5. 只从 default 分支第二个子节点递归收集 `AST_ASSIGN_EQ/AST_ASSIGN_LE(0x55/0x56)`；控制条件、任务实参和其他 case item 不会借用 X。
6. 每个赋值必须恰有两个直接子节点；其首子节点通用字符串字段含 `$` 时跳过。
7. `FUN_180585480` 扫描整个赋值子树中的 `AST_CONSTANT`，只收集编码字节 `0x02`（X），排除与模块根同一源码行的常量。Z 不触发本规则。
8. 一个赋值中存在一个或多个 X 都只输出一条；多个违规赋值分别输出，位置均归属对应 default 分支。
9. 固定消息为“避免在default分支中出现包含'x'的值.”，DLL 内部严重度为 Warning。

## 产品接入边界

- 源码适配器要求完整的 `case/casex/casez`，并限定到模块内、可证明为标识符根的控制表达式。
- 只接受直接 default item，递归扫描其语句中的阻塞/非阻塞赋值；按赋值节点保留诊断重数。
- X 可位于 RHS 或带选择的 LHS，因为原生 helper 扫描完整赋值子树；Z 不报告。
- 简单标识符根左值名称含 `$` 时跳过；拼接左值的根是拼接节点，不把其后代名称错误提升为根字符串过滤条件。
