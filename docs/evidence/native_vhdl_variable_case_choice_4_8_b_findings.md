# GJB9765.4.8.b VHDL CASE 变量选择项规则恢复记录

## 目标与二进制身份

- 目标规则：`GJB9765.4.8.b`
- 附件版本：T-Linter V3.1.4.25120520251205115359
- `T-Linter.dll` SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 构造函数：`FUN_180029680`（`0x180029680`）
- slot 0：`FUN_18065f460`（`0x18065f460`）
- 选择表达式检查器：`FUN_1806603d0`（`0x1806603d0`）
- 枚举名称收集器：`FUN_180660180`（`0x180660180`）
- 本记录来自 Ghidra 12.1.4 对用户附件的离线静态反编译，不代表观察了原软件运行。

## Recovered predicate

- `FUN_18065f460` 对每个设计根清空一组允许作为选择项的静态名称，并从若干声明节点补充名称。
- `FUN_180660180` 搜索类型 `0x76`，再沿直接子节点 `0xa3` 收集所有 `0x13` 标识符。后续相邻规则恢复已把这一形状交叉确认成 entity、generic、identifier，因此该路径明确贡献 entity generic，而不是此前推测的枚举字面量。
- 主函数还从 `0x77` 声明路径及带 `+0x178` 标志的常量 `0x0a` 节点补充允许名称。枚举字面量的来源归入仍未完全命名的 `0x77` 声明派生路径，不再错误归因到 entity/generic 路径。
- 普通顺序 CASE 路径收集类型 `0x57`，遍历其直接 `0x58` 选择组，并把每组第一个 choice 表达式传给 `FUN_1806603d0`。
- `with ... select` 使用独立根类型 `0xb7`；其 `0xb6` 子节点中从索引一开始每隔两个子节点取一个选择表达式，同样传给 `FUN_1806603d0`。
- `FUN_1806603d0` 递归收集一个选择表达式下的所有 `0x13` 标识符；依次查询允许集合，遇到第一个不在集合内的名称即报告并结束该选择项，因此每个选择表达式最多报告一次。
- `0x180f09fb8` 的 GB18030 文本为“选择参数不能使用变量”。附件分别以普通 CASE 的 `when TMP` 和 `with A select ... when TMP` 验证两条入口。

## 产品接入

- 同时检查顺序 CASE 的 `when ... =>` 和 `with ... select` 的 `when` 选择项。
- 将已声明的端口、信号和变量视为可肯定证明的运行时名称；它们出现在选择项表达式中时报告。
- 常量、泛型、枚举字面量以及纯文字选择项允许通过。
- 每个选择表达式最多报告一次，并定位到首个已解析的运行时名称。
- CASE generate 不属于恢复的 `0x57/0xb7` 两条路径，明确排除。
- 静态与运行时名称按 architecture 所属 entity 分开建立，保持原生“每个设计根清空并重建”边界。

## 已知边界

- `0x77` 的完整声明派生结构、subtype/package 可见性、alias、纯函数、属性、限定表达式、物理单位和 configuration 绑定尚未完全恢复。
- 产品不因一个无法解析的名称就直接报警；未知名称保持人工复核，避免把缺少工程上下文的符号伪判为违规或合规。
- 严重语法错误、前端错误恢复节点、生成后节点和原生遍历顺序仍未完整等价。

## 回归覆盖

`tests/standard_accuracy_tests.cpp` 覆盖附件同形的普通 CASE 与 WITH SELECT 变量选择、常量/泛型/枚举字面量遵循例、一个表达式含多个运行时名称时只报一次，以及 CASE generate 排除边界。

V1.4.58 新增跨设计根同名边界：entity A 的 generic `CHOICE` 不得把 entity B 的同名运行时
端口 choice 误当静态名称。旧实现按整文件合并集合导致漏报；改为按命名 architecture/entity
重建集合后报告恢复，既有同根常量、generic 与枚举字面量正例继续通过。

V1.4.59 补齐 architecture 的合法结束形式。原生以 AST 设计根为边界，与源码采用完整
`end architecture`、命名 `end rtl;` 或裸 `end;` 无关。产品旧范围扫描只识别完整形式，会把
后续 architecture 吞入前一范围并漏检。新增命名结束和裸结束两个跨根回归，均在修复前失败、
修复后报告一条 4.8.b；裸结束仅在下一个设计单元或文件末尾确定为 architecture 终点，避免
把内部结构的裸 `end;` 直接误作根结束。
