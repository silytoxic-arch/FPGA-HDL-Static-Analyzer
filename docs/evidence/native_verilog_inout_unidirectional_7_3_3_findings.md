# GJB10157.7.3.3 双向端口连接单向端口原生判据

## Recovered predicate

目标为用户附件中的 `T-Linter.dll`，SHA-256 为
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

- 构造函数为 `0x180022ea0`；slot 0 为 `FUN_1806c9ed0`，静态反编译证据为
  `ev_9d37e17a014972cb692902d2d3196184236e04217b9f86a7ec11fe29ebe95fe0`；
- 模块过滤器为 `FUN_1807238a0`，接纳 `AST_MODULE(2)`，证据为
  `ev_aaa493aac258e6c8e9f4d04fcd2ebeb575f37e5d55e363a21c32a358a3f3965b`；
- 主函数遍历实例关联记录，分别处理具名关联和按序关联；
- 对已解析的实际声明检查两个相邻方向字节 `+0xa0`、`+0xa1`。两者均非零后，再检查
  形式端口声明的相同字节；形式端口任一字节为零即报告；
- 附件把两个方向字节同时置位的实际对象描述为父模块 `inout` 端口，把形式端口任一方向
  缺失的对象描述为子模块 `input` 或 `output`；子模块形式端口同为 `inout` 时不违规；
- 诊断使用实例、形式端口和实际端口名称构造消息，并定位到关联记录。

上述结论来自离线静态反编译及附件正反例对照，不是运行时跟踪。方向字段的调试类型名没有
恢复，`input/output/inout` 语义是由分支形状和附件共同确定的高置信度解释。

## Product integration boundary

产品在工程结构解析完成后执行以下有界检查：

- 父、子设计单元都必须是 Verilog/SystemVerilog module；
- 子模块名称必须在当前工程中唯一解析，外部黑盒、缺失库单元或重名目标不猜测方向；
- 实际信号必须能归一化到父模块声明的 `inout` 端口；
- 形式端口方向必须明确为 `input` 或 `output`；
- 支持具名、SystemVerilog 同名简写、按序连接，以及以端口标识符为根的位选/范围选择；
- 表达式、拼接和无法绑定声明的实际值不报告。

附件 HTML 只包含父模块，未包含 `my_module1`/`my_module2` 的定义，因此单独扫描附件示例时
不能证明形式端口方向。该场景保持 `ProjectContextRequired`，不会为了匹配示例而伪造端口
模型。原生库解析、interface/modport、primitive、别名、generate 层次及精确诊断次数仍未
恢复；不声明完整厂商算法等价。

V1.4.7 的附件审计器同步修正了这一证据边界：违反例和遵循例均因缺少被例化子模块定义而
记为 `context-required`，不再把前者记为检测失配、也不把后者记为已验证匹配。该变化只纠正
审计结论，不放宽产品检测器的唯一解析要求。

V1.4.258 将本项检查迁移到匹配的展开工程根、token 和虚拟设计单元，报告时才映射来源；重新导入二进制复核了入口及绑定判据。见 [第一百四十轮记录](../native_rule_recovery_pass140.md)。完整参数/库/生成及厂商运行等价仍未证明。
