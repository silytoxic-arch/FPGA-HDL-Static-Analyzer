- 附件示例页 SHA-256：`c2686ec34a52cd507b279890d50ae7d3e6e370a5e666ef32dc32afe0defdcc3a`
- 构造函数：`FUN_180029360`（`0x180029360`）
- slot 0：`FUN_1807849b0`（`0x1807849b0`）
- 声明/名称图构建器：`FUN_180785f30`（`0x180785f30`）
- IF 条件收集器：`FUN_1807859e0`（`0x1807859e0`）

## Recovered predicate

- 共享初始化器先在 `+0x178` 写入双字节值 1；`FUN_180029360` 随后在同一位置写入 `0x0100`，并在 `+0x17a` 写入 1。按小端序，三个选项字节最终为 `0,1,1`。
- `FUN_1807849b0` 因而关闭 `4.7.c` 使用的第一分支，启用 `FUN_1807859e0` 和 `FUN_180785240`；每个设计根仍先由 `FUN_180785f30` 建立解析后的常量名称映射。
- `FUN_1807859e0` 只处理类型 `0x5d` 的控制根及其直接类型 `0x58`、单条件子节点。直接类型 `0x10` 字面量或能在常量映射中解析的类型 `0x13` 名称进入违规集合。
- 其他表达式交给 `FUN_180785890`；只有 `0x34`、`0x35`、`0x36`、`0x37`、`0x3a`、`0x3b` 六类直接关系表达式被接受，且左右直接操作数必须各自为字面量或已解析常量名。该分支只判断静态形状，不计算真假。
- 附件三个 IF/ELSIF 常量条件和三个 CASE 常量选择器均标注为违规；运行时端口选择器和包含 `conv_integer(B)` 的动态比较均为合规。这是 CASE 产品适配的直接示例证据；CASE 进入共享违规集合的完整原生辅助路径仍未完全命名。
- `FUN_180785240` 只处理满足类型 `0x5c` 或 `0x60` 的两个循环根；在其类型 `0x0e`、恰有两个子节点的范围中，逐个检查直接类型 `0x13` 边界名称。名称不在常量映射时立即报告；字面量和复合边界不是该直接名称分支的候选。
- DLL `0x180f1e2b8` 起的 GB18030 文本依次为“禁止非常量的循环条件”和“禁止常量条件表达式”。

## 产品接入

- 对 VHDL `IF`、`ELSIF` 和顺序 `CASE` 的控制表达式应用与附件一致的直接静态原子/六类关系判据。
- 对顺序 `FOR ... LOOP` 和 `FOR ... GENERATE` 的上下界分别检查；只有直接运行时标识符边界报告，字面量、初始化常量和匹配 entity generic 接受。
- 常量按 architecture 隔离，generic 按 `ARCHITECTURE ... OF entity` 绑定；deferred constant 不猜测为已解析常量。
- `WHILE` 常量条件仍由 `GJB9765.4.7.c` 独立报告，不交叉计入本规则。

## 已知边界

- 专有 AST 类型的正式枚举名、CASE 选择器进入共享违规集合的完整帮助函数路径、`+0x168` 映射的全部声明类别、包可见性、进程/子程序遮蔽、别名、复合循环边界、属性、重载和错误恢复节点仍未完全恢复。
- 产品只对证据覆盖的直接静态控制形状和直接名称循环边界作肯定判断；其余干净结果保持人工复核，不据此宣称合规。
- 不宣称与专有 VHDL 前端的完整名称解析、生成后 AST 或诊断顺序完全等价。
