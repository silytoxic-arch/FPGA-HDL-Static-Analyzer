## 观察到的原生逻辑

- `FUN_1805cd990`（`0x1805cd990`）递归遍历当前节点的全部子树；当节点类型为 `0x92`、存在子节点且名称转小写后恰为 `file_open` 时，只收集该调用节点的直接子节点中类型为 `0xb2`、字符串载荷非空的节点。递归在收集后继续，因此嵌套调用由其自身节点独立判断。证据 `ev_647f0cf8f8988d7a1509761e855ab44dc954cdf83ab996266e37f9484aa7916b`。
- `FUN_1805cd0f0`（`0x1805cd0f0`）逐个处理收集到的字符串节点，对字符串搜索相邻字节 `:/` 或 `:\`，每个命中的字面量形成一条 Warning。常量区 `0x180efcc84` 为 `3a 2f`，`0x180efcc88` 为 `3a 5c`；紧随其后的 GB18030 文本为“文件的引用要使用相对路径而不是绝对路径”。证据 `ev_dc2d8ad1268eba2174e70d1886a991d63c82f4428732222e895fd8be082b0534`。
- 从规则入口、递归收集器到报告分支均未读取目标文件、判断路径存在性或查询工程层次关系。该规则的确定违规判据不依赖工程上下文。
- 并未观察到仅以 `/` 开头、仅含冒号但后续不是斜杠，或普通相对路径的报告分支；协议样式 `https://...` 因包含 `:/` 也会命中原生字节判据。
- 附件示例的 `FILE_OPEN(F2, "G:/test.dat")` 为违反例，`FILE_OPEN(F2, "../test.dat")` 为遵循例。两例与上述判据一致，但示例本身不能证明完整 AST 前端行为。

## 产品接入与边界

产品在 VHDL 词法流中识别 `FILE_OPEN(...)`，只检查括号内直接字符串参数；注释、无关字符串、外层调用的嵌套字符串不触发。`:/`、`:\` 按字面量逐条报告；单独 `/tmp/...`、`logical:name` 和普通相对路径不按该原生谓词报告。边界回归覆盖大小写、Windows/盘符、协议前缀、Unix 根路径、冒号非斜杠、注释、无关字符串和嵌套参数。
