# GJB10157.5.2.15 配置链补证

目标文件：附件 `T-Linter.dll`，SHA-256
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
本记录来自离线静态分析，不执行厂商程序，也不把文档示例当作二进制算法证据。

## 已观察事实

- 规则构造函数 `FUN_1800214a0` 创建 `GJB10157_VLOG.5.2.15` 对象后，向专用字段块写入
  `+0x158=0`、`+0x159=1`、`+0x15a=1`（小端写入 `_DAT_18134a558=0x100`，随后
  `DAT_18134a55a=1`）。
- 已恢复运行函数 `FUN_1805306e0` 按单字节读取这三个字段：
  `+0x159` 控制 parameter/localparam 的 ASCII 小写拒绝，`+0x15a` 控制 AST_WIRE 名称检查，
  `+0x158=0` 选择“允许仅首字母大写”的分支。
- 对专用全局地址 `0x18134a558` 的 Ghidra 引用枚举只得到构造函数写入
  `0x18002151b`，未观察到第二个直接写入点。
- 导出函数 `CheckRule::setRuleNameCase`（`0x180629120`）查找由规则名索引的通用规则对象，
  写入的是对象 `+0x144..+0x147` 四个布尔字段，不是 5.2.15 的专用 `+0x158..+0x15a`。
- `runCheck.exe` 对 `VLR-040005` 至 `VLR-040008` 等通用命名规则调用上述导出函数；该路径不能证明
  5.2.15 的三个专用标志会被覆盖。
- 附件全部 `.lprp` 中 `GJB10157_VLOG_5_2_15_NUM` 只有 `Enabled` 和 `Severity`，没有命名大小写参数。

## 冲突判定

随包 HTML 的错误例 `parameter data` 与 DLL 默认谓词一致；正确例 `parameter Data` 含 ASCII 小写，
按固定的 `+0x159=1` 分支仍会被报告。因此该页面的 `follow` 标签与二进制默认逻辑直接冲突，
不能再用“可能存在 `.lprp` 配置覆盖”解释。

产品保留二进制证据支持的确定违规检测器，并在附件样例审计中保留这个不吻合项，不篡改附件预期。
`Automated` 只表示存在可执行的确定违规检测器；未报警仍为 `ManualReviewRequired`。完整 AST_WIRE
来源映射、宏、内存数组和不透明类型仍不宣称等价。

## V1.4.10 条件编译边界

`FUN_1805306e0` 接收的是前端已经建立的 AST declaration 节点，而不是互斥条件分支仍同时存在的
原始文本。V1.4.10 因此把产品判定移动到工程配置预处理成功后的活动 token 流：

- 工程 `defines` 选中的 parameter、localparam 和 wire 类声明执行已恢复的大小写判据；
- 非活动分支中的违规名称不报告；
- 诊断保留声明在原文件中的物理行列；
- 预处理失败时不猜测活动声明，仍保留人工复核边界。

这是产品侧对原生 AST 输入边界的有界适配。厂商宏展开、include 内容注入、生成 AST、内存数组、
不透明类型和所有 AST_WIRE 来源仍未恢复；不据此宣称完整前端等价。

## V1.4.86 诊断、定位与数量补证

新增离线证据：

- `a2_5_naming_case_entry.txt`，SHA-256 `13a1afd1f7ffad5be0c2a08657d7e67a149cc0ddef9b861841aa76deafb598f4`；
- `a2_5_naming_case_strings.txt`，SHA-256 `d82ef023972b6158488bcf768dc27f98ba8641ba97e63b27220068c9e23f06f2`；
- `a2_5_naming_case_message_helper.txt`，SHA-256 `eb01263358076bdb17416583d939fc53efb9708e4755f603ea0cf1bc96a1bcb1`。

直接观察到：

- 参数/localparam 分支在发现第一个 ASCII 小写字母后，为该声明输出一次；默认 wire 分支在首字节不是 ASCII 字母或首字节之后出现 ASCII 大写字母时输出一次。
- 五处输出路径都把严重级别构造成 `error`，使用所属 `AST_MODULE` 的源路径和声明节点 `+0x210` 的物理行，未构造列字段。
- `FUN_18003e420` 先复制规范化名称，再追加固定字节串。默认配置实际使用的完整消息为：
  - `<名称>:建议常量的命名中字母全部采用大写`；
  - `<名称>:建议变量的命名中字母全部采用小写或者仅首字母大写`。
- `+0x158 != 0` 的备用 wire 分支后缀为 `:建议变量的命名中字母全部采用小写`，但附件构造函数固定 `+0x158=0`，产品不虚构该配置入口。

产品现在同步固定 Error、原生消息和第 1 列的行级位置，并保留同一行多个声明节点的诊断数量。厂商标识符规范化、完整前端 AST 来源和生成结构仍未知；无告警仍需人工复核。
