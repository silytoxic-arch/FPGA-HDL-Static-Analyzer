## 原生静态观察

`FUN_1805c9410` 使用 `fgets(..., 0xff, ...)` 扫描源文件，遇到 `--` 停止检查本行余下内容。其两个判定分支分别匹配相邻字节 `<=` 和 `:=`；运算符前后只接受 ASCII 空格或 Tab，缺任意一侧即输出 Warning。证据 `ev_2b0d5e0146b2eec171471cfa7f8b03c888c826162d2b552cd597ee4fe2ab7016`。这是反编译伪代码观察，不是原厂源码，也未观察实际运行。

辅助函数 `FUN_1805c8fc0` 收集 AST 类型 `0x56`/`0xa2` 的源码行号（证据 `ev_a6ad172e51fa76ab9c38d541c28cd4625d828a98c026fa3688a8fff928516997`）；已观察到的运行函数随后排序该集合，但扫描源码行时未见使用该集合过滤。此处不推断它在其他路径上的作用。

## 产品接入

V1.4.24 不再按完整物理行扫描，而是复现 `fgets(0xff)` 的读取块：

- Windows 文本模式下每块最多 254 个数据字节，并按块递增诊断序号；
- 在每块首个字面 `--` 处停止候选扫描，即使它位于字符串中；
- 在截断前逐个识别 `<=`、`:=`；
- 候选仍读取注释起点字节作为右邻接；
- 跨块的运算符不拼接，恰好结束在块边界且没有右邻字节的运算符不报告；
- 只有运算符紧邻两侧都是 ASCII 空格或 Tab 才不报告；
- 字符串中的运算符也参与检查；
- 每个不合规运算符输出一条 Warning，并定位到运算符首字符。

附件违反例中的 `C1 <=B1` 与 `C1<= INPUT1` 检出，遵循例中的 `C1 <= B1`、`C1 <= INPUT1` 不检出。回归测试还覆盖两侧均缺分隔、Tab、注释、普通字符串、字符串中的 `--`、form-feed、254 字节边界和运算符紧邻注释。

## 尚未恢复的边界

产品按目标 Windows PE 与 `fopen("r")` 推断模拟常规 CRLF→LF 转换。反编译中左边界的第二字节地址保护、NUL、Ctrl-Z、代码页、流错误、多个 AST 源记录指向同一文件时的重复扫描、文件变化及完整诊断排序仍未通过运行态证据验证。无告警继续保持 `ManualReviewRequired`，不宣称完整算法等价。
