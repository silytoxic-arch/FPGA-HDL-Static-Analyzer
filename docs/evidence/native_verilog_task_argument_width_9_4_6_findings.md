## 已观察事实

1. 筛选器只接纳 `AST_ASSIGN_EQ(0x55)`，节点名称必须精确等于 `$para_assign`，至少有两个子节点，且前两个子节点之一的内部名称包含 `$task$`。
2. 执行函数分别对第一个和第二个子节点调用 `0x1808f4650`，将结果初始化为 `-1`；只在两个整数宽度不等时进入报告路径。
3. 当第一个子节点含 `$task$` 时，报告后缀为 `，任务输入：` 加该内部名称最后一个点号后的文本；当第二个子节点含 `$task$` 时，后缀为 `，任务输出：` 加同样截取的文本。
4. 原生 GB18030 文本位于 `0x180ef6788`：`task语句，输入信号的位宽%d与输出信号的位宽%d不一致%s`。两个整数按赋值第一个、第二个子节点顺序传入，最后一个字符串为上述方向后缀。
5. 文件和行号取自 `$para_assign` 绑定节点的 `+0x1e0` / `+0x210`；严重级固定为 `Warning`。执行函数对每个不等宽绑定逐节点报告。
6. 位宽递归器覆盖已解析声明、常量、位/片选、拼接、重复、比较/逻辑、算术、条件表达式及部分函数/系统调用；未知或过大宽度由前端错误路径处理。

## 前端生产路径新增观察

1. `$para_assign` 在完整 DLL 中有四个直接引用；其中 `FUN_180914500` 是实际前端生产者，另外两个大函数和规则筛选器是消费者。
2. `0x180923da1` 所在路径为 task 调用选择 `$task$` 前缀；同一路径为 function 调用选择 `$func$`，随后把调用名、源码域、行号和唯一序号拼入内部名称。
3. 生产者只为带输入或输出方向标志的 task 形参进入绑定路径，并为每个位置实参克隆/解析对应 AST，而不是只处理标识符或数值片选。
4. `0x1809250cb` 检查形参方向字节。结合附件已知输入/输出示例，该字节为输入路径时，`0x1809250ef..0x1809250ff` 以“形参、实参”顺序构造 `AST_ASSIGN_EQ(0x55)`；否则 `0x18092511c..0x180925136` 反向构造“实参、形参”。方向字节的语义名称属于由二进制分支与附件行为共同支持的推断，child 寄存器顺序本身是指令级观察。
5. `0x18092514b` 把新节点名称设置为 `$para_assign`，并从当前实参 AST 复制 `+0x200..+0x210` 源码位置元数据；随后给第一个 child 的 `+0xab` 置 1，再按方向放入两个绑定列表之一。
6. 因此 legacy/ANSI 声明差异在本规则运行前已被前端归一化；规则核心消费的是统一 task 形参 wire 与任意已解析实参表达式的绑定。

## 产品接入

- 源码适配器限定为同一 module 内可静态证明的 ANSI 或 legacy task 位置绑定。
- 本轮结果记录绑定位置、赋值左右宽度、task 方向及形参名，输出原生宽度顺序和方向后缀。
- 固定十进制 ANSI/legacy module 端口及 module-scope wire/reg/logic 可为裸实参提供宽度；数值位选择按 1 位处理，数值片选按端点差加 1 处理。
