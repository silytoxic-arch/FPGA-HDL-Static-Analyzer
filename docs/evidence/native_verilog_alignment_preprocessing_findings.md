# GJB10157 Verilog 对齐与同一行赋值规则的条件编译边界

## 范围

本记录覆盖 `GJB10157.5.1.2`、`.5.1.3` 和 `.5.1.6`。附件 `T-Linter.dll`
SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 二进制直接观察

- `.5.1.2` 的入口只接纳 AST_CASE；if/else 路径跟随 AST_REDUCE_BOOL、DEFAULT、BLOCK
  和嵌套 CASE，普通 case 路径读取 COND/CONDX/CONDZ 分支位置，再比较前端节点列号。证据
  `ev_e4a68e44f81363c13a1facdbbbc50f1ff77d7b2000c704f1f20e67e851c9cf64`。
- `.5.1.3` 从 AST_MODULE 递归收集 AST_WIRE，按方向字段划分端口与内部声明后读取源位置；
  证据 `ev_5184e185fe9f98ae94b96102f5e80121c0b163833724e2af2ecf4029abd35091`。
- `.5.1.6` 对 AST 候选节点进行类型过滤和同记录分组，明确排除 AST_FOR 及另一未命名类型；
  它不是原始文本的分号计数。证据
  `ev_00b8248f3e7197396d283e7ffad729fbef3d8b0b3fc324ae6e49bd1178f730d0`。

三条原生路径都依赖前端节点及其源位置，因此条件编译选择应发生在规则输入形成之前。

## V1.4.17 产品适配

产品此前直接扫描原始 token，未激活 `ifdef/else` 分支中的错位语句、错位声明或同一行赋值
也可能进入规则。V1.4.17 改为：

- 工程 `defines` 预处理成功后，仅检查活动 token；
- 活动分支三种确定违规各按恢复谓词报告；
- 未激活分支不产生这三条规则的报告；
- 诊断保持原始物理行号；
- 预处理失败时不猜测活动结构。

物理行长度、注释率、文件头等已恢复为原始文本判据的规则继续读取原始文件，本次没有把它们
错误地改成活动 token 语义。

## 仍未知

- 厂商完整宏/include/generate 展开与前端列号正规化；
- `.5.1.6` 未命名 AST 类型 0x60、完整候选分组及诊断重数；
- 隐式网络、用户自定义类型、畸形源码恢复和共享嵌套节点重数。

因此确定匹配可自动报告；无匹配仍为 `ManualReviewRequired`，不声明完整算法等价。
