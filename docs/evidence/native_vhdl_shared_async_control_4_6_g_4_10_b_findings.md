# GJB9765.4.6.g / 4.10.b 原生共享行为恢复

## 目标与身份

- 规则：`GJB9765_VHDL.4.6.g` 与 `GJB9765_VHDL.4.10.b`。
- 二进制：`T-Linter.dll`，SHA256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
- 两条规则的不同构造函数安装不同规则名称，但 vtable slot 0 都指向 `FUN_180650a90`。
- slot 伪代码证据：`ev_db7f61fc4a1fbadb5a400f779d6a4ffba97ebf540868b8b5acb705865a0133cf`。
- 关系辅助函数 `FUN_180652070` 伪代码证据：`ev_90f915f639542a3da6bbf92ee94c91cc0152784e18928c954ed377b4ed14fa80`。

## 恢复的核心判断

共享入口通过 `FUN_180652070` 建立异步控制关系，并对到达同一寄存器的控制源进行比较；源名称相同时进入报告路径。构造函数中的规则名称决定最终诊断文案。

只读字符串确认：

- `GJB9765.4.6.g` 与 `GJB9765.4.10.b` 都使用同一控制关系入口；
- GB18030 文案包含“复位与置位信号不应来自同一个信号”和“的复位端和置位端被相同的信号”。

附件正反例给出可直接恢复的源码谓词：

- 同一进程、同一赋值目标；
- 时钟事件之前存在至少两个显式 `if/elsif` 异步分支；
- 两个分支控制信号名称相同，则两条规则各报告；
- `RST`/`SET` 或两个不同组合信号分别驱动时通过。

产品只实现这个有界形态：每个进程先定位时钟事件，再解析时钟事件之前的顶层 `if/elsif` 链，提取分支控制信号、直接赋值目标和可直接证明的二值动作。同一目标被同一信号控制至少两个异步分支，且直接动作值集合同时包含 `0`、`1` 时才报告。直接标量字符常量和附件使用的 `(others => '0'/'1')` 聚合均纳入；动态数据不猜测为复位或置位。

## 附件验证

- 违反例外部端口 `RST` 同时控制置位和复位：两条规则各命中 1 处。
- 违反例组合信号 `int_async_sig` 同时控制置位和复位：两条规则各命中 1 处。
- 正确例分别使用 `RST`/`SET` 和两个不同组合信号：两条规则均零告警。
- 附加边界：同一控制信号串行控制不同寄存器目标时，不提升为“同一寄存器多个异步端”的告警。
- 附加边界：同一控制信号的两个分支都把同一目标复位为 `0` 时不报告；一个分支为动态数据、另一个为 `1` 时也不推断缺失的复位动作。
- 附加边界：`'1'=RST` / `'0'=RST` 的字面量左置形式仍解析到同一个直接控制源并报告。

## 未决范围

`FUN_180652070` 的完整关系类型、别名传播、复合条件、嵌套 IF/CASE、组件或原语复位端口、生成逻辑、函数返回值、错误恢复、重复设计根和原生诊断顺序仍未完全恢复。当前产品仅对直接目标和直接 `0/1` 动作建立复位/置位结论；未告警结果继续要求人工复核。
