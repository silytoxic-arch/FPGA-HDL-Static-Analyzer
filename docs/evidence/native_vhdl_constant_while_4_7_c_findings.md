## Recovered predicate

- `FUN_1804a1210` 在 `+0x178` 写入双字节值 1；按小端序三个选项字节 `+0x178..+0x17a` 实际为 `1,0,0`。因此 slot 0 在建立声明图后只执行 `FUN_1807856c0` 和 `FUN_1807857a0`，不会进入 `4.7.a` 使用的 `FUN_1807859e0/FUN_180785240` 分支。
- `FUN_180785f30` 按设计根递归建立解析后的声明/名称映射；后续查找使用大小写折叠后的名称。
- `FUN_1807857a0` 只处理类型 `0x58` 且只有一个条件子节点的控制节点。结合附件规则和两处示例，该节点对应顺序 `WHILE ... LOOP`。
- 条件子节点是类型 `0x10` 的直接字面量，或类型 `0x13` 且能在常量名称映射中解析时，节点进入常量条件集合。
- 对复合条件，仅类型 `0x34`、`0x35`、`0x36`、`0x37`、`0x3a`、`0x3b` 六类双目关系运算被接受；左右直接子节点必须分别是字面量或可解析常量名。该分支判断“是否静态”，不计算最终真值。
- 普通运行时信号/变量名、常量与运行时名称混合比较和其他复合运算不满足此核心谓词；附件示例把该选项路径绑定为 WHILE 检查，IF 分支则由 `4.7.a` 的独立选项字节控制。

## 产品接入

- 为 `GJB9765.4.7.c` 使用专用 VHDL WHILE 检查，不再复用会同时映射 IF/ELSIF/条件赋值的通用 `RTL-CONSTANT-CONDITION` 结果。
- 支持直接布尔、数值、字符和字符串字面量，具有本地初始化器的常量，以及与当前 architecture 匹配的 entity generic。
- 支持 `=`、`/=`、`<`、`<=`、`>`、`>=` 六种直接关系表达式；两侧都必须是直接字面量或已解析静态名称。
- 常量按 architecture 隔离，generic 按 `ARCHITECTURE ... OF entity` 绑定，避免从另一个设计单元借用同名常量。
- 未初始化的 deferred constant 不作肯定判断。
