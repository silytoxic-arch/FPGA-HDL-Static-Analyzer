# GJB10157.7.2.2 基本门锁存器原生判据

目标：用户附件 `T-Linter.dll`，SHA-256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。本记录区分静态观察和产品实现；没有执行厂商程序。

## 已观察的报告路径

1. 规则构造函数 `0x180022ba0` 的 vtable slot 0 是 `FUN_1805698f0`。
2. 入口注册四个单元类型：`FUN_180568ec0` 取 `$and`，`FUN_180568cb0` 取 `$or`，`FUN_180568050` 取 `$logic_and`，`FUN_1805689f0` 取 `$logic_or`。对应字符串分别位于 `0x180e865e9`、`0x180e865f1`、`0x180e866d1`、`0x180e866e1`。
3. 入口调用 `FUN_180565fe0` 建立单元输入/输出信号关系。该函数末段调用递归 `FUN_18056cb20`：它建立递增访问索引和 lowlink 值、维护活动栈，在根节点索引等于 lowlink 时弹出分组。因此“分组是强连通反馈分量”是受静态结构支持的解释。
4. 入口逐个遍历分量，按四种类型累计计数。`if (2 < count)` 分支直接跳至下一分量，未进入该分量告警路径。统计的是指定四类单元，不是所有单元总数；反相器不会增加该计数。
5. 对保留分量，`FUN_18056bfd0` 从输入/输出关系求内部信号名称；入口拼接名称并以 `0x180ef2be8` 的 GB18030 文本报告：`发现使用基本逻辑门来描述锁存器`。

## 产品实现

`verilog_gate_feedback.h` 将标量连续布尔表达式及 AND/OR/NAND/NOR/XOR/XNOR/NOT/BUF 基本门实例转换为模块内有向图，用迭代强连通分量算法检查反馈。NAND/NOR 转为一个计数门加一个反相单元；BUF 按连线处理；别名本身不能形成基本门告警。仅在环内含至少两个单元且指定四类门计数不大于 2 时报告，每个环一条。

保留大小写敏感名称、模块作用域和原生“大于两个计数门则跳过”的边界。时序过程不作为组合图边；重复驱动、未知实例、向量、常量折叠、参数、generate 以及不支持的表达式会让该模块保留复核，而非推导一个不可靠的反馈图。
