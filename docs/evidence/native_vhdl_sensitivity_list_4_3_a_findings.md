## Recovered predicate

- 构造函数把对象偏移 `+0x158..+0x15b` 的四个子检查开关全部置 1，并把 `+0x15c` 置 0；slot 0 对每个设计单元清空对象偏移 `+0x160/+0x170/+0x180` 的名称映射后执行递归收集。
- `FUN_1805d51e0` 遍历过程子树，识别赋值类节点、普通标识符和解析后的引用，并把名称送入读集合或驱动集合。`FUN_1805d5300` 同时构造显式敏感列表集合，并在完成一个受支持的非时钟过程后调用集合比较。
- `FUN_1805d3880` 的三个启用分支分别执行：
  1. 遍历过程读取集合，名称不在显式敏感列表时逐名报告“敏感信号列表缺失信号%s”；
  2. 遍历显式敏感列表，名称既不在读取集合也不在驱动集合时逐名报告“敏感信号列表有冗余信号%s，进程内未使用的信号不要出现在敏感信号列表中”；
  3. 遍历显式敏感列表，名称不在读取集合但位于驱动集合时逐名报告“敏感信号列表有冗余信号%s，进程内被驱动的信号不要出现在敏感信号列表中”。
- 上述三条诊断模板位于 `0x180efdee8` 起始的 GB18030 字节区，分别从 `0x180efdee8`、`0x180efdf00`、`0x180efdf50` 开始；`FUN_1805d4160` 使用 `0x180efdf98` 的通用冗余模板处理另一组已解析名称关系。
- 原生实现按名称逐条报告，而不是把多个缺失或冗余名称合并为一条。缺失项使用过程体内对应引用节点的位置；冗余项使用敏感列表或其解析记录的位置。
- 时钟/不受支持的过程形态通过调用参数跳过集合比较；未看到把时钟过程按组合逻辑缺失列表处理的路径。

## 产品接入

- 继续将 `RTL-INCOMPLETE-SENSITIVITY` 与 `RTL-REDUNDANT-SENSITIVITY` 都映射到 `GJB9765.4.3.a`；原生诊断文本证明两种方向都属于本规则。
- VHDL 检查现按每个差异名称分别输出，缺失信号定位到首次过程体读取，冗余信号定位到显式敏感列表项，并写入标准化后的信号名。
- 写入但未读取的列表信号仍按冗余处理，与原生“被驱动的信号”分支一致。
- VHDL 名称继续按不区分大小写比较；`process(all)` 和包含边沿/`event` 的时钟过程不进入该组合集合比较。
