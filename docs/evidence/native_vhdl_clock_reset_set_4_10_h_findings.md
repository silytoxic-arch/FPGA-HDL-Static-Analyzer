## Documented constant-action branch（已撤回推断）

附件把纯 rising_edge(clk) 下的 dout <= '0' 标为违反；此前为了吻合这个例子，
产品增加了文档驱动的纯常量动作分支。第一百二十七轮恢复实际前端和收集器后确认，
边沿调用生成 0x65/0x66，而 EQ 控制收集路径要求已有 0x36 条件；直接常量赋值
不会单独生成本规则的复位条件。该额外报警分支已删除。

仅对具有精确源码摘要的这个例子记录静态实现/文档差异；保留原文与预期标签，
不把差异算作吻合，也不伪装成厂商运行验证。

## 第一百二十八轮：扩大已证明的来源范围

原生收集器无条件递归，新增对 postponed process、IF/FOR generate 与 block
后代的来源检查。完整结束符限定范围；局部声明及整数迭代变量隐藏外层对象后，
不会误用外层的 IEEE 标量类型。明确的局部标量建立独立词法 owner。
同一 owner 配对保留原生次数；不同局部 owner 的同名额外配对仍未确认原生限定名，
保持 incomplete，不猜测跨范围相等。

无原型反编译的一处假 null 根参数已用寄存器指令核对，明确 ABI 注释后重新输出；
错误版本保留为反例证据，不作为源算法事实。
详见 [第一百二十八轮](../native_rule_recovery_pass128.md)。

## 第一百二十九至一百三十一轮：声明与进程来源

标识符枚举和无关 subtype 不再阻断整个 architecture；按声明顺序绑定可见的
无约束 IEEE 标量 subtype 链，并分别处理 block/generate 中的类型/对象遮蔽。
process 也支持有界局部 variable/constant/类型声明及初始化，允许唯一顶层 IF
前后的简单信号赋值与 NULL。声明、INITIAL、赋值和 NULL 不被误计为第二个源 IF。

多个顶层 IF、复杂语句和未确认的同名跨 owner 配对继续未知。

这扩大了已恢复谓词的有界来源范围，不声称恢复了完整原生类型/语法引擎。
