# GJB10157 Verilog 名称形态规则条件编译边界

## 范围

本记录覆盖 `GJB10157.5.2.1`、`.5.2.2`、`.5.2.4` 和 `.5.2.12`。这些规则均从
`T-Linter.dll` 的前端 AST 声明节点读取名称；本产品只恢复其证据支持的名称谓词，并以有界
源码声明适配器重建输入，不声称恢复完整厂商前端。

附件 `T-Linter.dll` SHA-256：
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 二进制直接观察

- `.5.2.1`：MODULE/WIRE/PARAMETER/LOCALPARAM/CELL/TASK/FUNCTION 的非空归一名称，首个
  ASCII 字节为数字或下划线时报告。证据：
  `ev_8ed10f75820818d3d20d08887706e8cd7659c8e91158a8f12d34d1be83f68c3b`。
- `.5.2.2`：排除 FUNCTION 本身的六类声明；归一名称含连续下划线或以下划线结尾时报告。
  函数内部的网络/参数后代仍可进入收集器。证据：
  `ev_32bd8b91ae9488d76d830d21919304bee359a91224d19bde6409118acd1fab75`、
  `ev_440621dd15465fbff20fba21f55c4de203e5e109759ef80d4edf7fcab5abdb86`。
- `.5.2.4`：同一六类声明的非空名称经过 ASCII 大小写归一后，与
  `VDD/VSS/VCC/GND/VREF` 全名精确相等才报告；不是前缀或子串判断，FUNCTION 本身不报告。
  证据：`ev_a9ff5e1f8c558a95613fe54cd4ca2bccb6312f68c4803bd832692c1ea973d5a0`。
- `.5.2.12`：同一六类声明的非空归一名称，字节长度在闭区间 2..32 之外时报告，FUNCTION
  本身不进入长度检查。证据：
  `ev_72031d097e80e28af266b1d999a091e98e505f631f13006bbb16c39c3b51e52b`、
  `ev_18d1ea59101ccfacbaf11002bc798a90887dab8fc02865c01c8d2c786def1449`。

## V1.4.13 产品适配

原生规则读取已完成条件选择的 AST 声明。产品此前扫描原始 token，并保守跳过任何
`ifdef/ifndef` 块中的声明，因此活动分支中的确定违规也不会报告。

V1.4.13 在工程 `defines` 预处理成功后，对活动 token 流运行同一个有界声明适配器：

- 活动分支中的四类确定违规正常报告；
- 只存在于非活动分支的声明不参与判断；
- 诊断行列继续映射到原始物理源文件；
- 预处理失败时不猜测哪个声明存在。

## 仍未知

- 完整宏参数、include 和 generate 展开后产生的 AST 声明；
- 转义标识符、非 ASCII/区域设置、复杂 cell 和不透明类型的完整前端归一行为；
- 厂商语法错误恢复，以及完整宏/include/generated 前端和全局排序细节。`.5.2.1`、`.5.2.2` 与 `.5.2.4` 的唯一模块组、固定正文、Error、无列及每节点多重性均已在后续恢复；其中专有 AST 位置整数的精确生产语义仍未完全命名。

因此命中可以确定为违规；无命中仍保持 `ManualReviewRequired`，不声明整条规则合规。
