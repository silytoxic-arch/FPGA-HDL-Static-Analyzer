## Recovered predicate

执行槽从每个设计根收集类型 `0x52` 的进程节点，为每个进程单独调用关系构建器。新增定点反编译确认关系构建器的优先级及本规则的消费范围：

- `FUN_18065a0c0` 的进程向量来自 `FUN_1804c5890`；该函数的完整定点反编译证明它只遍历输入根的直接 `AST_ARCHITECTURE(0x75)` 子节点和各 architecture 的直接 `AST_ALWAYS/process(0x52)` 子节点，不递归进入 generate、block、子程序或其他并发节点。因此嵌套 process 不属于本规则的逐进程比较集合。证据见 `native_vhdl_direct_process_collector_4c5890.txt`，SHA-256 `fdfe77d6d9ec134b166d321c11ef651b5b7fbc15bba2280f725f8afe72d05f91`；

- `FUN_1804d71d0` 成功时写入类别 3；x86-64 指令 `0x1804d730c..0x1804d7352` 证明它在 `FUN_1804c4430` 找到边沿时返回 `0`，只有没有找到边沿时返回 `1`，因此类别 3 是无边沿关系；
- 否则 `FUN_1804d24a0` 产生类别 1 或 4：外层非边沿控制之后找到 ELSIF/ELSE 链接边沿，具有 `FUN_1804d20e0` 证明的常量动作时为类别 1，否则为类别 4；
- 再否则 `FUN_1804d68a0` 产生主 IF 条件本身为边沿的类别 2；
- `FUN_18065a0c0` 精确遍历类别 `[1,2)`、`[2,3)`、`[3,4)`，没有遍历类别 4。类别 3 没有时钟名，不会产生多时钟比较；类别 4 即使源码含后续边沿也不进入本规则。

新增对 `FUN_1804c5070` 与类别 2 生产器 `FUN_1804d68a0` 的联合恢复进一步限定了候选所有权：

- `FUN_1804c5070` 只在设计根下两个固定 `AST_BLOCK(0x54)` 层级中收集带 `+0x183` 来源标志、且 `+0x188` 指回 `AST_IF(0xaa)` 的 `AST_CASE(0x57)`；该固定深度对应进程顺序语句块的直接源码 IF，分支、CASE 或 LOOP 内更深的 IF 不会成为独立关系根；
- `FUN_1804d68a0` 只遍历所选来源 IF 的直接 `AST_COND(0x58)` 子节点。主条件找到边沿后，最终关系对象 `+0x18` 保存外层来源 IF、`+0x20` 保存该外层边沿名称、`+0x58` 写入类别 2；
- 它随后检查分支块首项所链接的来源 IF，只为内部关系记录和 `+0x10` 标志服务。ELSIF 以及分支中的嵌套 IF 不会把其边沿名称覆盖为本条规则的另一个类别 2 时钟；
- 同一进程存在多个独立顶层来源 IF 时，每个 IF 分别生成关系，因此不同主条件时钟仍参加进程内比较。

对类别 1/2 中的关系，后续分支按关系名称和一个整数边沿字段维护集合：

- 进程内出现第一个时钟关系时建立基线，不报告；
- 后续关系使用新的归一化时钟名称时，报告“同一个process中出现多个时钟信号”；
- 后续关系复用已有名称、但整数边沿字段与已存记录不同时，拼接报告“同一个process中出现时钟” + 名称 + “的多个沿触发”；
- 名称与边沿字段均相同的重复关系不报告；
- 集合在各进程之间重新建立，因此不同进程各自使用一个时钟不构成本条违规。

### 类别 1 的静态动作边界

新增定点反编译恢复了 `FUN_1804d20e0` 的完整直接分支。该函数递归进入 `AST_BLOCK(0x54)`，并只把恰有两个子节点的 `AST_ASSIGN_LE(0x56)` / `AST_VARASGN(0xa2)` 作为动作赋值。其 RHS 满足下列任一条件时返回真：

- 直接 `AST_CONSTANT(0x10)`；
- `AST_CONCAT(0x22)` 的首个直接子节点是 `AST_OTHERS(0x89)`；
- `AST_CONCAT(0x22)` 的每个直接子节点都是 `AST_CONSTANT(0x10)`；
- 单一 `AST_IDENTIFIER(0x13)`，且节点 `+0x58` 已绑定、规范化名称存在于全局树 `0x181347dd8`。

关系构建器在每个设计根开始时清空该树，并以当前设计根调用 `FUN_1804cbad0`。后者只从下列直接结构建立不区分大小写的命名值集合：

- `AST_GENERIC(0xa3)` 的已绑定直接标识符，即所属实体泛型；
- `AST_ARCHITECTURE(0x75)` 的直接 `AST_LOCALPARAM(0x0a)`，即 architecture 常量；
- 同一 architecture 的直接 `AST_TYPE(0x77)` 所声明的枚举标识符。

因此普通信号、process 局部常量、局部 package 内的常量以及其他 architecture 的声明不会通过此名称成员测试。命名值构建器还保存初始化值，但 `FUN_1804d20e0` 在本分类点只检查名称成员资格，不再次比较具体值。

### 类别 1 的分支顺序与 ELSE 链接 IF

`FUN_1804d24a0` 对来源 IF 的直接子节点按顺序处理，恢复出的状态边界如下：

- 主 `AST_COND(0x58)` 先建立静态动作标志；随后逐个处理直接 `AST_ELSIF(0xab)` 的直接条件；
- 第一个带边沿的 ELSIF 成为主关系时钟，后续带边沿 ELSIF 以 0x28 字节记录追加到关系对象 `+0x40..+0x50` 的向量；`FUN_18065a0c0` 会继续消费该向量，因此同一 IF/ELSIF 链中的多个边沿均参加 `R-9-4` 比较；
- 非边沿 ELSIF 在尚无“额外边沿记录”时仍调用 `FUN_1804d20e0`，可以把静态动作标志置真。也就是说静态分支可以位于首个边沿之前，或首个与第二个边沿之间；第二个边沿已经追加后，再出现的非边沿静态分支不再改变类别 4；
- 对直接 `AST_ELSE(0xac)`，函数遍历其直接块，并在发现多个 `+0x188` 来源 IF 时不断覆盖指针，最终只处理最后一个直接链接 IF；
- 对该链接 IF 只遍历直接 `AST_COND(0x58)`，因此使用其主条件，不借用其 ELSIF。IF 若嵌套在 ELSE 内的 CASE/LOOP 等更深结构中，也不属于这一直接链接层级。

这些观察解释了类别 1 与类别 4 的分界不是“第一分支必须静态”，也不是“任意位置出现静态赋值即可”，而是一个受额外边沿记录状态约束的顺序判定。

### 条件边沿收集顺序与旧式 event

新增恢复确认 `FUN_1804c4430` 为条件边沿识别入口，其过滤表 `0x180ee30c0` 的四个类型依次为 `AST_POSEDGE(0x65)`、`AST_NEGEDGE(0x66)`、`AST_LOGIC_AND(0x45)`、`AST_BIT_AND(0x25)`。`FUN_1804f3870` 先在当前节点类型命中过滤表时追加当前节点，再按子节点向量顺序递归，因此产生“当前节点优先、子节点从左到右”的 AST 先序候选序列；入口按该序列扫描并在第一个成功候选处停止。

对 AND 候选，`FUN_1804d4cc0` 扫描全部直接子节点，不要求 `event` 属性与等式的源码左右顺序。只要一个直接子节点是带唯一 `event` 属性的标识符，另一个直接子节点是同名标识符与精确二进制字符常量的 `AST_EQ(0x36)`，即可恢复上升沿/下降沿。由此可确认：

- `clk'event and clk='1'` 与 `clk='1' and clk'event` 均可识别；
- 围绕直接操作数的源码括号在 AST 中消失，不阻断识别；
- `AST_LOGIC_OR(0x46)` / `AST_BIT_OR(0x26)` 不属于旧式边沿候选，但其后代中的合法 AND 或 edge 节点仍会由递归收集器发现；
- 左结合表达式中，合法左子树的旧式边沿先于后续显式 edge 调用；若更早的显式 edge 位于左子树，则先选择该显式 edge；
- 不能把相邻源码片段误当成 AST 子树，例如 `enable and clk'event and clk='1'` 的尾部两项不是一个独立右子树，而显式括号 `enable and (clk'event and clk='1')` 会建立可识别子树。

持久化证据为 `native_vhdl_edge_condition_preorder.txt`。

## 产品接入

移除 `RTL-MULTIPLE-CLOCKS-PER-PROCESS` 到本条款的宽泛翻译，改为 VHDL 专用、逐进程检查：

- 不再直接消费宽泛 `clockEvents`；该模型会把赋值右侧、断言等非 `AST_COND` 位置的 edge 函数也记录为时钟；
- 按已恢复源码形状重建类别 1/2：直接主 IF 边沿属于类别 2；类别 1 按直接 ELSIF 顺序累计主边沿、额外边沿与受状态约束的静态动作，并只使用 ELSE 中最后一个直接链接 IF 的主条件；
- 只枚举 architecture 的直接 process；generate、block、子程序等嵌套范围内的 process 不进入本规则；
- 按进程顺序语句块枚举独立顶层 IF；排除 CASE、LOOP、分支块内的更深 IF。类别 2 只记录外层 IF 主条件的第一个边沿，不把 ELSIF 或链接嵌套 IF 当作新增时钟；
- 排除无边沿类别 3 和未证明常量异步动作的类别 4；在 IF/ELSIF 条件范围内按原生先序过滤提取第一个可识别的直接或后代边沿；
- VHDL 名称按不区分大小写归一化；
- 对第一个关系之后的每个新增时钟信号分别报告；
- 对同一时钟的相反边沿报告；
- 对同名同沿重复关系去重；
- 诊断位置落在发生冲突的时钟事件上。
