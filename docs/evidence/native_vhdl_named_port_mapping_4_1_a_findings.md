## Recovered predicate

`FUN_180779190` 从每个设计根递归遍历 AST，将类型 `0xa5` 的节点加入全局向量，并继续访问其子节点。`FUN_180778a50` 随后逐个处理这些关联容器，直接枚举容器子节点：类型 `0x8b` 被视为允许的具名关联；遇到首个其他类型便用该子节点 `+0x214` 的源码行构造诊断，然后退出当前容器的子节点循环。

由控制流可得：

- 全部子项均为类型 `0x8b` 时不报告；
- 存在位置关联或混合关联时报告；
- 同一关联容器内即使有多个位置项，也只报告一次；
- 多个违规关联容器分别报告，因此诊断重数是每个违规实例最多一条。

原生常量 `0x180f1cd20` 按 GB18030 解码为“实例化模块使用名称关联方式映射，而不使用位置关联方式”，与附件 GJB9765.4.1.a 正反例一致。

## 产品映射与验证

产品把原生关联容器映射为解析成功的 VHDL 实例端口映射：`hasPositionalConnections` 为真时在实例位置发出一条 `GJB9765.4.1.a`。新增回归覆盖两个位置实例、一个实例含多个位置项、位置/具名混合映射，以及带 `formal => open` 的全具名映射。

## 限制

类型 `0xa5`、`0x8b` 的厂商枚举名仍未恢复；原生前端中 generic map 与 port map 的完整分类、configuration/binding、包限定名称、generate、畸形语法恢复、重复设计根和诊断顺序仍未知。产品只对解析器确认的 VHDL 实例端口映射应用该判据，诊断定位在实例而不是首个位置关联子项；干净结果不声明与厂商前端完全等价。
