# GJB10157.6.2.3 / 6.2.7 组合逻辑复位原生判据

## Recovered predicate

目标为用户附件中的 `T-Linter.dll`，SHA-256 为
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

静态逆向观察到：

- `GJB10157_VLOG_6_2_3` 构造函数位于 `0x180022700`；
- `GJB10157_VLOG_6_2_7` 构造函数位于 `0x180022840`；
- 两个构造函数均先注册兼容键 `VLR-110069`，并分别把规则对象
  `0x18134c7d0 / 0x18134cac0` 的 `+0x158` 模式字节清零；
- 两个类的 slot 0 均为 `FUN_180758410`（`0x180758410`），证据
  `ev_84ff04283d5bc45c830f2cd48b7030d46eb94114556b32aa556a0b8308ae6833`；
- 两个类的 slot 1 均为模块过滤器 `FUN_1807238a0`，证据
  `ev_aaa493aac258e6c8e9f4d04fcd2ebeb575f37e5d55e363a21c32a358a3f3965b`。

`FUN_180758410` 在模块内收集 `AST_ASSIGN(0x4d)` 与 `AST_ALWAYS(0x52)`。
对于 `AST_ALWAYS`，只有不含 `AST_POSEDGE/AST_NEGEDGE(0x65/0x66)` 的过程进入
组合赋值路径，并继续收集 `AST_ASSIGN_EQ/LE(0x55/0x56)`。赋值目标与已建立的
异步复位关系匹配后，普通组合表达式进入诊断构造；连续赋值右侧为单个
`AST_IDENTIFIER(0x13)` 时不直接报警。右侧为 `AST_LOGIC_NOT(0x47)` 或
`AST_BIT_NOT(0x24)`、恰有一个直接子节点且该子节点为 `AST_IDENTIFIER(0x13)` 时也进入
关系传播路径。枚举名称与宽度类别的独立交叉证据见
`native_ast_not_types_0x24_0x47.txt`。

别名并非只检查一层。`FUN_180758410` 每轮把当前关系名对应赋值中的直接/单目 NOT
来源加入下一来源集合，随后调用 `FUN_18075a210` 清空当前工作集；遍历下一来源时以
`FUN_180676aa0` 查询已访问名称计数，仅在计数为零时通过 `FUN_180579cf0` 插入下一轮。
循环持续到当前工作集为空。三个辅助函数的定点反编译分别确认了“清空树”“匹配项计数”
和“插入树”语义，详见 `native_verilog_reset_alias_worklist_6_2_3_6_2_7.txt`。
访问树只对下一轮关系名称去重；当前名称下的每个非别名赋值记录都会各自进入诊断构造，
没有按名称或物理行合并。因此同一物理行的两个独立驱动应报告两次，而两条别名路径汇聚
到同一上游名称时，该上游只遍历一次。

附件中两个条款的违规示例均为 `assign my_comb_rst = A & B` 后把
`my_comb_rst` 用作异步控制；正确示例均由 `always @(posedge CLK)` 寄存产生复位。
因此产品为两个条款保留独立诊断，但复用同一个有证据支持的核心判据。

## Recovered diagnostic surface

`FUN_180758410` 在诊断分支读取规则对象 `+0x158`。两个已注册对象均为零，故都进入
同一默认分支：

- `FUN_1800d37b0` 按“C 字符串 + 动态字符串”的顺序拼接地址 `0x180f10888`
  的 GB18030 常量 `异步复位` 与归一化赋值目标；
- `FUN_1801380f0` 再追加地址 `0x180f1ab50` 的常量 `用组合逻辑驱动`；
- 地址 `0x180ee83b0` 为 `警告`；
- 文件来自违规赋值 AST `+0x1e0`，物理行来自 `+0x210`，报告对象没有写入列号。

因此两个规则的精确正文均为 `异步复位<归一化目标名>用组合逻辑驱动`，级别均为
`Warning`，位置为违规赋值的物理行且无原生列。完整静态摘录见
`reverse-tools/evidence/t_linter_pass77/r5_3_combinational_reset.txt`。

## Product integration boundary

产品只在同一 Verilog 模块内，对解析器确认的异步复位/置位信号执行以下确定性检查：

- 非平凡连续赋值表达式驱动异步复位时报警；
- 无边沿组合过程赋值驱动异步复位时报警；
- 直接标识符别名及单级 `!`/`~` 标识符（含标识符选择）别名不直接报警；
- 双重 NOT、函数调用、归约运算及其他非标识符直接子节点不冒充别名；
- 对直接或单目反相别名执行带访问集合的多级反向传播，直到外部源、组合驱动或循环终止；
- 逐非别名赋值节点报告；仅对已访问的关系名称去重，不按物理行合并；
- 两个规则均输出 `异步复位<目标名>用组合逻辑驱动`、`Warning` 和赋值物理行；
- 带 `posedge`/`negedge` 的时序过程生成复位不按本判据报警。

尚未恢复异步复位关系图的完整生产过程、跨层次传播、原语或库单元复位端口、
宏、generate、复合左值、分层标识符的专有前端降低方式及跨设计根诊断排序。
这些形式仍是未知边界；无诊断时保持 `ManualReviewRequired`，不声明完整厂商算法等价。
