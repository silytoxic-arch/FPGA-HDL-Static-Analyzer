# R-13-9 / GJB10157.9.4.9 敏感列表关系恢复记录

## 目标与证据边界

- 目标：T-Linter `GJB10157_VLOG.9.4.9`，产品公开编号 `R-13-9`。
- 二进制：`T-Linter.dll`，SHA-256 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
- 本记录来自 Ghidra 12.1.4 离线静态反编译和附件 HTML 样例，不代表执行过厂商程序。
- 原始导出保存在 `reverse-tools/evidence/r13_9/` 的 `native_entry_functions.txt`、`relation_initializers.txt`、`relation_vtables.txt`、`relation_virtual_methods.txt` 和 `relation_strings.txt`。

## 已观察事实

1. 构造函数 `0x180591860` 注册规则名，并在对象偏移 `+0x158`、`+0x2b0` 分别构造两个关系对象；其内部规则类型为 `VLR-110012` 和 `VLR-110013`，前缀分别初始化为 `r1_`、`r2_`。
2. 执行函数 `0x180591ad0` 对相同的名称/AST 位置数据并行更新两对象，随后分别调用虚函数判断关系是否成立；这证明原生实现维护两个方向不同的关系，不是把全部差异合并成一个结果。
3. `VLR-110012` 的虚表 slot 0 为 `0x180756330`。该函数按名称遍历关系结果，并使用 GBK 字节串：
   - `0x180f1a860`：`组合always敏感列表中信号`
   - `0x180f1a850`：`是冗余的`
   因而该对象对应冗余敏感项，完整消息为 `组合always敏感列表中信号<名称>是冗余的`。
4. `VLR-110013` 的虚表 slot 0 为 `0x180755270`。该函数按名称遍历另一方向的关系结果，并使用：
   - `0x180f1a7b0`：`组合always块的敏感列表不完整，缺少信号`
   - `0x180f1a790`：`敏感列表不完整，缺少信号`
   默认组合过程路径使用前一模板，因此缺失消息为 `组合always块的敏感列表不完整，缺少信号<名称>`。
5. 两个输出函数都位于逐名称循环内调用诊断提交函数；附件错误例也分别列出 `D`、`A6`、`CLK` 等名称。因此原生报告粒度是每个缺失/冗余名称一条，而非每个 `always` 合并一条。
6. 附件三组正反例证明普通显式组合敏感列表同时检查两个方向；`posedge` 时序过程不按本条组合关系报告。

## 产品接入

- Verilog 显式非边沿 `always` 继续建立正文读取集合与敏感列表集合，并分别计算缺失和冗余关系。
- 每个差异名称独立输出；缺失项定位到正文中该名称的首次读取，冗余项定位到敏感列表中该名称的首次出现，同时写入 `signal` 字段。
- 诊断消息改为上述原生中文模板。同一 `always` 同时存在缺失和冗余时保留两类结果，不按位置吞并。
- 自动敏感列表和含 `posedge`/`negedge` 的过程仍排除；普通 Verilog 中只对已在显式列表出现的未声明名称做有界隐式网线建模。

## 尚未恢复

- 原生 AST 名称归一化、别名和跨层次引用、函数调用隐式读取、宏展开及错误恢复语法的完整处理仍未知。
- 两个关系对象的所有内部映射字段、结果排序和预处理后源位置规则尚未完全命名。
- SystemVerilog `always_comb` 的隐式函数体敏感性属于语言前端语义，本条有界适配器未宣称与厂商完整前端等价。
- 未产生诊断的结果继续保留 `ManualReviewRequired`，不能据此宣称合规。
