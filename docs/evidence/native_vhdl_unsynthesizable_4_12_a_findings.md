# GJB9765.4.12.a 原生判断恢复记录

## 样本与边界

- 样本：附件 `T-Linter.dll`
- SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 目标规则入口：`FUN_1805b9590`（slot 0）
- 递归候选收集器：`FUN_1805ba200`
- 方法：Ghidra 12.1.4 只读反编译；未执行或修改厂商程序。

## Recovered predicate

入口先对每个分析根调用 `FUN_1805ba200`，再依次处理三个互相独立的候选数组。该结构证明 4.12.a 不是“任意不可综合语句”的泛化标签，而是以下三类确定谓词。

### 1. 空字符串常量

收集器仅接纳 AST 类型 `0x0a` 且节点字节 `+0xa6 != 0` 的记录。入口遍历该记录的直接子节点，仅在子节点类型为 `0x10`、其直接字符串长度恰为 2、字节恰为 ASCII `""` 时报告。

原生 GB18030 文本位于 `0x180efa990`，解码为“空字符串常量不可综合”。产品因此只检查完整直接初值为 `""` 的 VHDL `constant` 声明；普通字符串表达式、非空常量以及 `"" & "x"` 组合表达式不作该告警。

### 2. 非整型 generic

收集器在 AST 类型 `0xa3` 上收集其每个直接子节点。入口只在候选的 `+0x109 == 0` 且 `+0x110 == 0` 时报告。既有独立原生证据已将 `+0x109` 映射为 integer 类型标志；`+0x110` 的正式字段名尚未恢复。

原生 GB18030 文本位于 `0x180efa9a8`，解码为“非整型generic不可综合”。产品接入可在源码中无歧义识别的标准非整数类型，包括附件给出的 `string`、`std_logic`、`std_logic_vector`，并补充 boolean、real、time、bit/vector、signed/unsigned 等标准类型。`integer`、`natural`、`positive` 保持通过；用户自定义 subtype/package 类型不猜测底层类型，继续标记为需要人工复核的未覆盖边界。

### 3. wait for

收集器仅接纳 AST 类型 `0x7c`、至少有一个子节点且第一个子节点类型为 `0x5c` 的记录。入口对每个记录逐一报告。结合原生 GB18030 文本 `0x180efa9c0`（“wait for语句不可综合”），可确定这是 `wait for` 的精确子类判断，而不是所有 wait 语句。

产品因此报告每个活动源码中的 `wait for`，但不报告 `wait until`、`wait on` 或裸 `wait;`；注释和字符串由词法器排除。

三个分支均使用候选节点 `+0x214` 的物理行号，严重度固定字符串为 `Error`（`0x180edc5a8`）。

## 产品接入与撤销的宽泛映射

V1.3.84 用上述三个直接谓词替换原有仅依赖附件三种 generic 类型的文档适配器。同时撤销 `VHDL-PROCESS-NO-SUSPENSION` 和通用 `RTL-NONSYNTHESIZABLE-DELAY` 到本条款的宽泛映射：原生候选收集器没有这两个泛化分支，`after` 延时和无悬挂进程不能据此自动归入 4.12.a。

回归覆盖：

- integer/natural generic 正例；附件三种非整数 generic 反例；boolean/real/time 扩展反例；用户 subtype 边界。
- 单个及多个 `wait for` 反例；`wait until`、`wait on`、裸 wait、注释/字符串边界正例。
- 直接空字符串常量反例；非空、组合表达式和普通空字符串表达式正例。

## 未恢复范围

AST 类型 `0x0a/0x10/0xa3/0x7c/0x5c` 的厂商正式枚举名、`+0x110` 的正式含义、用户 subtype/package 类型传播、前端常量折叠与限定表达式、错误语法恢复及精确遍历顺序仍未知。当前接入是证据支持的核心谓词子集，不宣称与厂商前端完全等价；未覆盖干净结果仍需人工复核。
