# GJB10157.5.2.13（A-2-3）原生时钟命名规则恢复

## 目标与身份

- 附件：`T-Linter.dll`
- SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`
- 构造函数：`0x180021380`
- 规则入口：`FUN_18052ebd0`（`0x18052ebd0`）
- 公开编号：`A-2-3`
- 内部映射：`GJB10157.5.2.13`

本文件记录的是对附件二进制的离线静态分析，不是原程序运行观测，也不代表已恢复厂商前端的完整语义模型。

## 已观察事实

1. 构造函数注册字符串 `GJB10157_VLOG.5.2.13` 和对应虚表。
2. `FUN_18052ebd0` 遍历全局设计记录；`FUN_1804dedf0` 仅接受首字节为 `2` 或 `3` 的关系记录。其正式枚举名称尚未恢复。
3. 关系名称经设计映射解析回候选 AST；`FUN_1804df040` 对 Verilog 转义标识符名称执行规范化。
4. 规范化名称进入每个设计记录独立的集合。集合中已有相同字节序列时跳过，因此同一信号在上升沿、下降沿重复出现只报告一次。
5. 唯一名称分别执行完整匹配：
   - `clk_[0-9a-z]+[0-9a-z_]*`
   - `Clk_[0-9A-Z]+[0-9A-Z_]*`
6. 两个正则均不匹配时，规则从候选 AST 的 `+0x1e0` 读取源路径、从 `+0x210` 读取物理行；没有观察到列号字段。
7. 严重度固定为 `error`。
8. 二进制中的 GB18030 消息由前缀、规范化名称、后缀拼接：

   `时钟信号<name>命名应采用“clk_x”或者“Clk_X”,其中“x”代表特定含义的时钟频率`
9. 虚表槽 `FUN_1807238a0` 仅接受类型 `2`，DLL 自身类型表将其映射为 `AST_MODULE`。
10. 准备阶段 `FUN_18062d430` 递归遍历模块树，只对类型 `6`（`AST_WIRE`）调用 `FUN_18062b0a0`。后者以模块键和 `AST_WIRE` 名称建立规则对象 `+0x58` 的二级映射，并把该声明节点指针写入内层记录 `+0x40`。
11. `FUN_18052ebd0` 按关系所属模块和规范化信号名查询同一映射，从内层记录 `+0x40` 取回声明节点；失败诊断的文件 `+0x1e0` 和物理行 `+0x210` 因此来自 `AST_WIRE` 声明，而不是 `posedge/negedge` 使用点。

## 产品接入

- 保留两个正则的 ASCII、大小写和完整匹配语义。
- 对解析到的 Verilog 时钟候选按模块、规范化名称去重，不再按边沿重复告警。
- 只对可在当前活动预处理分支中解析到的端口、`wire`、`reg` 或 `logic` 声明执行规则；隐式网及不支持的声明形态不伪造原生映射命中。
- Verilog 转义标识符由词法器移除前导反斜杠后再匹配和显示。
- 诊断使用完整原生消息、`Error`、声明物理行和第 1 列。
- 增加正例、反例、边界、同名双边沿、转义标识符、内部声明、隐式网和跨模块作用域测试。
