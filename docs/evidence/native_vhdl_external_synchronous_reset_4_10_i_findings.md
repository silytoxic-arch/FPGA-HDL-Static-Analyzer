## Recovered predicate

原生入口首先收集设计单元中 AST 类型 `6` 的名称，并通过 `FUN_1804d77f0` 放入去重集合。随后它收集所有 AST_ALWAYS（`0x52`）进程，并对每个进程调用 `FUN_1804d56f0` 构造时钟/复位关系树。

入口从关系树中选择类别 `2` 且有效标志非零的记录，遍历其嵌套名称记录；当关系名称能够在前述外部端口集合中找到时进入报告分支。因此它不是简单地查找名含 `rst` 的赋值，而是求“同步复位关系名称”和“设计单元外部端口名称”的交集。

DLL 中相邻 GB18030 字符串解码并拼接为：

`同步复位时,外部复位信号` + 信号名 + `宜使用两级级联寄存器同步`

附件正反例确定了类别含义：

- 违反例在时钟沿分支内直接使用实体输入 `rst` 作为同步复位条件，形成交集并报告。
- 符合例先用同一时钟沿执行 `rst_n_syn0 <= rst`、`rst_n_synl <= rst_n_syn0`，业务进程使用内部第二级 `rst_n_synl`；该名称不属于实体输入端口，因此不报告。

## 产品接入

产品实现源码可以严格证明的直接交集：

- 只处理解析器确认的 VHDL 时序进程。
- 时钟沿必须是进程主体的首个 IF 条件。
- 同步复位必须是紧邻时钟沿分支的简单嵌套 IF 条件。
- 控制信号必须是当前实体声明的输入端口，并具有 `arst`、`rst`、`reset` 或 `srst` 前缀。
- 异步复位分支、普通同步使能和同步器进程赋值右端的原始复位名不参与本规则。

验证覆盖附件直接外部同步复位、内部两级同步信号、直接异步复位和普通同步使能。
