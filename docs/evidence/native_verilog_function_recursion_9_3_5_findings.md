## 已观察事实

1. 构造函数 `FUN_180588ac0` 安装虚表 `0x180ef5d80`；slot 0 为消费函数 `FUN_180588f70`，slot 2 为候选选择器 `FUN_18058a120`。
2. 选择器只接收 `AST_FUNCTION(4)`，并要求函数子树中至少存在一个 `AST_FCALL(0x1c)`。不含函数调用的函数不会进入本规则的名称表。
3. 消费函数把候选函数按名称放入对象级有序映射；比较使用长度和 `memcmp`，区分大小写。键只有函数名字符串，没有 module、文件或候选组身份。映射在外层候选组循环之间不清空。
4. 重复名称会覆盖报告节点指针，但同名候选收集到的可解析调用边会合并。每个候选函数递归收集全部 `AST_FCALL` 后，只为全局名称表中可解析的被调函数建立边；不在表中的调用被忽略。
5. 邻接表按调用者名称有序遍历，每个调用边按收集顺序启动一次 DFS。当前路径以调用者开头，活动名称集合阻止非起点重入；只有再次到达路径首名称才形成闭环。
6. `FUN_18058a970` / `FUN_180588740` 使用 `FUN_180588900` 对活动名称集合进行字典序比较，证明去重键是“环成员名称集合”，不是路径旋转、调用点或单个函数。因此 `f→g→f` 只产生一条，而成员集合不同的重叠环分别产生诊断。
7. `FUN_1802db780` 在首次出现一个成员集合时复制当前路径。报告定位到路径首函数的源文件和物理行，不按环内每个函数分别输出。
8. 只读数据按 GB18030 解码为：`禁止调用递归函数.`、`函数`、`存在递归调用`、`组成递归调用` 和分隔符 `、`。单节点文本为 `禁止调用递归函数.函数<模块>/<函数>存在递归调用`；多节点依路径顺序列出 `<模块>/<函数>` 并以 `、` 分隔，末尾为 `组成递归调用`。
9. DLL 内部输出严重度字符串为 `Warning`；官方 GJB10157 强制规则配置仍为 Error，产品保留官方配置严重度。

## 产品接入边界

- 源码适配器对一次分析中的完整显式 module 建立一个区分大小写的函数名称图，并按原生“至少含一个调用”的候选边界处理函数。跨 module 的不同函数名可以构成一个环；跨 module 的同名候选共享一个名称键。
- 诊断按成员集合去重，定位和消息使用首次发现的路径；重复自调用不重复报告，成员集合不同的重叠环分别报告。
- 同名候选的报告节点采用最后写入名称表的函数，调用边则从全部同名候选合并；回归测试覆盖跨 module 闭环以及同名自递归只报告一次。
- 包、类、层次调用、宏/include 产生的定义、无法唯一证明的局部遮蔽和不完整语法不作肯定推断，并保持 `ManualReviewRequired`。
- 条件编译先由产品的活动分支预处理器限定，非活动分支不能构造调用边。
