# GJB10157 9.4.10（A-13-1）复杂数组索引原生证据

## 范围与来源

本记录针对附件 `T-Linter.dll` 的离线静态分析。附件 SHA-256 为
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

- 规则运行函数 `0x18058c1a0`；
- 候选过滤函数 `0x18058ca20`；
- 反编译保存件 `reverse-tools/evidence/a13_1/native_entry_functions.txt`；

## 已观察事实

1. 构造函数登记规则名 `GJB10157_VLOG.9.4.10`。
2. 候选过滤函数接纳四类原生 AST 节点：类型 `0x49`、`0x4a`、`0x4d`、`0x55`；还接纳带直接 range 子节点的 `AST_IDENTIFIER`（`0x13`）。结合既有类型证据，`0x4d` / `0x55` 分别对应阻塞/非阻塞赋值路径；`0x49` / `0x4a` 位于存储器读写路径。
3. 对 `0x49` / `0x4a` 候选，运行函数逐个检查直接子节点：只有 `AST_CONSTANT`（`0x10`）和 `AST_IDENTIFIER`（`0x13`）被视为简单根；出现其他根类型即报告。
4. 对带 range 或 multirange 的 `AST_IDENTIFIER`，运行函数同样逐个检查选择边界的根类型，规则仍是只允许 constant/identifier。
5. 对两子节点的赋值候选，只有左值为生成名称 `$mem2reg_rd*_ADDR` 或 `$mem2reg_wr*_ADDR` 时进入地址检查；其右值不是 constant/identifier 根时报告。
6. 报告发生在候选循环内部，因此诊断粒度为每个失败候选，而不是每个文件合并一次。
7. 严重度字面量为 `Warning`。
8. `0x180ef6148` 的 40 字节 GBK 字符串精确解码为：`建议数组索引为简单的信号，避免使用表达式`。
9. 附件文档违反例为 `B1[A1*2-1]`，合规例为 `B1[A1]`，与上述“AST 根只允许常量或标识符”边界一致。

## 产品接入

产品不复用附件代码，而在完成条件预处理后的源 token 上实现独立适配器：

- 表达式位置的普通数组/位选择中，数值或标识符根通过；
- 算术、一元运算、函数调用、拼接及条件表达式根报告；
- 声明维度被遮蔽，不作为运行时数组索引；
- 普通切片的每个边界按相同简单根规则检查；
- 每个复杂选择独立产生一条 `Warning`，使用恢复的精确中文提示；
- 官方对外编号保持三段式 `A-13-1`，内部条款键仍为 `GJB10157.9.4.10`。

## 推断与未知边界

以下不是已证明的厂商等价语义：

- `0x49` / `0x4a` 的精确枚举名称来自存储器读写控制流的高置信解释，但本轮没有厂商 AST 枚举表；
- 括号是否在附件前端保留独立节点、常量折叠时点、mem2reg 名称来源及准确源码定位仍未知；
- 宏、include、包限定名、对象成员、indexed part-select 与完整 SystemVerilog 前端降级仍未恢复；
- 产品故意不伪造 `$mem2reg_*_ADDR` 源名称，也不把无法解析的形式判为合规；无告警仍保持人工复核状态。

因此，本轮把该规则提升为“证据支持的核心谓词 + 已接入源适配器”，不宣称完整厂商算法等价。
