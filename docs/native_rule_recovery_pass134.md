## 实现及输入一致性

`FrontendPreprocessorSession` 保存独立缓存，创建/reset 对应清空边界；按显式根顺序处理。
每个根重新应用配置和默认工具宏，然后合并源码缓存。缓存中的源码定义可覆盖本次配置，
包括先前源码定义的 SYNTHESIS 值；配置宏被源码 undef 后，后一次读入仍会重新应用配置。
所有静态引擎队列操作仍受同一锁保护，预算和队列按根清理；不同会话不共享缓存。

GJB10157 分析移到 Analyzer 导入阶段只展开一次，标准检查复用同份结果。
每根入口处的已定义名称集合传给保留物理位置的条件编译投影；指令/include 的有效性取自
该根在正确会话中的展开诊断，不再用孤立缓存重复验证跨文件宏 include。
七条命名规则仍按同份展开输入建立工程模块唯一性索引，沿用已公开的实际词法来源定位政策。
任何根展开失败时，唯一性仍未证明，不以省略失败根来制造合规。

显式路径和展开后的清单保留输入顺序，重复同一路径仅保留首次出现；目录各自按路径排序。
不再用全局排序破坏“先定义后使用”。CLI 帮助和清单说明已给出顺序要求，不猜测宏依赖。
