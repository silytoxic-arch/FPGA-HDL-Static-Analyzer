# V1.4.104 R-6-1 层次端口方向绑定

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。对外规则编号继续严格采用官方三段式 `R-X-X` / `A-X-X`。

## 新恢复的原生边界

- `R-6-1` 原生入口 `FUN_1805fa8a0` 按设计根调用工程连接构造器 `FUN_1804d0140`，并传入两个工程解析容器。
- 构造器依据形式端口字段 `+0xa0/+0xa1/+0x104` 产生连接种类；相邻 DLL 分支及附件正反例已将三者分别确认为 `IN/OUT/INOUT`。
- 入口把连接种类 `1/2/7` 加入驱动集合；其中 `1/2` 对应 `OUT/INOUT`。
- 第二次连接遍历只对种类 `3`、标志为零的内部实际信号进入诊断，并再次要求该名称属于候选集合、不在驱动集合且未报告。
- 这证明层次连接不是统一的“已连接即安全”：输入形式端口消耗内部实际信号，输出或双向形式端口可以驱动内部实际信号。

证据：`reverse-tools/evidence/r6_1_hierarchy_direction_records.txt`，SHA-256 `ceaa55b9a01a07369325507153b1c95dba73af3638034da6297a5c268d090692`。

## 产品修正

- 本 architecture 中声明的 component 可按形式端口方向判定直接标识符实参；
- 工程内唯一 entity 可跨文件绑定，具名和位置映射均支持；
- 连接 `IN` 的内部信号视为层次读取，无本地赋值或层次输出驱动时报告 `R-6-1`；
- 连接 `OUT/INOUT` 的内部信号加入驱动集合，不再因本地读取产生误报；
- 同一信号同时存在输入读取和输出驱动时，驱动证据优先；
- 重名 entity、未声明隐式 component、表达式、选择名、`open`、configuration/generate 绑定不猜测，保持 `ManualReviewRequired`。

## 回归覆盖

- 普通内部信号未驱动读取、已赋值读取、未读取声明和重复读取去重；
- 本地 component 的输入实际信号未驱动反例与输出实际信号驱动正例；
- 唯一跨文件 entity 的位置输入/输出映射；
- 重名跨文件 entity 的方向歧义失败关闭；
- 诊断位于父 architecture 的实际信号，并携带信号名。
