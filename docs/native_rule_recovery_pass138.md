# 第一百三十八轮：条件位宽输入与 if/三目降低链

目标 DLL SHA-256：`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
本轮没有执行厂商 DLL；以下分别是二进制静态反编译、原生表离线重放和产品回归。

## 新增静态证据

从目标 PE 的 Bison 表重放预定义 token 流，完整接受 `module m;always @* if(cond) q=0;else q=1;endmodule`。
归约 563（0x233）对应 `$@67`，完整规则 565（0x235）的 RHS 为
`attr TOK_IF '(' expr ')' $@67 behavioral_stmt $@68 optional_else`。
保留的 `FUN_180950990` 同编号反编译动作创建 0x57 CASE、置节点 +0x183 为 1，
创建 0x54 BLOCK、0x58 COND，并把输入条件包装为 0x2d REDUCE_BOOL 追加到 CASE。
因此此前未知的普通源级 if→CASE/REDUCE_BOOL 关系现有原生静态依据。

同样重放连续赋值三目表达式，规则 641（0x281）的 RHS 为
`basic_expr '?' attr expr ':' expr`；同编号动作创建 0x48 TERNARY，依次追加条件、真值和假值。
A-11-4 主入口 `FUN_18057ecc0` 再次定点反编译，确认它对 CASE 中 REDUCE_BOOL 的第一个子项，
以及 TERNARY 的第一个子项推断宽度并与 1 比较。不能将任意 CASE 都称为源级 if。

表重放未执行词法器或语义动作；动作含义来自独立静态反编译。公开 Yosys 0.17
固定提交 `6f9602b4cfedc6441f55272f6c025d64620cd24f` 的语法源码仅作语义交叉印证，
没有用公开枚举数或内存布局替代厂商类型。证据、脚本和 SHA 在本轮清单中保留。
