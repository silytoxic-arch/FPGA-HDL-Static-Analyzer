# V1.4.103 A-5-32 跨文件层级命名绑定

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。

## 新恢复的原生边界

- `FUN_1806bc5c0` 遍历规则对象 `+0x78` 中的每个已绑定设计根。
- 每个根都会连同对象 `+0x68/+0x78` 的两个工程解析容器传给 `FUN_1804d0140`。
- `FUN_1804d0140` 在当前根收集 `AST_INSTANCE_ENTITY(0x93)` 与 `AST_INSTANCE_COMPONENT(0x94)`，并使用工程容器解析目标和形式端口。
- 构造器调用没有物理文件参数，因此父 architecture 与目标 entity 可以来自不同源文件。
- 具名 `0x8b` 关联与位置 `AST_IDENTIFIER(0x13)` 关联最终形成相同连接记录，入口对两侧完整名称执行不区分大小写比较。

证据：`reverse-tools/evidence/a5_32_bound_root_project_resolution.txt`，SHA-256 `c3c12da777faaf2d7e1d7c9eab5d269d3c292ccb97535343f787cb4c840a160f`。

## 产品修正

`A-5-32` 不再依赖解析器必须在同一文件先看到目标 entity：

- 直接 `entity work.child` 实例可以绑定工程中另一个文件的唯一 `child` entity；
- 具名直接标识符实参与位置直接标识符实参都使用已解析的形式端口；
- 目标名称匹配多个 entity 时不按文件顺序猜测；
- 当前 architecture 的本地 component 声明继续支持；
- 表达式、选择名、`open`、混合非法关联，以及没有本地声明的隐式 component 不扩展判定范围。

## 回归覆盖

- 跨文件直接 entity 的具名映射名称不一致；
- 同一跨文件目标的位置映射名称不一致；
- 大小写一致的时钟名称保持不报告；
- 两个同名目标 entity 时不产生推测性诊断，并保持 `ManualReviewRequired`；
- 原有同文件具名/位置正反例、表达式和 `open` 排除继续通过。
