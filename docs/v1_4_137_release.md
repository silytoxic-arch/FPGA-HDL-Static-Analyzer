# V1.4.137 R-9-4 类别 1 分支顺序

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。对外规则编号继续严格采用官方三段式 `R-X-X` / `A-X-X`。

## 本轮恢复

对用户附件 `T-Linter.dll` 的类别 1/4 生产器 `FUN_1804d24a0` 进行定点静态恢复，确认：

- 主条件分支先建立静态动作标志，随后按源码顺序处理直接 ELSIF；
- 第一个 ELSIF 边沿成为主关系，后续边沿作为 0x28 字节附加记录保存，主规则会继续消费这些记录；
- 非边沿静态 ELSIF 只在尚无“附加边沿记录”时更新静态动作标志，因此可位于首边沿前或前两个边沿之间；
- 第二个边沿已经追加后，后续静态 ELSIF 不会再把类别 4 提升为类别 1；
- ELSE 中若存在多个直接链接来源 IF，原生循环最终选择最后一个；只使用该 IF 的直接主条件，不使用其 ELSIF，也不接受 CASE/LOOP 内更深的 IF。

上述结论来自离线反编译，不代表运行了附件程序。DLL SHA-256 为 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 产品接入

- 类别 1 由顺序状态机处理全部直接 ELSIF，不再只检查第一个 ELSIF；
- 分开维护主边沿、附加边沿数量和静态动作标志；
- ELSE 分支搜索直接语句层的链接 IF，并只分类最后一个链接 IF 的主条件；
- 类别 2 外层主条件所有权、类别 3 无边沿和类别 4 排除保持独立。

## 新增边界验证

- ELSE 直接链接 IF 的时钟与后续独立顶层 IF 时钟不同：1 条 `R-9-4`；
- 静态非边沿 ELSIF 位于首边沿前：类别 1，两个边沿输出 1 条；
- 静态非边沿 ELSIF 位于前两个边沿之间：类别 1，输出 1 条；
- 静态分支位于第二个边沿之后：保持类别 4，输出 0 条；
- ELSE 中两个直接链接 IF：只取最后一个；
- 所选链接 IF 自身的 ELSIF：不作为类别 1 附加时钟。

既有类别 2、静态 RHS、大小写折叠、同名同沿/异沿、不同进程隔离和附件正反例继续回归。
