# 第八十五轮：R-6-2 拼接左值与按需登记

## 已观察的二进制消费者

目标映像及哈希与第八十二轮一致。复核同一完整反编译
`/private/tmp/tlinter-r62-pass82.txt` 的 FUN_180561f70：

- 赋值首子节点为 AST_CONCAT(0x22) 时，递归收集其中的 identifier，逐个归一化
  后追加到目标向量，保持收集器遍历顺序。
- 无 identifier 的 RHS 将全部目标键写为 1；参数名命中也将全部目标写为 1。
- 每个非参数 RHS identifier 依次查找目标键。在首个不存在的键处插入 0，立即
  break 退出本次目标循环。下一个 RHS identifier 再从向量头查找。
- 已有键即使为 0 也跳过；重复动态赋值因此能逐步登记此前未登记的其他目标。
- 报告消费者只遍历实际存在的键。未被登记的目标不能凭源码出现就额外报告。

## 上游语法佐证与推断

已读取 Yosys 官方 `frontends/verilog/verilog_parser.y` 的
`lvalue_concat_list` 和 `concat_list`：右侧列表先构造，左侧项追加至 children
尾部，故平坦拼接的 AST 直接子节点是源码从右到左的顺序。

来源：https://github.com/YosysHQ/yosys/blob/main/frontends/verilog/verilog_parser.y

上游语法是映射佐证，不能单独证明厂商完整 parser 的每种降低行为。本产品据此
对平坦、每项均为简单 identifier 的左值拼接采用右到左顺序；嵌套拼接、索引和
生成节点暂不借此推断完整等价。

## 产品接入及测试

单边沿适配使用显式名称→布尔状态表，不预先为拼接每项插入零值。例：

- `{Q1,Q2} <= A`：仅登记 Q2 为 0，产生一条 R-6-2。
- `{Q3,Q4} <= A+B`：两个 RHS identifier 分别登记 Q4、Q3，产生两条。
- `{Q5,Q6} <= 0`：两目标均为 1，不报告。
- 同一过程中连续两次 `{Q1,Q2} <= A`：两次逐步登记 Q2、Q1，最终两条。

上述组合及既有准确性测试通过；`git diff --check` 通过。源码尚未发布为新版本。
多边沿状态清表/候选、嵌套与选择左值、局部遮蔽和原生定位字段继续恢复。
规则仍为部分接入，完整专有前端等价仍为 0/209。
