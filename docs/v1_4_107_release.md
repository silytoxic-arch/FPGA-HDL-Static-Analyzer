# V1.4.107 R-6-2 命名宽度参数

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。对外规则编号继续严格采用官方三段式 `R-X-X` / `A-X-X`。

## 新恢复的原生边界

- `FUN_180600050` 在遍历匹配实体的 generic 容器时，对可求值默认项调用 `FUN_1804b78d0`，并将名称与整数结果写入对象 `+0x1a8` 的名称值表。
- 同一递归路径遇到类型 `0x0a`（附件类型表中的 `AST_LOCALPARAM`）且该节点可求值时，也把名称和值写入同一表。
- `FUN_1805fff90` 从该表按名称读取宽度参数；未命中时返回 `-1`。
- 这解释了 `FUN_1805ff100` 中转换函数第二参数为简单名称时的求宽来源。
- 以上结论来自附件 DLL 的静态反编译，不代表运行了附件软件。

证据：`reverse-tools/evidence/r6_2_width_entry_collector_resolver.c`，SHA-256 `a7f1be023c877cc9906fbdd9a7eb6f96bb894321b3c10975f7702fea5985537f`。

## 产品修正

- `R-6-2` 的五个向量结果转换函数现在支持同一实体中直接正整数 generic 默认值，例如 `WIDTH : positive := 4`；
- 支持当前 architecture 声明区中的直接正整数 constant；
- architecture constant 按原生遍历写入顺序覆盖同名 generic；
- 命名宽度同时用于直接赋值和 `and/or/xor/xnor` 位运算操作数比较；
- 表达式 generic、包常量、进程/子程序局部常量、动态求值和普通单参数 `to_integer` 仍不猜测，保持 `ManualReviewRequired`。

## 回归覆盖

- generic 默认值为 4、目标宽度为 8：必须报告；
- 同名 architecture constant 为 8：覆盖 generic 后不得报告；
- architecture constant 为 4 且转换结果参与 8 位 bitwise：必须报告；
- generic 默认值为表达式 `2 + 2`：不得伪造已知宽度；
- V1.4.106 的数值宽度、`对象'length`、非白名单函数和所有既有规则测试继续执行。
