# V1.4.101 A-5-31 逐设计根复位命名图

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。

## 新恢复的原生边界

- `FUN_1805f5080` 按规则对象 `+0x78` 的设计根容器逐项处理。
- 每个非空根开始时，原生入口清空 `+0x158` 名称树并重建当前根的复位种子集合。
- 赋值关系容器在根循环内部重新初始化，再以同一根调用 `FUN_1805f6790` 和 `FUN_1805f6590`。
- `FUN_1805f6790` 仅从当前根的 `AST_ARCHITECTURE(0x75)` 直接 `AST_ASSIGN_LE(0x56)` 子节点建立关系。因此同一物理文件的多个设计根不共享关系图。

静态证据：`reverse-tools/evidence/a5_31_per_design_root_scope.txt`，SHA-256 `78c5566febd23b4e26ca896b07f16c3d3639df2d6d51ef5c4dc9d1676e1d9d79`。

## 产品修正

此前一个 VHDL 文件只要包含多个 entity，产品就保留直接复位检查但关闭别名传播及非复位 `rst` 检查，导致漏报。

V1.4.101 改为按 `architecture ... of entity` 建立独立作用域，每个设计根分别收集：

- 所属 entity 端口；
- 当前 architecture 声明区的直接 signal；
- 当前 architecture 的复位种子；
- 当前 architecture 并发区的直接 `dst <= src` / `dst <= not src` 关系。

复位身份只沿本根“目标 → 来源”关系向上游传播，不会泄漏至同文件的另一个设计根。

## 回归覆盖

- 第一个设计根以 `rst_alias <= bad_source` 建立复位别名，确认 `bad_source` 被本根上游传播识别并报告。
- 第二个设计根含非复位 `rst_payload`，确认独立执行 `rst` 子串检查。
- 两个根位于同一物理 VHDL 文件，确认候选集合、种子集合和关系图互不合并。
- 既有直接/反相传播、禁止下游反向传播和嵌套 block 排除回归继续保留。
