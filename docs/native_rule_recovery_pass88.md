## 已观察的原生逻辑

FUN_180560210 在事件关系命中且边沿节点数不等于一时，分别以祖先类型序列
{AST_ALWAYS,AST_BLOCK,AST_BLOCK} 与 {AST_ALWAYS,AST_BLOCK} 调用
FUN_1804f33d0 收集 AST_CASE(0x57) 候选。

对每个收集到的候选：

1. 清空赋值列表，递归收集全部 AST_ASSIGN_EQ/LE(0x55/0x56)。
2. FUN_1805601e0 为当前候选创建一张新名称→布尔状态表。
3. 依次对全部赋值调用 FUN_180561f70，使用第八十二至八十五轮已恢复的状态更新。
4. 每个最终值为零的实际目标键独立报告，默认正文为 `触发器<名称>无初值`，
   严重度固定 error，源文件取模块路径，行号取当前 AST_CASE +0x200，无原生列。
5. 处理完当前候选后销毁状态表和赋值列表，再处理下一个候选。

消费者没有将常量状态更新限制为复位分支；候选整个子树中的数据分支赋值同样参与。
此行为不同于此前产品仅比较首个复位分支与数据分支目标集合的近似。

IF/ELSE 候选也用整棵 IF 树独立计算状态，覆盖常量、参数、拼接与状态保留行为。
正文为精确原生 `触发器<名称>无初值`，定位映射为候选 IF 起始行、产品第 1 列。

Q2 的数据 RHS 为 P+D 时复现 any-parameter 置位规则。原有准确性测试全部通过。
