# V1.4.98 A-5-29 分支归属与官方编号校验记录

## 新恢复的原生边界

- AST 枚举函数确认 `0xaa/0xab/0xac/0xad` 分别是 `AST_IF / AST_ELSIF / AST_ELSE / AST_ATTRIBUTE_DESIGNATOR`。
- `FUN_1804c5070` 只通过严格的 `BLOCK -> BLOCK -> CASE` 路径取得链接的源码 IF；`FUN_1804d1f90` 只接纳含 ELSIF，或 ELSE 内含链接 IF 的候选。
- 容器创建和复制函数确认类别 2 消费者读取的是关系对象 `+0x10` 的标志；该标志由 `FUN_1804d68a0` 根据最后处理的嵌套条件是否含受支持常量赋值写入。

## 产品修正

V1.4.97 把同一进程内任意字面量赋值作为下降沿候选的准入条件，范围比原生条件关系对象更宽。V1.4.98 将其收窄为：字面量 RHS 赋值必须位于对应 `falling_edge(identifier)` 的 IF/ELSIF 分支内。分支外赋值不再造成误报；分支内链接的嵌套 IF 仍保留。

新增回归覆盖：

- 下降沿分支直接字面量赋值继续报告；
- 下降沿分支只有数据传送时不报告；
- 同一进程的分支外存在字面量赋值，但下降沿分支仅数据传送时不报告；
- 下降沿分支内嵌套 IF 存在字面量赋值时继续报告。
