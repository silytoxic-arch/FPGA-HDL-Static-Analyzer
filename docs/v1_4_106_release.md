# V1.4.106 R-6-2 VHDL 转换函数结果宽度

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。对外规则编号继续严格采用官方三段式 `R-X-X` / `A-X-X`。

## 新恢复的原生边界

- `FUN_1805ff100` 的函数调用分支逐名比较 `to_unsigned`、`to_integer`、`to_signed`、`conv_std_logic_vector`、`to_stdlogicvector`、`to_bitvector`。
- 只有函数 AST 恰有两个子节点时才继续求宽。
- 第二子节点为常量时直接取其数值；为无子节点名称时从 `FUN_1805fff90` 背后的登记值表读取；为带 `length` 属性的名称时回查对象声明宽度。
- 推导出的函数结果宽度参与 `R-6-2` 的赋值、关系运算和四类位运算比较。
- 以上结论来自附件 DLL 的静态反编译，不代表运行了附件软件。

证据：`reverse-tools/evidence/r6_2_width_entry_collector_resolver.c`，SHA-256 `a7f1be023c877cc9906fbdd9a7eb6f96bb894321b3c10975f7702fea5985537f`。

## 产品修正

- 接入五个有明确向量结果宽度的白名单函数：`to_unsigned`、`to_signed`、`conv_std_logic_vector`、`to_stdlogicvector`、`to_bitvector`；
- 支持正整数第二参数，例如 `to_unsigned(3, 4)`；
- 支持已知信号或端口的 `对象'length`，例如 `to_signed(3, data'length)`；
- 函数结果宽度同时用于直接赋值和位运算操作数比较；
- 非白名单函数、零宽/超大宽度、登记常量/泛型值、动态表达式以及普通单参数 `to_integer` 不猜测，保持 `ManualReviewRequired`。

## 回归覆盖

- 显式宽度与目标不等：必须报告；
- `对象'length` 与目标等宽：不得报告；
- `对象'length` 与目标不等宽：必须报告；
- 白名单函数作为位运算操作数：按结果宽度比较；
- 非白名单 `resize`：不得伪造宽度结论；
- 既有赋值、关系、直接位运算、选择/切片与拼接测试继续通过。
