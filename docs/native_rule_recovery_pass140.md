## 原生判据复核

旧临时分析项目及部分持久项目的数据文件缺失，不能作为可继续分析的有效数据库。
本轮用现有 Ghidra 新建独立导入，核对目标摘要后仅准备 `0x18057b2f0`、`0x1806c9ed0` 和
`0x18066e7e0` 三个入口，保留恢复脚本、静态文本和指令。

R-10-1 的 slot 0 在新数据库中识别为指向 `FUN_18066e7e0` 的 thunk。
已知位宽调用点所属 PE runtime-function 范围为 `[0x18066e7e0, 0x180670342)`。
`0x18066fe68` 向第五参数槽写 0，`0x18066fe7b` 调用 `FUN_1808f4650`，
随后先比较 `-1`、再比较保存的形式宽度，两种相等都跳过告警。未依赖反编译器推测的参数个数。
A-8-1 的入口再次显示实际声明 `+0xa0/+0xa1` 均非零，而形式声明任一字节为零时进入报告。
这些复核支持已有判据，不代表已恢复全部前端绑定算法。

## 输入缺陷与接入

V1.4.257 的字面子模块/父模块会报告 R-10-1 位宽不等；相同内容由完整模块宏生成时漏报。
旧检查使用物理源码缓存及另一路绑定模型，无法覆盖实际展开的父子单元。

本轮新增展开工程输入视图：每个根保存相匹配的不可变展开文本、token 与虚拟设计单元。
先完成根的存储，再建立所有模块名的所有权索引；不能解析位宽的定义也不会被排除在重名统计外。
相同物理路径的不同输入根保留独立身份，不以路径字符串合并文本缓存。

R-10-1 与 A-8-1 使用该工程视图解析唯一项目目标。连接、形式声明和实参在虚拟坐标中判断，
最终诊断通过父根的来源视图映射到宏调用或头文件。既有字面精确列保持，无法证明列时使用 1。
已识别的显式方向连接仍可在含通配符的实例中检查；仅有通配符的隐式绑定没有被臆造。

未知位宽、参数化形式宽度及不能绑定的外部单元继续复核；任一 Verilog 根未成功展开时，
不能据剩余根证明工程目标唯一。重复父/子目标不任意选择。该索引不是完整 HDL elaboration。
