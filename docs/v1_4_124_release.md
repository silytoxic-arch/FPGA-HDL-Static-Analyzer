# V1.4.124 R-6-8 共享异步控制源的复位/置位动作边界

本版本只推进规则逆向、判断逻辑和验证，不调整界面或表格布局。对外规则编号继续严格采用官方三段式 `R-X-X` / `A-X-X`。

## 原生证据闭环

- `GJB9765_VHDL.4.6.g` 与 `GJB9765_VHDL.4.10.b` 的 vtable slot 0 都指向 `FUN_180650a90`。
- 共享入口调用 `FUN_180652070` 建立复位/置位关系，在解析到同一寄存器目标后比较两端控制源名称；相同名称进入告警路径。
- 附件违反例的同一目标分别获得常量 `0`、`1`，两个分支控制源均为 `RST` 或 `int_async_sig`；正确例改用两个不同控制源。
- 因此“同一源 + 同一目标”还不充分，必须先有可证明的 reset/set 两类动作。两个分支都赋 `0` 只有复位，没有置位；动态数据也不能被猜测成另一类动作。

证据：`docs/evidence/native_vhdl_shared_async_control_4_6_g_4_10_b_findings.md`，原生伪代码证据 `ev_db7f61fc4a1fbadb5a400f779d6a4ffba97ebf540868b8b5acb705865a0133cf`、`ev_90f915f639542a3da6bbf92ee94c91cc0152784e18928c954ed377b4ed14fa80`；附件 DLL SHA-256 为 `60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。

## 产品修正

- 每个异步分支只记录直接标识符赋值目标及可直接证明的二值动作。
- 支持标量 `'0'` / `'1'` 和附件使用的 `(others => '0')` / `(others => '1')`。
- 同一目标、同一控制源的动作集合必须同时包含 `0`、`1` 才触发 `R-6-8` 及共享规则。
- 比较式允许控制标识符位于字面量左侧或右侧。
- 两个分支动作相同、动态数据赋值、不同目标或不同控制源均不报告。

## 新增验证
