Product consequence
===================

The source adapter may process several entity/architecture pairs from one
physical VHDL file, but it must create separate candidate sets, reset seed
sets, and target-to-source graphs for each architecture/entity design root.
It must not disable graph propagation merely because the file contains more
than one entity, and it must not allow a reset identity or alias edge to leak
from one root into another.

Inference and remaining unknowns
================================

Mapping the proprietary current-root object to a source architecture/entity
pair is a bounded source-level inference supported by the admitted
AST_ARCHITECTURE child and by VHDL's `architecture ... of entity` ownership.
The exact behavior for multiple architectures of one entity, configuration
selection, roots assembled across files, duplicate library-unit names, failed
binding, and native diagnostic ordering/multiplicity remains unresolved.
