# GJB10157.8.3 递归标识符分类复核

目标：附件 `T-Linter.dll`，SHA-256
`60e6b52875f4d7c3fbdf494d869b3a4bcc3fdc8ee63d8620ea9614da5d6599b0`。
方法：复核 Ghidra 12.1.4 离线静态反编译证据；未运行厂商程序。

## 静态观察

- 入口 `FUN_1805728e0`（证据
  `ev_831e82f060cbac3411dda956028bf6b283df8fb032e92e7f9d0b77df52239651`）
  从 `AST_ALWAYS(0x52)` 和 `AST_ASSIGN(0x4d)` 根递归收集
  `AST_ADD/SUB/MUL/DIV/MOD/POW`。
- 对每一个收集到的算术节点，入口把该节点交给 `FUN_180573af0`；不是只把
  运算符的两个相邻源代码 token 交给辅助器。
- `FUN_180573af0` 递归访问传入节点的子树，只在 `AST_IDENTIFIER(0x13)` 处解析
  声明对象，并把对象 `+0xa4` 的布尔分类加入位向量。
- 入口分别统计位向量中的 0 与 1；两类均存在才报告。因此父算术节点与嵌套子
  算术节点各自独立判断，字面量本身不贡献分类。

## 产品映射

产品对有界 Verilog 算术表达式按 `+/-`、`*//%`、`**` 优先级和结合性重建
子树，对每个子树收集可解析声明的标识符符号属性。该映射修复了
`signed_a * 2 + unsigned_b` 等无括号链的漏报，同时避免把只有同类声明的
内层节点误报。

## 未知边界

错误恢复和原生诊断顺序/重数仍未恢复。无告警结果继续保持人工复核。
